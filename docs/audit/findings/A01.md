### A01-007 — `nginx/nginx.conf` is HTTP-only, clobbers upstream `X-Forwarded-Proto`, disables keepalive pooling, and sets a 24h `proxy_read_timeout`
- Severity: P1
- Category: security
- Where: `nginx/nginx.conf:7, 15, 21–63`; `next.config.ts:111–115`; `app/actions/marketing-ops.ts:124`
- Brief claim contradicted (if any): §4.1.1 "production-ready Nginx reverse proxy configuration"
- Evidence:
  1. **HTTP-Only + `X-Forwarded-Proto` Overwrite (`L27, 57`)**: Listens solely on `listen 80;` (no `443 ssl http2`, no HTTP→HTTPS redirect, no `Strict-Transport-Security`, no `Content-Security-Policy`, no `Permissions-Policy`, no `server_tokens off;`). Worse, `proxy_set_header X-Forwarded-Proto $scheme;` (`L57`) overwrites any TLS-terminating load balancer's `X-Forwarded-Proto: https` with `"http"`, breaking Better Auth secure cookies and OAuth callback URLs.
  2. **24-Hour `proxy_read_timeout` + Broken Keepalive (`L7, 23, 52–53, 61`)**: `location /` sets `proxy_read_timeout 86400;` (**24 hours**) for **every** URL and hardcodes `proxy_set_header Connection "upgrade";` (`L53`). In Nginx, `upstream { keepalive 64; }` (`L23`) requires `Connection ""` on standard HTTP/1.1 requests; hardcoding `"upgrade"` disables upstream connection reuse on every page/API call and lets `1,024` slow connections (`worker_connections 1024`, `L7`) hold worker slots open for 24 hours (trivial DoS).
  3. **`add_header` Inheritance Trap (`L31–44`)**: `location /_next/static/` (`L40`) defines `add_header Cache-Control "public, max-age=31536000, immutable";` (missing `always`) and manually repeats `L31–33`; in Nginx, any `add_header` added later at `server {}` (such as HSTS or CSP) is silently dropped inside `/_next/static/` unless moved to a shared snippet.
  4. **25 MB Nginx vs 1 MB Next.js Server Action Limit (`L15`)**: `nginx.conf:15` sets `client_max_body_size 25M;`, while `next.config.ts:111–115` omits `experimental.serverActions.bodySizeLimit` (Next 16 default: **`1MB`**), causing `uploadRawFlyerFileAction(formData)` (`marketing-ops.ts:124`) to fail with `413 Body exceeded 1 MB limit` on high-res supplier flyers! Meanwhile `upstream` hardcodes `127.0.0.1:3000` (`L22`), which `502`s across separate Docker containers.
- Impact (business terms): Plaintext HTTP exposes admin credentials and pilgrim PII if deployed directly; behind Cloudflare/ALB it breaks HTTPS protocol detection; a trivial slow-read attack exhausts all 1,024 Nginx connections; and >1 MB supplier flyer uploads via Server Action fail with HTTP 413.
- Root cause: `nginx.conf` combined dev WebSocket/HMR settings (`86400s` timeout, literal `"upgrade"`, port 80, `127.0.0.1`) into a nominal production config without TLS, `map $http_upgrade`, rate-limiting (`limit_req_zone`), or Next.js `bodySizeLimit` alignment.
- Recommended fix: Add TLS (`listen 443 ssl; http2 on;` + port 80→443 `301`), `server_tokens off;`, HSTS + CSP via a shared `include` snippet (with `always` on all `add_header`s), preserve upstream `$http_x_forwarded_proto` when trusted (`map $http_x_forwarded_proto $forwarded_proto`), use `map $http_upgrade $connection_upgrade { default upgrade; '' ''; }`, lower `location /` `proxy_read_timeout` to `60s`, add `limit_req_zone` on `/api/auth/` and Server Actions, and set `experimental.serverActions.bodySizeLimit: "10mb"` in `next.config.ts` (or route all raw flyer uploads exclusively through R2 presign).
- Test to add: Config/integration test starting Nginx in Docker against the standalone server and asserting `Connection: keep-alive` reuse, security headers on both `/` and `/_next/static/*`, `60s` timeout config (`nginx -T`), and >1 MB flyer validation behavior.
- Effort: M (<1d)
- Confidence: High
