### A04-001 — 3-way schema/migration/script drift on `marketing_channels` unique index breaks `syncRealWhatsappGroups` with SQLSTATE `42P10`

- Severity: P0
- Category: data-integrity
- Where: `db/schema/suppliers-and-marketing.ts:343–348`; `drizzle/0001_cynical_proudstar.sql:512–514`; `scripts/sync-slice40-schema.ts:116–119`; `lib/whatsapp/linked-device.ts:664–665, 691–692`
- Brief claim contradicted (if any): N/A
- Evidence:
  1. `db/schema/suppliers-and-marketing.ts:347` declares a non-partial unique index: `uniqueIndex("idx_channel_external_id").on(table.externalGroupIdOrHandle)`.
  2. `drizzle/0001_cynical_proudstar.sql:512–514` omitted `idx_channel_external_id` entirely (only `idx_channel_platform`, `idx_channel_area`, and `idx_channel_active` exist).
  3. `scripts/sync-slice40-schema.ts:116–119` patched Neon out-of-band with a **partial** unique index under a different name: `CREATE UNIQUE INDEX IF NOT EXISTS idx_marketing_channels_external_handle ON marketing_channels (external_group_id_or_handle) WHERE external_group_id_or_handle IS NOT NULL`.
  4. `lib/whatsapp/linked-device.ts:664–665` and `691–692` execute `.onConflictDoUpdate({ target: marketingChannels.externalGroupIdOrHandle, set: ... })` **without** `targetWhere: sql\`${marketingChannels.externalGroupIdOrHandle} IS NOT NULL\``.
  5. Reproduced live on `alramlah-audit-pg` (`PostgreSQL 16.16`): both (a) the `drizzle/0001` table definition and (b) the table with `idx_marketing_channels_external_handle ... WHERE external_group_id_or_handle IS NOT NULL` reject `INSERT INTO marketing_channels ... ON CONFLICT (external_group_id_or_handle) DO UPDATE` with `ERROR: there is no unique or exclusion constraint matching the ON CONFLICT specification` (SQLSTATE `42P10`), because PostgreSQL never infers a partial unique index unless `ON CONFLICT` includes a matching `WHERE` predicate.
- Impact (business terms): Synchronizing real WhatsApp groups and Status broadcast channels from a linked WhatsApp device (`syncRealWhatsappGroups`) fails 100% of the time at the database layer on both migration-provisioned databases and `sync-slice40-schema.ts`-provisioned databases, blocking Safe WA Group/Status Queue onboarding in `/admin/campaigns` and `/admin/settings`.
- Root cause: Schema changes after `0001_cynical_proudstar.sql` were pushed via ad-hoc raw SQL in `scripts/sync-slice40-schema.ts` using a `WHERE ... IS NOT NULL` partial predicate that does not match `db/schema/suppliers-and-marketing.ts:347` or the Drizzle `.onConflictDoUpdate()` call in `linked-device.ts`.
- Recommended fix: Generate a canonical Drizzle migration (`0002_*.sql`) that drops `idx_marketing_channels_external_handle` if present, deduplicates any duplicate non-null `external_group_id_or_handle` rows, and creates the non-partial `CREATE UNIQUE INDEX IF NOT EXISTS "idx_channel_external_id" ON "marketing_channels" ("external_group_id_or_handle")` (in PostgreSQL, a standard unique index already permits multiple `NULL` values while satisfying `ON CONFLICT (external_group_id_or_handle)`).
- Test to add: Integration test against disposable PostgreSQL applying `drizzle/0000`..`0002` and invoking `syncRealWhatsappGroups` twice with overlapping JIDs plus multiple `NULL`-handle manual channels, asserting zero `42P10`/`23505` errors.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### A04-003 — Re-running `db/seed.ts` silently overwrites `long_term` (90-day) visa rate to `short_term` `PKR 42,500 / 30 days`

- Severity: P0
- Category: data-integrity
- Where: `db/seed.ts:141–187`
- Brief claim contradicted (if any): N/A
- Evidence: `db/seed.ts:143–175` inserts a two-row array containing both `tier: "short_term"` (`minDays: 1, maxDays: 30, pricePkr: 42500, priceSar: 470, label: "Short-Term Umrah Visa (Up to 30 Days)"`) and `tier: "long_term"` (`minDays: 31, maxDays: 90, pricePkr: 68000, priceSar: 750, label: "Long-Term Extended Umrah Visa (31 to 90 Days)"`), then chains:
  ```ts
  .onConflictDoUpdate({
    target: schema.visaRates.tier,
    set: {
      pricePkr: 42500,
      priceSar: 470,
      label: "Short-Term Umrah Visa (Up to 30 Days)",
      minDays: 1,
      maxDays: 30,
      updatedAt: new Date(),
    },
  })
  ```
  Instead of `sql\`excluded.price_pkr\`` (etc.), hardcoded `short_term` literals are applied to **every** conflicting row — turning the `long_term` row into `price_pkr = 42500, price_sar = 470, min_days = 1, max_days = 30`. Additionally, `db/seed.ts:2102–2146` overwrites admin-edited `group_packages` pricing/titles on every seed run via `.onConflictDoUpdate` on `slug`.
- Impact (business terms): Any second execution of `db/seed.ts` (confirmed in `w0-env-baseline.md` §3 on `alramlah-audit-pg`) corrupts `long_term` (>30-day) visa quotes from `PKR 68,000` down to `PKR 42,500` — an immediate **`PKR 25,500` direct revenue loss per pilgrim** (`PKR 127,500` loss on a 5-person family) in `Visa Only` immediate pricing and Admin Quote Worksheet pre-fills.
- Root cause: Copy-paste error in `.onConflictDoUpdate({ set: ... })` using constant `short_term` values instead of PostgreSQL `EXCLUDED.*` column references.

### A04-004 — `drizzle-orm/neon-http` driver lacks interactive `db.transaction()` support, leaving 11 multi-step business mutations non-atomic

- Severity: P0
- Category: data-integrity
- Where: `db/index.ts:11–31`; `node_modules/drizzle-orm/neon-http/session.js:151–159`; `app/actions/applications.ts:179–339, 471–536, 617–674`; `app/actions/quotes.ts:149–310, 411–507`; `app/actions/marketing-ops.ts:200–423, 773–963, 1009–1083, 1137–1189, 2109–2189`; `lib/whatsapp/intake-flow.ts:760–882`
- Brief claim contradicted (if any): N/A
- Evidence:
  1. `db/index.ts:21–22` initializes Drizzle exclusively over `@neondatabase/serverless`'s stateless HTTP `neon(connectionString)` client via `drizzle-orm/neon-http`.
  2. `node_modules/drizzle-orm/neon-http/session.js:151–153` explicitly throws on any transaction attempt:
     ```js
     async transaction(_transaction, _config = {}) {
       throw new Error("No transactions support in neon-http driver");
     }
     ```
     (While `neon-http` supports single-roundtrip non-interactive `db.batch([...])` at `session.js:117–133`, **zero** calls to either `db.transaction(` or `db.batch(` exist anywhere in `web/`.)
  3. All 11 multi-table write flows execute sequential auto-committed HTTP queries where mid-flight errors leave partial or inconsistent state:
     - `submitCustomApplication` (`app/actions/applications.ts:179–339`): 4 sequential inserts (`applications` -> `application_hotel_stays` -> `application_transport_segments` -> `application_quotes`); best-effort `catch { await db.delete(applications) }` (`L331–339`) exposes half-written applications to `/admin`, `/admin/desk`, and `sla-overdue-quote-monitor` during the 50–300ms window and leaks orphan header rows if the process/network drops before `DELETE`.
     - `submitGroupBookingApplication` (`applications.ts:471–536`) & `submitHajjInquiryApplication` (`applications.ts:617–674`): 2 sequential inserts (`applications` -> `application_quotes`) with best-effort compensating delete.
     - `saveApplicationQuote` (`app/actions/quotes.ts:149–310`) & `updateApplicationStatus` (`quotes.ts:411–507`): mutate `group_departures.booked_seats`, `application_quotes`, and `applications.status` across 3 separate HTTP commits with **zero** rollback on failure (see `A04-005`).
     - `upsertSupplierFlyerWithPackages` (`app/actions/marketing-ops.ts:200–423`): runs `1 + N + 2` auto-committed writes (`UPDATE supplier_flyers`, `N × UPDATE supplier_flyer_packages`, `DELETE` removed cards — permanently cascading `post_assets` + `daily_post_distributions` — then `INSERT` new cards). Failure on final `INSERT` permanently destroys deleted cards & campaign assets.
     - `publishFlyerCardToPublicGroupPackages` (`marketing-ops.ts:773–963`) & `publishAllFlyerCardsToPublicGroupPackagesAction` (`1009–1083`): upserts `group_packages` (`853–890`), *then* queries `departure_cities` and returns `{ error: "No active departure cities configured..." }` at `900–905` **after `group_packages` is already committed live on `/` with 0 departures**, then upserts `group_departures`, then links `supplier_flyer_packages`.
     - `convertPostLookupToApplication` (`marketing-ops.ts:1137–1189`): inserts `applications` with `status: "quoted"` (`1142`), then inserts `application_quotes` (`1170`) with **zero** rollback — leaving `"quoted"` applications with 0 quote rows if step 2 fails.
     - `deleteSupplierFlyerAction` (`marketing-ops.ts:2109–2189`): executes `2N + 2M + 4` sequential updates/deletes across 7 tables with zero atomicity.
     - `advanceUmrahIntakeFlow` (`lib/whatsapp/intake-flow.ts:760–882`): inserts `applications` (`761`, notably **without** creating an initial `application_quotes` v1 row unlike all web flows), updates `whatsapp_conversations.intake_flow_state = COMPLETED` (`795`), sends Meta WhatsApp message (`811`), and inserts `whatsapp_messages` (`849`). If `795` fails after `761`, conversation stays at `AWAITING_HOTEL_TIER` and the pilgrim's retry creates duplicate `ART-WA-...` dossiers.
- Impact (business terms): Transient Neon HTTP timeouts, serverless cold-start aborts, or constraint errors mid-request corrupt booking records: pilgrims receive errors while orphan applications/packages appear live, `"quoted"` dossiers exist with PKR 0 / missing quote versions, and deleted Studio flyer cards cannot be recovered on save errors.
- Root cause: Architectural choice of stateless `drizzle-orm/neon-http` as the sole database client without configuring `@neondatabase/serverless` WebSocket `Pool` (`drizzle-orm/neon-serverless`) for interactive ACID transactions (`BEGIN ... COMMIT/ROLLBACK`) or `db.batch([...])` for single-roundtrip atomic batches.
- Recommended fix: Export a transactional client `dbPool` in `db/index.ts` backed by `@neondatabase/serverless` `Pool` + `drizzle-orm/neon-serverless` (using `DATABASE_URL_POOLED`) alongside `db` (`neon-http`) for fast single-statement reads (with `ws` polyfill for Node/Trigger workers), and wrap all 11 multi-step mutations in `await dbPool.transaction(async (tx) => { ... })`, keeping external HTTP calls (Meta WhatsApp send, Gotenberg PDF render) outside the DB transaction boundary.
- Test to add: Fault-injection integration tests on disposable Postgres that force step `k` of `submitCustomApplication`, `saveApplicationQuote`, `publishFlyerCardToPublicGroupPackages`, and `upsertSupplierFlyerWithPackages` to throw, asserting 0 partial rows or mutated seat counters remain after rollback.
- Effort: L (>1d)
- Confidence: High
