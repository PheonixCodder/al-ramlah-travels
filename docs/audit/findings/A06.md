## 1. Combinatorial Matrix (`6 Presets × 31 Non-Empty Pillar Bitmasks × 6 City Sequences × Routes/Cabins × Pax`)

### 1.1 Five Conflicting `hasCityLegs` / Sequence / Persistence Predicates Discovered

Across the Journey Builder client and server action, **five incompatible predicates** determine whether city sequence, stay chaining, and airport selections exist:

1. **Context `hasCityLegs`** (`components/planner/planner-context.tsx:454`):
   `pillars.hotels || (pillars.transport && presetMode !== "transport_only")`
2. **Step-1 UI `isCitySequenceVisible`** (`components/planner/city-sequence-module.tsx:77–81` & `dates-and-travellers-bar.tsx:29–33`):
   `presetMode !== "visa_only" && presetMode !== "transport_only" && presetMode !== "flights_only" && (pillars.flights || pillars.hotels || pillars.transport)`
3. **Ziyarat local `hasCityLegs`** (`components/planner/ziyarat-selection-module.tsx:43`):
   `Boolean(pillars.hotels || pillars.transport)` *(ignores `presetMode !== "transport_only"`)*
4. **Client Submit Payload Gate** (`components/planner/review-and-submit-step.tsx:182–184`, `live-summary-card.tsx:67–69`, `lead-capture-dialog.tsx:92–94`):
   Sends `citySequence`, `entryAirport`, `exitAirport` **iff** `hasCityLegs === true`; otherwise sends `undefined`.
5. **Server Persistence Gate** (`app/actions/applications.ts:140–166, 208–212`):
   Persists `citySequence`, `entryAirport`, `exitAirport` **iff** `data.includeFlights || data.includeHotels` (defaulting `!entryAirport -> "JED"`, `!exitAirport -> "MED"` when `citySequence` is omitted, and forcibly overwriting `exitAirport = "JED"` on `madinah_makkah` at `L160`).

## 2. Detailed Findings (`§3.3` Format)

### A06-001 — Visa-Only Pricing Misquotes: `PKR 0` Official Quote Bypass, Client/Server Fallback Split (`68k` vs `65k`), Dead Masar FX Conversion, & Seed Overwrite
- Severity: P0
- Category: functional
- Where: `lib/validations/application.ts:47–54`, `app/actions/applications.ts:104–136, 307–317, 889`, `components/planner/planner-context.tsx:1557–1569`, `lib/domain/quote-hints.ts:169–178`, `db/seed.ts:175–187`
- Brief claim contradicted (if any): §5.4 "Only Visa Only mode displays an immediate fixed PKR total to the customer"
- Evidence:
  1. **Zero-PKR Official Quote Bypass**: `customJourneyApplicationSchema` (`lib/validations/application.ts:47–54`) marks `ksaArrivalDate` and `ksaDepartureDate` `.optional()`. Empirical harness (`Probe G`): `customJourneyApplicationSchema.safeParse({ presetMode: "visa_only", includeVisa: true, passengers: { adults: 2, children: 0, infants: 0 }, contact: ... })` returns **`true`**. In `submitCustomApplication` (`app/actions/applications.ts:104`), `if (data.includeVisa && data.ksaArrivalDate && data.ksaDepartureDate)` is skipped, leaving `calculatedVisaTotalPkr = 0`, and lines `307–317` auto-insert an official Version 1 `application_quotes` row with `grandTotalPkr: 0` — immediately exposed to the customer via `lookupApplicationStatus` (`applications.ts:889`).
  2. **Client vs Server Long-Term Fallback Split**: When `visa_rates` is empty or its query fails (`app/(public)/page.tsx:58`), `planner-context.tsx:1561` computes `"Guaranteed Fixed Total"` using `longTermPricePkr: 68000`, whereas `applications.ts:109` uses `let longTermPkr = 65000` (`PKR 3,000`/passport discrepancy locked into Quote v1).
  3. **Masar SAR Brackets Dead in `submitCustomApplication`**: `applications.ts:122–128` passes `{ withMasar: data.includeHotels, withMasar10DaysSar: ... }` to `calculateVisaTierAndCost` **without `sarToPkrRate`**. Because `lib/domain/visa-calc.ts:78` requires `options?.sarToPkrRate && options.sarToPkrRate > 0`, server submission locks `PKR 85,000` (`42,500/pax`) for a 2-pax 10-day hotel+visa trip while `calculateApplicationRateHints` (`lib/domain/quote-hints.ts:172`, passing `sarToPkrRate: 75`) computes `PKR 75,000` (`37,500/pax`).
  4. **Seed Idempotency Corruption (`W0-001`)**: `db/seed.ts:175–187` updates ALL `visa_rates` rows with `pricePkr: 42500` on a second seed run, underquoting >30-day `Visa Only` bookings by `PKR 25,500`/passport.
- Impact (business terms): Direct revenue loss and contractual dispute: pilgrims receive an official `ART-YYYY-XXXX` `Visa Only` quote at `PKR 0`, `PKR 42,500` (instead of `68,000`), or `PKR 65,000` (after seeing `68,000` "Guaranteed Fixed Total"), and staff see conflicting pre-filled vs hinted visa figures (`PKR 85,000` vs `PKR 75,000`) on the Quote Worksheet.
- Root cause: Optional date fields in `customJourneyApplicationSchema` without `.superRefine` when `includeVisa` is true; duplicated hardcoded fallback constants (`68000` vs `65000`); missing `agencySettings.sarToPkrRate` lookup in `submitCustomApplication`; unscoped `db.update(schema.visaRates)` in `db/seed.ts`.
- Recommended fix: Require `ksaArrivalDate` and `ksaDepartureDate` in `customJourneyApplicationSchema.superRefine` whenever `includeVisa || presetMode === "visa_only"`; unify fallback constants in `lib/domain/visa-calc.ts`; pass `agencySettings.sarToPkrRate` into `calculateVisaTierAndCost` in `submitCustomApplication`; scope `db/seed.ts` updates by `eq(schema.visaRates.durationTier, ...)`.
- Test to add: Unit + integration test asserting (a) `visa_only` without dates fails Zod validation, (b) `planner-context` and `submitCustomApplication` produce identical `calculatedVisaTotalPkr` for 14d and 45d with and without DB rows, and (c) `submitCustomApplication` matches `calculateApplicationRateHints` on a 10-day Masar stay.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no
