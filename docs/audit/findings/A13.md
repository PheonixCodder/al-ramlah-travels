### A13-001 — Gotenberg v8 Screenshot Route 404s, Lacks Fetch Timeouts, Swallows Errors, and Drops Task Retries

- Severity: P0
- Category: functional
- Where: `lib/posters/gotenberg.ts:96–176` (`renderHtmlViaGotenberg`); `trigger/render-gotenberg-asset.task.ts:380–387` (`runRenderGotenbergAsset`); `../services/gotenberg/pkg/modules/chromium/routes.go:568, 661, 760` (`screenshotUrlRoute`, `screenshotHtmlRoute`, `screenshotMarkdownRoute`)
- Brief claim contradicted (if any): §6.3 (`docs/PLATFORM_MASTER_BRIEF.md:819`) "Renders pixel-perfect 4K PNGs and infinite-resolution Vector PDFs via Gotenberg v8"
- Evidence:
  1. **Non-existent Gotenberg v8 screenshot route (`HTTP 404` on 100% of poster renders):** `lib/posters/gotenberg.ts:119–123` posts HTML screenshots to `/forms/chromium/screenshot` without the required `/html` suffix:
     ```ts
     const res = await fetch(`${baseUrl}/forms/chromium/screenshot`, {
       method: "POST",
       headers,
       body: form,
     })
     ```
     Cross-checking the upstream Gotenberg v8 router in `../services/gotenberg/pkg/modules/chromium/routes.go:568, 661, 760` and `chromium.go:889–896` proves Gotenberg v8 registers **only** `/forms/chromium/screenshot/url`, `/forms/chromium/screenshot/html`, and `/forms/chromium/screenshot/markdown` (unlike PDF conversion at `L152`, which correctly calls `/forms/chromium/convert/html`). Every 4K Multi-Package Sheet (`render-multi-package-poster.ts:271–278`) and Single-Package Spotlight (`render-single-package-poster.ts:350–357`) sets `capturePng: true` and immediately receives `HTTP 404 Not Found` from Gotenberg.
  2. **Missing `AbortSignal.timeout()` & silent missing-API-key behavior:** While `checkGotenbergHealth()` sets `signal: AbortSignal.timeout(8000)` (`lib/posters/gotenberg.ts:40`), neither render `fetch` (`L119`, `L152`) sets any `AbortSignal.timeout()`, allowing hung TCP/TLS sockets behind Caddy's `120s` proxy window (`../scripts/oracle-gotenberg/Caddyfile:18`) to stall workers indefinitely. In addition, lines `96–100` attach `X-Gotenberg-Api-Key` only `if (apiKey)`, silently sending unauthenticated requests (guaranteed `HTTP 401` at Caddy) instead of failing fast with a clear configuration error when `GOTENBERG_API_KEY` is unset.
  3. **Unconditional catch masks Gotenberg errors & Trigger.dev retry logic is inverted:** `gotenberg.ts:170–175` catches **every** error (`401`, `404`, `502`, `503`, `ECONNREFUSED`), discards `gotenbergErr`, and calls `renderHtmlViaChromiumCdp(options)`, surfacing `"Could not locate Google Chrome..."` instead of the real Gotenberg status. Worse, when that fallback throws inside `trigger/render-gotenberg-asset.task.ts:380–386`:
     ```ts
     throwIfNonRetryable(err, "RenderGotenbergAssetTask")

     return {
       success: false,
       kind: payload.kind,
       error: errorMsg,
     }
     ```
     Per `trigger/errors.ts:293–314`, `throwIfNonRetryable` throws `AbortTaskRunError` **only** for permanent errors and **returns normally** for retryable errors (`502`/`503`/timeout). Returning `{ success: false }` instead of calling `rethrowAsTaskError` marks failed Trigger.dev runs as `COMPLETED` and completely disables `retry: { maxAttempts: 3 }` (`render-gotenberg-asset.task.ts:399–404`).
- Impact (business terms): 100% of 4K Umrah multi-package sheets and single-package spotlight posters fail to render on the production Oracle Cloud Gotenberg server (`HTTP 404`), silently fall through to a non-existent local Chrome binary on Vercel/Trigger.dev, and terminate with `COMPLETED` status and zero automatic retries on transient network/503 hiccups.
- Root cause: `gotenberg.ts:119` omitted `/html` from Gotenberg v8's `/forms/chromium/screenshot/html` endpoint, wrapped all remote errors in an unconditional local-CDP catch block, omitted fetch timeouts, and `render-gotenberg-asset.task.ts:380` called `throwIfNonRetryable` instead of `rethrowAsTaskError`.
- Recommended fix: Change `lib/posters/gotenberg.ts:119` to `${baseUrl}/forms/chromium/screenshot/html`; require `GOTENBERG_API_KEY` whenever `GOTENBERG_API_URL` is set in production; add `signal: AbortSignal.timeout(75_000)` to both `fetch` calls (`L119`, `L152`); classify HTTP `400`/`401`/`403`/`404`/`422` as non-retryable errors without falling back to `renderHtmlViaChromiumCdp` when `NODE_ENV === "production"` or `GOTENBERG_API_URL` is configured; and replace `throwIfNonRetryable(err, ...)` + `return { success: false }` in `trigger/render-gotenberg-asset.task.ts:380–386` with `rethrowAsTaskError(err, "RenderGotenbergAssetTask")` when executing inside a Trigger.dev worker.
- Test to add: Unit tests in `tests/multimodal-and-gotenberg.test.ts` mocking `globalThis.fetch` for `renderHtmlViaGotenberg({ html, capturePng: true, capturePdf: true })`, asserting exact `POST` URLs (`.../forms/chromium/screenshot/html` and `.../forms/chromium/convert/html`), `X-Gotenberg-Api-Key` header presence, `AbortSignal` attachment, non-fallback error propagation in `NODE_ENV=production`, and `rethrowAsTaskError` throwing on `HTTP 503` in `runRenderGotenbergAsset`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### A13-002 — Production R2 Local-Disk Fallback Crashes Vercel/Docker and Persists Dead Worker URLs

- Severity: P0
- Category: infra
- Where: `lib/storage/r2.ts:53–82, 187–203, 226–259, 310–335` (`resolveWranglerOauthToken`, `uploadAssetToR2`, `createPresignedUploadUrl`); `app/api/uploads/local/route.ts:36–66` (`handleLocalUpload`); `Dockerfile:38, 47`
- Brief claim contradicted (if any): §4.1 (`docs/PLATFORM_MASTER_BRIEF.md:552`) "When R2 credentials are unset in local development, uploads fall back transparently"
- Evidence:
  1. **Silent production fallback on transient R2 errors & missing env vars (`H3`):** `uploadAssetToR2` (`lib/storage/r2.ts:196–203, 236–259`) and `createPresignedUploadUrl` (`L321–335`) do not gate `public/uploads/r2-local/` on `NODE_ENV !== "production"`. Worse, even when `R2_ACCOUNT_ID`/`R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY` **are** configured in production, any non-2xx R2 response or transient network timeout logs `console.warn` (`L197, 202, 237, 322`), probes host developer files `~/.wrangler/config/default.toml` (`L57–81`, see `A03-003`), and silently writes to local disk:
     ```ts
     const localFilePath = path.join(
       process.cwd(),
       "public",
       "uploads",
       "r2-local",
       ...sanitizedKey.split("/")
     )
     await fs.mkdir(path.dirname(localFilePath), { recursive: true })
     await fs.writeFile(localFilePath, buffer)
     ```
  2. **Guaranteed runtime failure across all 3 production compute runtimes:**
     1. **Vercel Serverless:** `process.cwd()` (`/var/task`) is mounted read-only; `fs.mkdir` at `lib/storage/r2.ts:251` and `app/api/uploads/local/route.ts:58` crashes with `EROFS: read-only file system`.
     2. **Docker Standalone (`Dockerfile:38, 47`):** Line `38` copies `/app/public` as `root:root` (`COPY --from=builder /app/public ./public`, omitting `--chown=nextjs:nodejs` used on `L44–45`), then drops privileges to `USER nextjs` (UID `1001`) on `L47`. Creating `/app/public/uploads/r2-local` throws `EACCES: permission denied`, and Next.js standalone mode does not dynamically serve runtime files written into `public/` cleanly across multi-replica restarts.
     3. **Trigger.dev Cloud Workers (`H6`):** Background tasks (`render-gotenberg-asset.task.ts`, `mirror-whatsapp-media.task.ts`, `extract-packages.task.ts`) run in ephemeral Trigger.dev containers. If R2 env vars are missing in the Trigger.dev dashboard or R2 returns a transient `503`, `uploadAssetToR2` writes the PDF/poster/WhatsApp media to the **ephemeral worker container's disk** and saves `url: "/uploads/r2-local/..."` into Neon PostgreSQL — producing a permanent `HTTP 404` on the Next.js web domain where that file never existed.
  3. **Broken S3 endpoint URL persisted when `R2_PUBLIC_URL` is unset:** In `lib/storage/r2.ts:187–189`, `226–228`, and `310–312`, if R2 credentials are set but `R2_PUBLIC_URL` is omitted (`optional()` in `lib/env.ts:49`), `uploadAssetToR2` returns `https://${accountId}.r2.cloudflarestorage.com/${bucketName}/${sanitizedKey}` — the authenticated S3 API endpoint, which rejects unauthenticated browser/Meta/TikTok `GET` requests with `HTTP 400/403`.
- Impact (business terms): Any missing `R2_*` secret on Trigger.dev/Vercel or a 1-second Cloudflare R2 hiccup either crashes uploads (`EROFS`/`EACCES`) or silently records broken `/uploads/r2-local/...` and `.r2.cloudflarestorage.com` URLs in PostgreSQL, permanently losing generated customer PDF quotes, supplier flyers, and inbound WhatsApp pilgrim attachments.
- Root cause: Local dev filesystem fallbacks and Wrangler CLI config scraping were left active in production code paths and wired as `catch`-block fallbacks for S3 API errors, while `R2_PUBLIC_URL` was left optional without validation.
- Recommended fix: Restrict `public/uploads/r2-local/`, `/api/uploads/local`, and `resolveWranglerOauthToken()` strictly to `process.env.NODE_ENV === "development" || process.env.NODE_ENV === "test"` (and delete `resolveWranglerOauthToken` per `A03-003`); require `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, and `R2_PUBLIC_URL` in production startup validation (`lib/env.ts`); throw typed retryable errors on R2 `5xx`/network failures instead of falling back to disk; and add `--chown=nextjs:nodejs` on `Dockerfile:38` if Docker local-testing is ever used.
- Test to add: Unit tests in `tests/r2-production-guards.test.ts` verifying that under `NODE_ENV="production"`, `uploadAssetToR2` and `createPresignedUploadUrl` throw immediately when `R2_*` or `R2_PUBLIC_URL` is missing or when R2 returns `HTTP 503` (never writing to `public/uploads/r2-local/`), and `/api/uploads/local` returns `HTTP 404`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### A13-003 — Campaign Video & Fallback Upload Pipeline Rejects Videos, Sends Malformed FormData, and Saves Ephemeral blob: URLs

- Severity: P0
- Category: functional
- Where: `app/api/uploads/presign/route.ts:8–32, 57–63` (`presignRequestSchema`, `POST`); `app/api/uploads/local/route.ts:18–66` (`handleLocalUpload`); `components/admin/hubs/campaigns-hub-client.tsx:1060–1115` (`handleFileUpload`); `lib/storage/r2.ts:304–309` (`createPresignedUploadUrl`)
- Brief claim contradicted (if any): §6.4 (`docs/PLATFORM_MASTER_BRIEF.md:863`) "Core 5 OAuth & native direct publishing across... Reels, TikTok, YouTube"
- Evidence:
  1. **`/api/uploads/presign` blocks 100% of video MIME types required for Reels, TikTok & YouTube Shorts:** `app/api/uploads/presign/route.ts:8–24` restricts `contentType` exclusively to `["image/jpeg", "image/jpg", "image/png", "image/webp", "application/pdf"]` and caps `sizeBytes` at `52428800` (50 MB, `L30`). Every `.mp4`/`.mov`/`.webm` video uploaded in Campaign Composer (`campaigns-hub-client.tsx:1065–1074`) is rejected with `HTTP 400 Unsupported file type`. Meanwhile, `sizeBytes` is validated in `presign/route.ts` but **never passed** to `createPresignedUploadUrl` (`L58–62`) or signed into `PutObjectCommand` (`lib/storage/r2.ts:304–308`, complementing `A03-002`).
  2. **Triple protocol mismatch in `campaigns-hub-client.tsx` fallback (`L1091–1104`):** When `presignRes.ok` is false (e.g., any video upload or R2 error), `handleFileUpload` posts `FormData` to `/api/uploads/local`:
     ```ts
     const formData = new FormData()
     formData.append("file", file)
     formData.append("folder", "social-media")
     const localRes = await fetch("/api/uploads/local", {
       method: "POST",
       body: formData,
     })
     if (localRes.ok) {
       const localData = await localRes.json()
       if (localData.url) {
         setMediaUrls((prev) => [...prev, localData.url])
         return
       }
     }
     ```
     Inspecting `app/api/uploads/local/route.ts:18–66` shows three bugs in those 14 lines: (a) `/api/uploads/local` requires `?key=` or `x-upload-key` (`L18–28`), so `POST /api/uploads/local` always fails with `HTTP 400 Missing required 'key' query parameter`; (b) even if `key` were provided, `await req.arrayBuffer()` (`L49`) writes the raw `multipart/form-data` boundary headers into the file rather than extracting `formData.get("file")`; and (c) the route returns `{ publicUrl }` (`L63`), whereas the client checks `localData.url` (`undefined`).
  3. **Ephemeral browser `blob:` URL persisted to PostgreSQL (`L1106–1111`):** After both uploads fail, `campaigns-hub-client.tsx:1106–1111` silently succeeds in the UI by appending `URL.createObjectURL(file)`:
     ```ts
     const objUrl = URL.createObjectURL(file)
     setMediaUrls((prev) => [...prev, objUrl])
     ```
     Because Zod's `z.string().url()` accepts `blob:https://...` strings, `createScheduledSocialPostAction` persists the tab-local `blob:` URL into `scheduledPosts`. When `publish-social-post.task.ts` executes on Trigger.dev at the scheduled PKT window, the worker cannot fetch `blob:...`, failing 100% of custom video Reels/TikTok/YouTube Shorts posts.
- Impact (business terms): Marketing staff cannot upload any MP4/MOV video for Instagram Reels, Facebook Reels/Stories, TikTok, or YouTube Shorts; worse, the Campaign Composer appears to succeed using a temporary `blob:` preview URL and then fails hours later when the scheduled campaign attempts to publish.
- Root cause: `presignRequestSchema` was written only for Studio image/PDF flyers and later reused by Campaign Composer without adding `video/mp4` / `video/quicktime`, while `campaigns-hub-client.tsx` implemented an untested `FormData` + `URL.createObjectURL` fallback against a raw-body `PUT` route.
- Recommended fix: Add `video/mp4`, `video/quicktime`, and `video/webm` to `presignRequestSchema` (`app/api/uploads/presign/route.ts:13–20`) with per-MIME size caps (e.g., `25 MB` images/PDFs, `250 MB` videos) and bind `ContentLength: sizeBytes` in `PutObjectCommand` (`lib/storage/r2.ts:304–308`); remove the broken `FormData` `/api/uploads/local` call and `URL.createObjectURL` fallback in `campaigns-hub-client.tsx:1091–1112` so upload failures surface an explicit toast error; and reject `blob:` / `data:` URLs in `createScheduledSocialPostAction`'s Zod schema (`https://` only in production).
- Test to add: Integration test in `tests/campaign-uploads.test.ts` verifying `/api/uploads/presign` issues signed `PutObjectCommand` URLs with `ContentLength` for `video/mp4` and `image/jpeg`, rejects oversized payloads, and `createScheduledSocialPostAction` rejects `blob:https://...` media URLs.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### A13-004 — Local Chromium CDP Fallback Runs in Production With --no-sandbox, Unbounded CDP Promises, and Zombie Process Leaks

- Severity: P1
- Category: reliability
- Where: `lib/posters/chromium-cdp.ts:7–30, 93–138, 159–288` (`CHROME_CANDIDATES`, `CdpSession`, `renderHtmlViaChromiumCdp`); `lib/posters/gotenberg.ts:91–93, 170–175`; `Dockerfile:7`; `trigger.config.ts:1–20`
- Brief claim contradicted (if any): §2.1 (`docs/PLATFORM_MASTER_BRIEF.md:236`) "Gotenberg Engine v8.17.0 (Chromium headless via Caddy TLS reverse proxy)"
- Evidence:
  1. **Active in `NODE_ENV=production` across Chrome-less runtimes (`H2`):** `lib/posters/chromium-cdp.ts:7–16` probes hardcoded Windows workstation paths (`C:\Program Files\Google\Chrome\Application\chrome.exe`, `msedge.exe`) and Linux paths (`/usr/bin/google-chrome`, `/usr/bin/chromium`), invoked unconditionally whenever `GOTENBERG_API_URL` is unset (`gotenberg.ts:91–93`) or throws (`L175`). Neither Vercel Serverless, `Dockerfile:7` (`FROM node:20-alpine`), nor `trigger.config.ts:1–20` (zero Puppeteer/Chromium build extensions) installs Chrome, guaranteeing runtime failure in production.
  2. **`--no-sandbox` + unbounded CDP WebSocket & HTTP hangs:** When Chrome *is* present (e.g., local dev or a self-hosted VM), `chromium-cdp.ts:171–184` spawns Chrome with `"--no-sandbox"` (`L175`, disabling Chromium OS process isolation on untrusted HTML; see `A03-001`). In `L187–207`, `proc.stderr.on("data", onData)` and `proc.stdout.on("data", onData)` are never detached after matching the DevTools URL (`stderrBuf` grows for the rest of the render), and there is **no `proc.on("exit")` listener** — if Chrome exits immediately on a bad flag or missing shared library, `wsEndpoint` hangs the full `12000ms` (`L190`). Subsequently, `fetch("http://127.0.0.1:${port}/json/list")` (`L213`), `ws.once("open")` (`L224–227`), and `CdpSession.send()` (`L101–133`) have **zero timeouts** and **zero `ws.on("close")` / `ws.on("error")` rejection handlers**:
     ```ts
     send<T = Record<string, unknown>>(
       method: string,
       params: Record<string, unknown> = {}
     ): Promise<T> {
       const id = this.nextId++
       return new Promise<T>((resolve, reject) => {
         this.pending.set(id, {
           resolve: resolve as (val: unknown) => void,
           reject,
         })
         this.ws.send(JSON.stringify({ id, method, params }))
       })
     }
     ```
     If Chromium crashes (`OOM` rendering a `3240×4560` canvas) while `Page.captureScreenshot` (`L254`) or `Page.printToPDF` (`L262`) is in flight, the WebSocket closes and `cdp.send(...)` **never settles**, wedging the Node request or Trigger.dev worker until `maxDuration: 300` (`trigger.config.ts:9`) expires.
  3. **Zombie Chromium processes & leaked `/tmp/alramlah_cdp_4k_*` directories (`L277–288`):**
     ```ts
     } finally {
       try {
         proc.kill()
       } catch {
         // ignore
       }
       try {
         await fs.rm(userDataDir, { recursive: true, force: true })
       } catch {
         // ignore
       }
     }
     ```
     `proc.kill()` sends asynchronous `SIGTERM` without waiting for `proc` `"exit"` or escalating to `SIGKILL` (and on Windows does not terminate Chrome's renderer/GPU child process tree without `taskkill /T /F`). Executing `fs.rm(userDataDir)` microseconds later fails silently (`EBUSY`/`EPERM` swallowed at `L285`) because Chrome still holds open SQLite/SingletonLock handles, leaking hundreds of MB of `/tmp/alramlah_cdp_4k_*` profile directories and zombie Chromium child processes.
- Impact (business terms): In production, accidental fallback hides real Gotenberg errors; on developer machines or any VM with Chrome installed, a crashed 4K render hangs worker slots for 5 minutes and leaks background Chrome processes and `/tmp` disk space until host exhaustion.
- Root cause: `chromium-cdp.ts` was ported from a single-shot local CLI script without production environment gating, WebSocket close/timeout propagation, or awaited child-process teardown.
- Recommended fix: Refuse to run `renderHtmlViaChromiumCdp` when `process.env.NODE_ENV === "production"` unless an explicit `ALLOW_LOCAL_CHROMIUM_CDP="true"` flag is set; reject all `this.pending` entries on `ws.on("close")` and `ws.on("error")` plus a `30_000ms` per-command timer in `CdpSession.send()`; detach `stdout`/`stderr` listeners once `wsEndpoint` resolves and reject immediately on `proc.once("exit")`; and in `finally`, await `proc` exit with a `3_000ms` timeout escalating to `proc.kill("SIGKILL")` before calling `fs.rm(userDataDir, { recursive: true, force: true, maxRetries: 3, retryDelay: 200 })`.
- Test to add: Unit test in `tests/chromium-cdp-lifecycle.test.ts` verifying `CdpSession` rejects pending promises immediately when the underlying `WebSocket` emits `"close"` or exceeds timeout, and verifying `renderHtmlViaGotenberg` throws a configuration error rather than invoking `findChromeExecutable` when `NODE_ENV="production"` and `GOTENBERG_API_URL` is unset.
- Effort: M (<1d)
- Confidence: High
- Needs owner decision: no

### A13-005 — Gotenberg Image & HTML Templates Omit Inter, Brand Fonts, and Arabic/Urdu Fonts, Degrading RTL Rendering

- Severity: P1
- Category: functional
- Where: `../scripts/oracle-gotenberg/docker-compose.yml:3`; `lib/posters/render-quotation-pdf.ts:195, 216, 224, 333`; `lib/posters/render-multi-package-poster.ts:145, 152`; `lib/posters/render-single-package-poster.ts:98, 106, 277, 282, 287`; `lib/posters/chromium-cdp.ts:58–66, 89`; `../services/gotenberg/build/Dockerfile:156–169`
- Brief claim contradicted (if any): §5.1 (`docs/PLATFORM_MASTER_BRIEF.md:621`) "Luxury Haramain aesthetic... Cormorant Garamond... Plus Jakarta Sans"
- Evidence:
  1. **Zero `@font-face` declarations & missing fonts inside `gotenberg/gotenberg:8`:** None of the three HTML generators (`render-quotation-pdf.ts`, `render-multi-package-poster.ts`, `render-single-package-poster.ts`) embed local `@font-face` WOFF2 rules or font stylesheets. Instead, they declare system font stacks:
     ```css
     /* render-quotation-pdf.ts:216, 224 & render-single-package-poster.ts:98, 106 */
     body { font-family: 'Inter', 'Noto Sans', sans-serif; ... }
     .cover-brand { font-family: 'Caladea', 'Noto Serif', Georgia, serif; ... }
     ```
     Cross-checking the upstream image definition at `../services/gotenberg/build/Dockerfile:156–169` confirms `gotenberg/gotenberg:8` installs `fonts-crosextra-carlito`, `fonts-crosextra-caladea`, `fonts-liberation`, `fonts-dejavu`, `fonts-noto-cjk`, `fonts-noto-color-emoji`, and `fonts-noto-core` — **neither `Inter` nor Al Ramlah's design-system fonts (`Cormorant Garamond` / `Plus Jakarta Sans` / `Amiri`) nor Urdu Nastaliq (`fonts-nafees` / `fonts-noto-extra` / `Noto Nastaliq Urdu`) nor `fonts-hosny-amiri` is installed**.
  2. **Arabic/Urdu pilgrim & Haramain hotel names lack RTL bidi isolation & Urdu Nastaliq shaping:** Pakistani Umrah pilgrims and supplier flyers routinely supply Urdu/Arabic names (`customerName` at `render-quotation-pdf.ts:333`, Arabic hotel names such as `فندق ساعة مكة فيرمونت` in `makkahHotelName` at `render-single-package-poster.ts:281`). None of the templates set `dir="auto"` or `unicode-bidi: plaintext` on dynamic fields, and `render-single-package-poster.ts:153, 156, 157` applies `letter-spacing: 2px; text-transform: uppercase;` on `.hc-city`, `.hc-name`, and `.hc-dist`. In Chromium on Linux, positive `letter-spacing` without an explicit Arabic Naskh/Nastaliq font stack can break cursive Arabic ligature joining or fall back to low-aesthetic `DejaVu Sans` / tofu `□□□` for extended Urdu/Persian codepoints (`ے`, `ٹ`, `ڈ`, `ڑ`, `ں`, `ﷺ`, `ﷻ`).

## What works

1. **Gotenberg Port `3000` Is Not Bound to Host `0.0.0.0` (`../scripts/oracle-gotenberg/docker-compose.yml:13–16`):** Contrary to the common Docker footgun (`ports: ["3000:3000"]` bypassing `iptables`/UFW and Caddy auth), `docker-compose.yml` correctly uses `expose: ["3000"]` attached only to `gotenberg_internal`, ensuring external internet traffic can reach Gotenberg solely through `caddy-proxy` on ports `80`/`443`.
2. **Oracle Cloud Ubuntu `iptables -I INPUT 1` Ordering Fix (`../scripts/oracle-gotenberg/setup-oracle-arm.sh:76–92`):** The provisioning script explicitly accounts for Oracle Ubuntu images' default `REJECT` rule on the `INPUT` chain by prepending (`iptables -I INPUT 1`) TCP `80`/`443` `ACCEPT` rules rather than appending (`-A`), and persists them via `netfilter-persistent save`.
3. **Caddy TLS Reverse Proxy Split Between `/health` and Authenticated Routes (`../scripts/oracle-gotenberg/Caddyfile:3–22`):** Caddy cleanly separates `GET /health` for uptime probes from `POST /forms/*` conversion endpoints gated by `X-Gotenberg-Api-Key`, enables HTTP/3 (`443/udp`) + `zstd`/`gzip` compression, and sets `depends_on: gotenberg: condition: service_healthy` (`docker-compose.yml:50–52`).
4. **Dedicated Trigger.dev Queue Concurrency Cap (`trigger/queues.ts:7–10`, `trigger/render-gotenberg-asset.task.ts:398`):** `gotenbergQueue` caps concurrent Trigger.dev renders at `concurrencyLimit: 2`, designed to prevent unbounded `batchTrigger` bursts (`trigger/extract-packages.task.ts:441`) from overwhelming the 4-OCPU / 24 GB Oracle Ampere VM once `A13-001` and `A13-006` are resolved.
5. **Self-Contained Inline Assets in Poster/PDF HTML (`lib/posters/chromium-cdp.ts:32–91`):** Company logos (`getCompanyLogoBase64()`) and Saudia/Airblue/PIA airline badges (`AIRLINE_SVG_LOGOS`) are embedded inline as `data:image/png;base64,...` and inline `<svg>` markup, making zero-egress `internal: true` Docker network isolation (`A13-006` fix) straightforward once fonts are bundled locally (`A13-005`).
6. **Path-Traversal Boundary Check in `/api/uploads/local` (`app/api/uploads/local/route.ts:31–47`):** For local-dev usage, `path.resolve(baseDir, ...)` combined with `!targetPath.startsWith(baseDir + path.sep)` properly blocks `../` directory escape outside `public/uploads/r2-local/` (though the route itself must be disabled in production per `A13-002` and `A03-002`).
