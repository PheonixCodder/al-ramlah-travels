### A21-001 — Unlocked Tailwind v4 `dark:*` Variant (`73` Occurrences Across `32` Files) Compiles to Live `@media (prefers-color-scheme: dark)` Without Dark Tokens, Rendering Text Unreadable (`1.03:1`–`1.60:1`) for OS Dark-Mode Users
- Severity: P1
- Category: a11y
- Where: `app/globals.css:1–4, 67–135`, `app/layout.tsx:84–98`, `app/admin/(auth)/login/page.tsx:129`, `components/admin/hubs/connections-settings-client.tsx:1364–1400, 1719, 1831, 2174, 2194, 2231–2232, 3198–3271`, `components/admin/campaigns/whatsapp-broadcast-drawer.tsx:629, 694, 714–715`, `components/admin/hubs/desk-hub-client.tsx:1897, 1965, 1983, 2307, 2341`, `components/admin/whatsapp/whatsapp-linked-device-card.tsx:722, 736`, `components/admin/desk/copilot-realtime-run-banner.tsx:166`, `components/ui/*.tsx` (`26` Base UI primitive files), `.next/static/css/8417dd9e62f45f21.css`
- Brief claim contradicted (if any): `design.md` §2 "single, locked luxury theme... DON'T write `dark:` class overrides"
- Evidence:
  1. Static scan across `196` files in `app/**` and `components/**` found **`73` `dark:*` utility lines across `32` files** (`6` application/admin views + `26` `components/ui/*.tsx` primitives).
  2. Neither `app/globals.css` (`L1–168`) nor `node_modules/shadcn/dist/tailwind.css` declares `@custom-variant dark (&:where(.dark, .dark *));`, and `:root` (`app/globals.css:67`) omits `color-scheme: light`. In Tailwind CSS v4, `dark:*` defaults to `@media (prefers-color-scheme: dark)`.
  3. Inspecting the built production CSS bundle `.next/static/css/8417dd9e62f45f21.css` confirmed **`8` live `@media (prefers-color-scheme:dark)` blocks containing `104` `.dark\:*` rules** (e.g., `.dark\:text-emerald-100`, `.dark\:text-amber-100`, `.dark\:text-rose-100`, `.dark\:text-amber-400`, `.dark\:bg-stone-900`, `.dark\:bg-input\/30`, `.dark\:data-unchecked\:bg-foreground`).
  4. Because `:root` defines only light Warm Ivory (`--background: #FAF6EE`) and Alabaster (`--card: #FFFFFF`) tokens, any pilgrim or admin whose OS is in Dark Mode gets light backgrounds paired with dark-mode foreground overrides: `connections-settings-client.tsx:1370, 1397, 2231–2232` renders `#FEF3C6` (`1.03:1`), `#D0FAE5` (`1.05:1`), and `#FFE4E6` (`1.11:1`) pastel text on pale ivory cards; `login/page.tsx:129` renders `dark:text-amber-400` (`1.60:1`) on the session-expired alert; `whatsapp-broadcast-drawer.tsx:714` & `connections-settings-client.tsx:3198` turn WhatsApp preview shells `#1C1917` stone-black; and `components/ui/switch.tsx:25`, `input.tsx:11`, `button.tsx:12`, and `tabs.tsx:62` apply unintended dark fills across every public and admin form.
- Impact (business terms): Over half of mobile pilgrims and evening admin staff run iOS, Android, macOS, or Windows in system Dark Mode; status banners, OAuth/WABA connection diagnostics, session-expiry alerts on `/admin/login`, and WhatsApp template previews become literally invisible (`~1.05:1` white-on-cream) while native date/time pickers and scrollbars render in mismatched dark chrome.
- Root cause: Tailwind CSS v4 uses `@media (prefers-color-scheme: dark)` unless overridden by `@custom-variant dark`, `:root` lacks `color-scheme: light`, and `dark:*` classes leaked from `shadcn` (`base-nova`) scaffolding and copied admin components.
- Recommended fix: (1) Add `@custom-variant dark (&:where(.dark, .dark *));` at the top of `app/globals.css` (after `@import`s) so no `dark:*` rule ever fires via OS media query since `.dark` is never mounted; (2) add `color-scheme: light;` to `:root` in `app/globals.css`; and (3) strip the `dark:*` classes from `login/page.tsx` and the `5` `components/admin/**` files (`33` application-level occurrences).
- Test to add: Automated CSS build assertion + Playwright E2E test launching `/` and `/admin/login` with `colorScheme: "dark"` verifying `0` `@media (prefers-color-scheme: dark)` `.dark\:*` rules in built CSS and `getComputedStyle(document.documentElement).colorScheme === "light"`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no
