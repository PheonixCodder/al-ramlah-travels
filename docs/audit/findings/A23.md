### 3.2 Serverless-Safe Zero-Paid-Infra Rate-Limit Architecture (`lib/security/rate-limit.ts`)

1. **Better Auth Endpoints (`/api/auth/*`)**:
   - Add Better Auth's `rate_limit` table (`id`, `key` unique, `count` integer, `last_request` bigint) to `db/schema/auth.ts` and configure `lib/auth.ts` with `rateLimit: { enabled: true, storage: "database", customRules: { "/sign-in/email": { window: 60, max: 5 } } }` and `advanced: { ipAddress: { ipAddressHeaders: ["cf-connecting-ip", "x-vercel-forwarded-for", "x-real-ip", "x-forwarded-for"] } }`.
2. **Server Actions & Route Handlers (`rate_limit_buckets` Atomic Upsert)**:
   - Because PostgreSQL executes a single `INSERT ... ON CONFLICT DO UPDATE` statement atomically under row-level lock even over stateless `neon-http`, zero Redis/Upstash subscription is required (while keeping a clean `RateLimitStore` interface if Upstash is ever added later):
     ```sql
     INSERT INTO rate_limit_buckets (bucket_key, hits, window_started_at, expires_at)
     VALUES ($1, 1, NOW(), NOW() + ($2 || ' seconds')::interval)
     ON CONFLICT (bucket_key) DO UPDATE
       SET hits = CASE
             WHEN rate_limit_buckets.expires_at <= NOW() THEN 1
             ELSE rate_limit_buckets.hits + 1
           END,
           window_started_at = CASE
             WHEN rate_limit_buckets.expires_at <= NOW() THEN NOW()
             ELSE rate_limit_buckets.window_started_at
           END,
           expires_at = CASE
             WHEN rate_limit_buckets.expires_at <= NOW() THEN NOW() + ($2 || ' seconds')::interval
             ELSE rate_limit_buckets.expires_at
           END
     RETURNING hits, EXTRACT(EPOCH FROM (expires_at - NOW()))::int AS retry_after_sec;
     ```
   - **Recommended Endpoint Budgets**:
     * `/api/auth/sign-in/email`: `5` req / `60s` per IP + `10` req / `15m` per normalized email.
     * `lookupApplicationStatus`: `5` req / `15m` per IP + `5` failed phone mismatches / `1h` per `referenceNumber` (prevents `ART-YYYY-XXXX` enumeration & phone guessing).
     * `submitCustomApplication`, `submitGroupBookingApplication`, `submitHajjInquiryApplication`, `submitContactMessage`: `5` submissions / `10m` per IP + hidden honeypot field check.
     * `/api/uploads/presign`: `30` URLs / `60s` per `session.user.id`.
   - **Cleanup**: Prune expired rows (`DELETE FROM rate_limit_buckets WHERE expires_at < NOW()`) inside the existing 6-hour maintenance cron (`schedules.task.ts`).
