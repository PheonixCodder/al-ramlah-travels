## 1. Executive Summary & Crawlability Inventory

Al Ramlah Travels currently ships **zero machine-readable crawlability or discovery endpoints**: `/robots.txt`, `/sitemap.xml`, and `/llms.txt` all fall through to `app/not-found.tsx` (`HTTP 404`). Search engines and AI answer engines (`OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`, `Claude-SearchBot`, `Google-Extended`) receive neither an XML sitemap to discover indexable Haramain commercial routes nor `Disallow:` boundaries protecting `/admin/`, `/api/`, `/voucher/`, or future `/quote/` capability paths. Worse, `PublicFooter` renders an explicit crawlable `<Link href="/admin">Staff Operations Portal</Link>` on every public page (`components/layout/public-footer.tsx:274-278`), actively guiding bots into an unauthenticated `307 -> /admin/login` crawl loop.

| Endpoint / Surface | Expected Next.js 16 Artifact | Actual State (`HEAD 6c54d4c`) | HTTP Status | Audit Verdict |

| `/sitemap.xml` | `app/sitemap.ts` (`MetadataRoute.Sitemap`) | Missing (`0` files in `app/` or `public/`) | `404 Not Found` | **FAIL (`S01-002`)** |

## 2. Detailed Findings

### S01-001 — Complete absence of `app/robots.ts` (`404` on `/robots.txt`), missing preview index-block, and public footer `/admin` crawl trap
- Severity: P1
- Category: seo
- Where: `app/robots.ts` (missing), `public/robots.txt` (missing), `components/layout/public-footer.tsx:274-278`, `proxy.ts:126-132`
- Brief claim contradicted (if any): None (Phase B baseline crawlability gap).
- Evidence:
  - Directory listing of `app/` (`error.tsx`, `favicon.ico`, `global-error.tsx`, `globals.css`, `layout.tsx`, `not-found.tsx`, `(public)/`, `admin/`, `api/`, `actions/`) and `public/` (`.gitkeep`, `logo-icon.png`, `logo.jpg`, `tiktok-app-icon-1024.png`) confirms neither `app/robots.ts` nor `public/robots.txt` exists; `.next/prerender-manifest.json` contains no `/robots.txt` route, so `GET /robots.txt` renders `app/not-found.tsx` (`HTTP 404`).
  - Simultaneously, `components/layout/public-footer.tsx:274-278` renders `<Link href="/admin" className="...">Staff Operations Portal</Link>` in the global footer on `/`, `/privacy`, `/terms`, and `/refund-policy`. Every crawl of `/` discovers `/admin`, hits `proxy.ts:129-131`, and follows a `307 Temporary Redirect` to `/admin/login?callbackUrl=%2Fadmin`.
  - No `VERCEL_ENV` / non-production environment check exists to emit `disallow: "/"` on Vercel preview or staging URLs (`*.vercel.app`).
- Impact (business terms): Search engines waste crawl budget hitting `/admin`, `/admin/login?callbackUrl=%2Fadmin`, and `/api/*`, cannot auto-discover `sitemap.xml` via `robots.txt`, and risk indexing non-production preview deployments that cannibalize `https://alramlahtravels.com` rankings.
- Root cause: Phase A focused on functional application routes and security headers (`proxy.ts`) without authoring Next.js App Router metadata route conventions (`app/robots.ts`), while placing an unguarded `/admin` link in the pilgrim-facing footer.
- Recommended fix:
  1. Create `app/robots.ts` returning `MetadataRoute.Robots` (per `nextjs-technical-seo-and-metadata.md` §6 and `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/robots.md`):
     - When `process.env.VERCEL_ENV && process.env.VERCEL_ENV !== "production"` (or `NEXT_PUBLIC_APP_URL` is not `https://alramlahtravels.com` in preview), return `{ rules: [{ userAgent: "*", disallow: "/" }] }` with no `sitemap`.
     - In production, allow `"/"`, disallow `["/admin/", "/api/", "/voucher/", "/quote/", "/_next/"]`, and set `sitemap: "${baseUrl}/sitemap.xml"` and `host: baseUrl` (normalized from `env.NEXT_PUBLIC_APP_URL` without trailing slash).
  2. Remove the public `<Link href="/admin">Staff Operations Portal</Link>` from `components/layout/public-footer.tsx:274-278` (or at minimum replace it with a real pilgrim trust link such as `/refund-policy`, `/about`, or `/faq`; staff access `/admin` directly by bookmark).
- Test to add: Vitest unit test `tests/unit/seo/robots.test.ts` asserting `robots()` returns production `allow: "/"`, `disallow` containing `"/admin/"`, `"/api/"`, `"/voucher/"`, `"/quote/"`, and `sitemap: "https://alramlahtravels.com/sitemap.xml"`, plus a second test case mocking `VERCEL_ENV="preview"` and asserting `disallow: "/"`; plus Playwright/source test verifying `PublicFooter` contains zero `href="/admin"` links.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### S01-002 — Complete absence of `app/sitemap.ts` (`404` on `/sitemap.xml`) across static and dynamic public routes
- Severity: P1
- Category: seo
- Where: `app/sitemap.ts` (missing), `public/sitemap.xml` (missing), `.next/prerender-manifest.json`
- Brief claim contradicted (if any): None (Phase B baseline discovery gap).
- Evidence:
  - `app/sitemap.ts` and `public/sitemap.xml` do not exist anywhere in `c:\dev\al-ramlah-travels\web`.
  - `.next/prerender-manifest.json` lists only `/`, `/_not-found`, `/admin/login`, `/privacy`, `/refund-policy`, and `/terms`. Requesting `GET /sitemap.xml` returns `HTTP 404`.
- Impact (business terms): Google Search Console, Bing Webmaster Tools, and IndexNow/Perplexity discovery pipelines have no canonical XML inventory of Al Ramlah Travels' indexable pages. Newly published Ramadan/Shawwal Umrah group packages (`/umrah-packages/[slug]`) and city/guide hubs (`/umrah-packages/from-lahore`, `/hajj-2027`, `/umrah-visa`, `/hotels/makkah`, `/ziyarat/makkah`) suffer delayed discovery during short seasonal booking windows.
- Root cause: `app/sitemap.ts` was never created during initial App Router scaffolding.
- Recommended fix:
  1. Create `app/sitemap.ts` (`export const revalidate = 3600` or aligned with catalog ISR + `revalidatePath("/sitemap.xml")` inside `app/actions/groups.ts`, `catalog.ts`, and `cms.ts`) returning `Promise<MetadataRoute.Sitemap>`.
  2. Include ONLY canonical `200 OK` indexable public URLs using normalized `baseUrl` (`https://alramlahtravels.com`):
     - Core hubs & trust pages: `/`, `/umrah-packages`, `/umrah-packages/from-lahore`, `/umrah-packages/from-karachi`, `/umrah-packages/from-islamabad`, `/hajj-2027`, `/umrah-visa`, `/hotels/makkah`, `/hotels/madinah`, `/ziyarat`, `/ziyarat/makkah`, `/ziyarat/madinah`, `/about`, `/contact`, `/faq`, `/privacy`, `/terms`, `/refund-policy`.
     - Dynamic active Umrah group package detail spokes (`/umrah-packages/${pkg.slug}`) queried via a resilient DB helper with genuine `lastModified` timestamps (never `new Date()` spam on static routes — use deterministic content/schema revision timestamps for static legal pages and DB `updatedAt` for dynamic entities per `nextjs-technical-seo-and-metadata.md` §5).
  3. Explicitly exclude `/admin/*`, `/api/*`, `/voucher/*`, `/quote/*`, and any redirect or `noindex` routes.
  4. Guard DB queries inside `app/sitemap.ts` with a clean try/catch fallback returning the static hub entries if `DATABASE_URL` is unreachable during isolated CI builds.
- Test to add: Vitest unit test `tests/unit/seo/sitemap.test.ts` mocking active vs inactive DB rows and asserting: (a) every returned `url` starts with `https://alramlahtravels.com` and has no trailing slash (except root if standardized) or query string, (b) zero `/admin`, `/api`, `/voucher`, or inactive package slugs appear, and (c) `lastModified` reflects DB `updatedAt` rather than `Date.now()` across repeated invocations.
- Effort: M (<1d)
- Confidence: High
- Needs owner decision: no

### S01-003 — Missing AI search/citation vs model-training crawler rules in `robots.ts` (`OAI-SearchBot`, `PerplexityBot`, `Claude-SearchBot`, `Google-Extended` vs `GPTBot`, `ClaudeBot`)
- Severity: P1
- Category: seo
- Where: `app/robots.ts` (missing)
- Brief claim contradicted (if any): None.
- Evidence:
  - Because `app/robots.ts` does not exist, there is zero explicit user-agent policy distinguishing **AI search/citation bots** (`OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`, `Perplexity-User`, `Claude-SearchBot`, `Claude-User`, `Applebot-Extended`, `Google-Extended`) from **AI foundation-model training crawlers** (`GPTBot`, `ClaudeBot`, `CCBot`, `Bytespider`), nor restricting AI citation bots from private capability paths (`/voucher/`, `/quote/`, `/admin/`, `/api/`).
- Impact (business terms): Pakistani diaspora and domestic pilgrims increasingly ask ChatGPT Search, Perplexity, Claude Search, and Google AI Overviews queries like *"best licensed Umrah travel agency in Lahore Askari 10"* or *"short-term vs long-term Saudi Umrah visa rules from Pakistan"*. Without explicit allow rules on public routes and disallow rules on `/admin/`, `/api/`, `/voucher/`, and `/quote/`, AI crawlers either lack clear boundaries or risk future blanket blocks that accidentally de-index Al Ramlah Travels from AI citations (per `ai-search-geo-and-crawlers.md` §2: blocking `OAI-SearchBot` or `Googlebot` kills live AI search citations).
- Root cause: No GEO crawler governance policy was defined in code.
- Recommended fix:
  1. In `app/robots.ts`, explicitly configure AI **search & user-citation** agents (`OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`, `Perplexity-User`, `Claude-SearchBot`, `Claude-User`, `Google-Extended`, `Applebot-Extended`) with `allow: "/"` and `disallow: ["/admin/", "/api/", "/voucher/", "/quote/"]`.
  2. Separate **foundation-model training** crawlers (`GPTBot`, `ClaudeBot`, `CCBot`) into a dedicated constant (`ALLOW_AI_TRAINING_BOTS` or explicit rule group) so Al Ramlah Travels can allow or disallow training independently without ever blocking live AI citation/grounding bots. Default recommendation for a local Pakistani brand seeking maximum LLM entity recall: allow public marketing copy on `/` while disallowing `/admin/`, `/api/`, `/voucher/`, `/quote/` (confirm owner preference if `CCBot` / `Bytespider` scraping should be disallowed).
- Test to add: Unit test in `tests/unit/seo/robots.test.ts` asserting `OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`, `Claude-SearchBot`, and `Google-Extended` are explicitly permitted on `"/"` and disallowed on `["/admin/", "/api/", "/voucher/", "/quote/"]`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: yes

### S01-005 — Dynamic DB entity `sitemap.ts` gaps: decoupled `groupDepartures.updatedAt`, unseeded `hajjPackages`, and slugless `hotels` / `ziyaratPlaces`
- Severity: P2
- Category: seo
- Where: `db/schema/packages.ts:43-101`, `db/schema/packages.ts:108-154`, `db/schema/packages.ts:169-206`, `db/schema/catalog.ts:171-225`, `db/schema/catalog.ts:372-390`, `app/(public)/page.tsx:167-258`, `components/public/hajj-inquiry-section.tsx:89-397`, `db/seed.ts`
- Brief claim contradicted (if any): None.
- Evidence:
  - **`groupPackages` vs `groupDepartures` freshness & visibility drift**: `groupPackages` (`db/schema/packages.ts:48,92,97`) has `slug`, `isActive`, and `updatedAt`. However, departure dates, seat counts (`bookedSeats`), and status (`open` | `filling_fast` | `sold_out` | `departed` | `cancelled`) live in `groupDepartures` (`db/schema/packages.ts:108-154`), whose `updatedAt` (`L149`) updates when seats are booked or departures change **without** touching `groupPackages.updatedAt`. Furthermore, `app/(public)/page.tsx:180-258` filters out active packages that have `0` open upcoming PKT departures (`departureDate >= todayPktIso` and `seatsLeft > 0`). If `sitemap.ts` naively queries `groupPackages WHERE isActive = true` while `/umrah-packages/[slug]` `404`s on packages with zero upcoming departures (or vice versa), `sitemap.xml` will emit `404` URLs or stale `lastModified` dates.
  - **`hajjPackages` empty DB fallback**: `hajjPackages` (`db/schema/packages.ts:173,197,202`) defines `slug`, `isActive`, and `updatedAt`, and `app/(public)/page.tsx:128-131` queries `hajjPackages WHERE isActive = true`. However, `db/seed.ts` seeds **zero** `hajjPackages` rows (`0` matches in `db/seed.ts`); `HajjInquirySection` silently falls back to 3 hardcoded client-side packages (`HAJJ_2027_PACKAGES` at `components/public/hajj-inquiry-section.tsx:89-397`) when `packages` is empty.
  - **`hotels` & `ziyaratPlaces` have no `slug` column**: `hotels` (`db/schema/catalog.ts:171-225`) has `id` (`uuid`), `city` (`makkah` | `madinah`), `validUntil` (`L213`), `isActive` (`L216`), and `updatedAt` (`L221`); `ziyaratPlaces` (`db/schema/catalog.ts:372-390`) has `id` (`uuid`), `city`, `isActive` (`L381`), and `updatedAt` (`L386`). Neither table has a `slug` column, so individual hotel/ziyarat rows cannot map directly to `/hotels/[slug]` without either deterministic slug helpers (`lib/seo/slugs.ts`) or aggregating `MAX(updatedAt)` grouped by `city` onto city-level spokes (`/hotels/makkah`, `/hotels/madinah`, `/ziyarat/makkah`, `/ziyarat/madinah`).
- Impact (business terms): Misaligned filtering between `app/sitemap.ts` and dynamic spoke `page.tsx` routes causes Google Search Console "Submitted URL not found (404)" or "Submitted URL seems to be a Soft 404" errors, while ignoring `groupDepartures.updatedAt` leaves `sitemap.xml` reporting months-old `lastModified` timestamps even as Ramadan/Shawwal seat availability updates daily.
- Root cause: Catalog tables were originally designed for a single-page modal/builder landing page (`app/(public)/page.tsx`) rather than multi-page hub-and-spoke URL routing and XML sitemap generation.
- Recommended fix:
  1. Centralize public SEO queries in `lib/seo/public-queries.ts` so **both** `app/sitemap.ts` and `/umrah-packages/[slug]` share the exact same indexability predicate (`groupPackages.isActive = true`, rendering past/sold-out packages gracefully as "Sold Out / Request Next Departure" `200 OK` pages or excluding expired-only packages identically in both route and sitemap) and compute `lastModified = max(groupPackages.updatedAt, max(groupDepartures.updatedAt))`.
  2. For `/hotels/makkah`, `/hotels/madinah`, `/ziyarat/makkah`, and `/ziyarat/madinah`, compute `lastModified` in `app/sitemap.ts` as `MAX(updatedAt)` across active rows for that `city` (with `validUntil >= todayPktIso` for `hotels`), falling back to a deterministic baseline date when empty.
  3. For `/hajj-2027`, compute `lastModified` from `MAX(hajjPackages.updatedAt)` where `isActive = true` (with deterministic fallback when `hajjPackages` has 0 DB rows, or extract shared server-visible Hajj 2027 tier constants out of the `"use client"` `hajj-inquiry-section.tsx` file so SSR/JSON-LD and `sitemap.ts` both see Hajj 2027 tiers).
- Test to add: Unit test `tests/unit/seo/public-queries-sitemap-parity.test.ts` verifying that when a `groupDeparture` row has a newer `updatedAt` than its parent `groupPackage`, `sitemap()` emits the newer `groupDeparture.updatedAt` as `lastModified`, and that every slug emitted by `sitemap()` resolves to `200 OK` in `/umrah-packages/[slug]`.
- Effort: M (<1d)
- Confidence: High
- Needs owner decision: no
