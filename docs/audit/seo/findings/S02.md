## 2. Detailed Findings

### S02-001 — Zero `alternates.canonical` tags across `/` and all public routes, leaving UTM and filter query URLs uncapped
- Severity: P1
- Category: seo
- Where: `app/layout.tsx:44-70`, `app/(public)/page.tsx`, `app/(public)/privacy/page.tsx:11-15`, `app/(public)/terms/page.tsx:10-14`, `app/(public)/refund-policy/page.tsx:11-15`
- Brief claim contradicted (if any): None.
- Evidence:
  - Searching the entire `app/` and `lib/` directories for `alternates` or `canonical` returns `0` matches.
  - Note per Next.js Metadata semantics (`nextjs-technical-seo-and-metadata.md` §2): setting `alternates: { canonical: "/" }` only on the root layout does **not** auto-generate per-route canonicals on child pages — child pages that omit `alternates.canonical` would either lack a canonical or inherit the wrong root canonical if set naively! Currently, neither root nor child pages define `alternates.canonical`.
  - Meanwhile, Al Ramlah Travels actively distributes WhatsApp broadcasts, Meta ads, Core 5 social auto-plugs (`ART-...` refs), and deep links (`/?utm_source=whatsapp&utm_campaign=ramadan`, `/#journey-builder`), every variation of which resolves `200 OK` without `<link rel="canonical" href="https://alramlahtravels.com/...">`.
- Impact (business terms): Link equity from WhatsApp shares, Instagram/Facebook/TikTok bio & first-comment links, and Google Business Profile UTM links fragments across parameterized URL variants (`/?fbclid=...`, `/?utm_source=...`), causing Google Search Console "Duplicate without user-selected canonical" warnings and diluting ranking signals for core Umrah/Hajj landing pages.
- Root cause: No shared `buildPageMetadata({ path, title, description, ... })` helper was created to enforce per-page self-referencing `alternates.canonical`.
- Recommended fix:
  1. Create `lib/seo/metadata.ts` exporting `buildPublicMetadata({ path, title, description, ogImage, noIndex })` that always sets `alternates: { canonical: path }` (resolved against `metadataBase` in `app/layout.tsx`, e.g. `"/"`, `"/privacy"`, `"/terms"`, `"/refund-policy"`, `"/umrah-packages"`, `"/umrah-packages/ramadan-last-ashra"`), stripping all query strings and trailing slashes.
  2. Do **not** set a static `alternates.canonical: "/"` inside `app/layout.tsx` (which child routes without `alternates` could inherit erroneously); instead require every indexable `page.tsx` under `app/(public)/**` to call `buildPublicMetadata({ path: "/..." })`.
- Test to add: Vitest suite `tests/unit/seo/canonical-metadata.test.ts` inspecting exported `metadata` / `generateMetadata()` across every indexable `app/(public)/**/page.tsx` and asserting `alternates.canonical` is explicitly defined, starts with `"/"` (or `"https://alramlahtravels.com"`), contains zero `?` or `#`, and has no trailing slash (except `"/"`).
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### S02-002 — `www` vs apex hostname split (`nginx/nginx.conf` serves both `200 OK` while `PublicFooter` links to `https://www.alramlahtravels.com` and `lib/env.ts` uses apex)
- Severity: P1
- Category: seo
- Where: `nginx/nginx.conf:68`, `components/layout/public-footer.tsx:323`, `lib/env.ts:223`, `Dockerfile:21`, `next.config.ts`
- Brief claim contradicted (if any): None.
- Evidence:
  - `lib/env.ts:223` and `Dockerfile:21` define the canonical origin as apex `https://alramlahtravels.com` (`NEXT_PUBLIC_APP_URL=https://alramlahtravels.com`).
  - `nginx/nginx.conf:67-68` configures a single HTTPS `server` block with `server_name alramlahtravels.com www.alramlahtravels.com;` that proxies both hostnames directly to `http://nextjs_upstream` with `HTTP 200` instead of `301`-redirecting `www.alramlahtravels.com` to `https://alramlahtravels.com$request_uri`.
  - Worse, `components/layout/public-footer.tsx:322-329` renders an external anchor `<a href="https://www.alramlahtravels.com" target="_blank" rel="noopener noreferrer">alramlahtravels.com</a>` on every public page, actively sending Googlebot to the `www.` subdomain!
- Impact (business terms): Search engines discover `https://www.alramlahtravels.com` directly from the site's own footer while `NEXT_PUBLIC_APP_URL` points to `https://alramlahtravels.com`, splitting PageRank, backlinks, cookies, and Google Search Console domain properties across two live `200 OK` hosts.
- Root cause: Uncoordinated hostname conventions between `PublicFooter` (`www.`), `lib/env.ts`/`Dockerfile` (apex), and `nginx/nginx.conf` (dual `server_name` without canonical redirect).
- Recommended fix:
  1. Standardize on apex `https://alramlahtravels.com` (matching `lib/env.ts:223` and `Dockerfile:21`).
  2. In `components/layout/public-footer.tsx:322-329`, replace the external `<a href="https://www.alramlahtravels.com" target="_blank">` with an internal `<Link href="/">alramlahtravels.com</Link>` (removing `www.` and `target="_blank"` on a self-link!).
  3. Add a `has: [{ type: "host", value: "www.alramlahtravels.com" }]` permanent `308` redirect rule in `next.config.ts` `redirects()` (or `301` in `proxy.ts` + dedicated `server_name www.alramlahtravels.com { return 301 https://alramlahtravels.com$request_uri; }` block in `nginx/nginx.conf`) so `www.*` permanently redirects to `https://alramlahtravels.com/:path*`.
- Test to add: Unit test on `next.config.ts` `redirects()` (or `proxy.ts`) verifying requests with `Host: www.alramlahtravels.com` permanently redirect (`301`/`308`) to `https://alramlahtravels.com` preserving path and query, plus assertion that `components/layout/public-footer.tsx` contains zero `www.alramlahtravels.com` references.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### S02-003 — `app/layout.tsx` bypasses `lib/env.ts` and falls back to `http://localhost:3000` for `metadataBase` during builds without shell `NEXT_PUBLIC_APP_URL`
- Severity: P1
- Category: seo
- Where: `app/layout.tsx:40-43`, `lib/env.ts:223`, `.next/prerender-manifest.json`
- Brief claim contradicted (if any): None.
- Evidence:
  - `app/layout.tsx:40-43` reads `process.env.NEXT_PUBLIC_APP_URL` directly instead of `env.NEXT_PUBLIC_APP_URL`:
    ```ts
    export const metadata: Metadata = {
      metadataBase: new URL(
        process.env.NEXT_PUBLIC_APP_URL || "http://localhost:3000"
      ),
    ```
  - Meanwhile, `lib/env.ts:223` carefully sets `NEXT_PUBLIC_APP_URL: isBuildPhase ? "https://alramlahtravels.com" : "http://localhost:3000"`, specifically to prevent localhost leakage during `next build`, **but `app/layout.tsx` never imports `env` from `@/lib/env`!**
  - Because `/`, `/privacy`, `/terms`, and `/refund-policy` are statically prerendered at build time (`.next/prerender-manifest.json`), any CI or container build where `process.env.NEXT_PUBLIC_APP_URL` is not injected into the build environment bakes `http://localhost:3000/logo.jpg` (and `http://localhost:3000/...` canonicals) directly into the prerendered HTML `<head>`. Also, if `NEXT_PUBLIC_APP_URL` is malformed in an environment, `new URL(...)` throws an uncaught exception crashing every page render.
- Impact (business terms): Broken `http://localhost:3000` OpenGraph image URLs and canonical tags on WhatsApp, Facebook, LinkedIn, and Google Search whenever a build runs without `NEXT_PUBLIC_APP_URL` explicitly exported in the build shell.
- Root cause: `app/layout.tsx` used raw `process.env.NEXT_PUBLIC_APP_URL || "http://localhost:3000"` before `lib/env.ts` centralized build-phase defaults, and was never updated.
- Recommended fix:
  1. Create a safe `getCanonicalSiteUrl(): URL` helper in `lib/seo/metadata.ts` backed by `env.NEXT_PUBLIC_APP_URL` (falling back safely to `"https://alramlahtravels.com"` in `NODE_ENV === "production"` and validating via `try { return new URL(...) } catch { ... }`), stripping any trailing slash.
  2. Use `metadataBase: getCanonicalSiteUrl()` in `app/layout.tsx:41`.
- Test to add: Unit test `tests/unit/seo/metadata-base.test.ts` verifying `getCanonicalSiteUrl()` resolves to `https://alramlahtravels.com` when `NODE_ENV="production"` and `NEXT_PUBLIC_APP_URL` is unset or malformed, never emitting `http://localhost:3000` in production builds.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### S02-004 — Defense-in-depth `noindex` gaps: `/voucher/[token]` lacks HTTP `X-Robots-Tag`, and `/admin/**` (including statically prerendered `/admin/login`) lacks HTML `metadata.robots`
- Severity: P1
- Category: seo
- Where: `proxy.ts:83-85`, `app/(public)/voucher/[token]/page.tsx:23-31`, `app/admin/(auth)/login/page.tsx:1-20`, `app/admin/(dashboard)/layout.tsx`
- Brief claim contradicted (if any): None.
- Evidence:
  - **Missing HTTP `X-Robots-Tag` on `/voucher/*` (and future `/quote/*`)**: `proxy.ts:83-85` sets `response.headers.set("X-Robots-Tag", "noindex, nofollow")` **only** when `pathname.startsWith("/admin") || pathname.startsWith("/api")`. Capability-signed `/voucher/[token]` URLs (which display lead pilgrim names, booking refs, hotel dates, and KSA emergency details) do **not** receive `X-Robots-Tag: noindex, nofollow, noarchive` at the HTTP header layer. If a voucher URL is ever shared in an email/WhatsApp preview crawler or rendered alongside a PDF download endpoint, header-level `X-Robots-Tag` is absent.
  - **Missing HTML `<meta name="robots" content="noindex, nofollow">` across ALL `/admin/**` routes**: Searching `app/admin/` for `robots` or `metadata` reveals zero `robots` directives. In particular, `app/admin/(auth)/login/page.tsx` is a `"use client"` component statically prerendered at build time (`.next/prerender-manifest.json` -> `"/admin/login"`), so its prerendered HTML `<head>` inherits `app/layout.tsx` default indexable metadata (`<title>Al Ramlah Travels — Bespoke Umrah, Hajj & Haramain Journeys</title>`, **no `<meta name="robots" content="noindex">`**). If `proxy.ts` is ever bypassed or misconfigured on an edge/static cache hit, `/admin/login` is completely indexable in HTML.
  - **Static dev asset in `public/`**: `public/tiktok-app-icon-1024.png` (`370,641 B`) is publicly served and bypasses `proxy.ts` (`proxy.ts:148` excludes `png` from matcher).
- Impact (business terms): Relies on a single layer (`proxy.ts` header alone for `/admin/login`, HTML meta alone for `/voucher/[token]`) to keep admin login screens and pilgrim capability vouchers out of search indexes and AI web caches (`noarchive`, `nosnippet`).
- Root cause: `proxy.ts` and App Router `metadata` were authored independently without enforcing dual-layer (`HTML meta` + `HTTP X-Robots-Tag`) `noindex` on sensitive routes.
- Recommended fix:
  1. Expand `proxy.ts:83` so `pathname.startsWith("/admin") || pathname.startsWith("/api") || pathname.startsWith("/voucher") || pathname.startsWith("/quote")` emits `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet`.
  2. Add `app/admin/layout.tsx` (a thin Server Component layout wrapping `(auth)` and `(dashboard)`) exporting `export const metadata: Metadata = { title: { default: "Staff Operations Portal | Al Ramlah Travels", template: "%s | Al Ramlah Admin" }, robots: { index: false, follow: false, nocache: true, googleBot: { index: false, follow: false, noimageindex: true } } }`.
  3. Update `app/(public)/voucher/[token]/page.tsx:27-30` to include `noarchive: true, nosnippet: true` alongside `index: false, follow: false`, and override `openGraph` / `twitter` to minimal non-PII fallback text.
- Test to add: Unit test in `tests/unit/proxy-headers.test.ts` asserting `proxy()` sets `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` on `/admin/login`, `/api/health`, `/voucher/abc.sig`, and `/quote/xyz`, and does NOT set `X-Robots-Tag: noindex` on `/`, `/umrah-packages`, or `/privacy`; plus metadata unit test verifying `app/admin/layout.tsx` exports `robots.index === false`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### S02-005 — Locked capability vouchers (`/voucher/[token]`) return HTTP `200 OK` instead of `403`, and `/admin/social` is omitted from `next.config.ts` permanent `308` redirects
- Severity: P2
- Category: seo
- Where: `app/(public)/voucher/[token]/page.tsx:43-99`, `components/public/voucher-loader.ts:189-211`, `next.config.ts:201-269`, `app/admin/(dashboard)/social/page.tsx:1-5`
- Brief claim contradicted (if any): `AGENTS.md` ("Legacy `/admin/*` paths remain clean server-side `redirect()` stubs" — 13 of 14 are in `next.config.ts`, `/admin/social` is missing).
- Evidence:
  - **Soft-`403` returning `200 OK` on `/voucher/[token]`**: In `components/public/voucher-loader.ts:189-211`, locked vouchers return `{ ok: false, reason: "unapproved" | "awaiting_deposit", httpStatus: 403, ... }`. However, in `app/(public)/voucher/[token]/page.tsx:43-99`, only `resolved.httpStatus === 404` calls `notFound()` (`L44`); when `resolved.httpStatus === 403`, the Server Component simply returns `<div data-voucher-status="403">...</div>` (`L53-99`), which Next.js App Router serves with **HTTP status `200 OK`**! The `httpStatus: 403` field in `voucher-loader.ts` is never actually wired to the HTTP response status.
  - **Missing permanent redirect entry for `/admin/social`**: `next.config.ts:201-269` configures `permanent: true` (`308`) redirects for 13 legacy admin routes (`/admin/packages`, `/admin/groups`, `/admin/hajj`, `/admin/hotels`, `/admin/rates`, `/admin/cms`, `/admin/suppliers`, `/admin/posters`, `/admin/whatsapp`, `/admin/whatsapp-groups`, `/admin/outreach`, `/admin/analytics`, `/admin/users`), **omitting `/admin/social`**, which instead hits `app/admin/(dashboard)/social/page.tsx:4` (`redirect("/admin/campaigns?tab=social")` -> temporary `307`).
- Impact (business terms): Automated monitoring, link checkers, and crawlers hitting locked voucher URLs see `HTTP 200 OK` instead of an access-denied `403`/`404` status (soft-error behavior), while `/admin/social` behaves inconsistently (`307` after auth layout execution) compared to the other 13 legacy admin redirects (`308` at config edge).
- Root cause: Next.js App Router `page.tsx` components cannot set arbitrary HTTP status codes via JSX data attributes (`data-voucher-status="403"`); emitting HTTP `403` in Next.js 16 requires `forbidden()` from `next/navigation` with `experimental: { authInterrupts: true }` + `app/(public)/voucher/[token]/forbidden.tsx` (per `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/forbidden.md`), and `/admin/social` was overlooked when populating `next.config.ts:201-269`.
- Recommended fix:
  1. Enable `experimental: { authInterrupts: true }` in `next.config.ts` and move the locked-voucher card UI (`app/(public)/voucher/[token]/page.tsx:53-99`) into `app/(public)/voucher/[token]/forbidden.tsx`, calling `forbidden()` when `resolved.httpStatus === 403` so Next.js 16 genuinely returns **HTTP `403 Forbidden`** while rendering the luxury Haramain locked-voucher notice (note: check existing voucher unit/E2E tests to ensure `forbidden()` assertion compatibility).
  2. Add `{ source: "/admin/social", destination: "/admin/campaigns?tab=social", permanent: true }` to `next.config.ts:201-269` so all 14 legacy admin routes share uniform `308` edge redirects.
- Test to add: Integration/route test asserting `GET /voucher/<valid-hmac-for-unapproved-quote>` returns HTTP status `403` (not `200`), and config test asserting `next.config.ts` `redirects()` includes all 14 legacy `/admin/*` paths including `/admin/social`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no
