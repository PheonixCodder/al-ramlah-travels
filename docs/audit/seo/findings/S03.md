## 1. Executive Summary & Quantitative CWV / RSC Inventory

Al Ramlah Travels' public landing page (`app/(public)/page.tsx`) correctly opts into ISR (`export const revalidate = 300`, avoiding `force-dynamic`), **but `96.4%` of public and planner TSX component files (`27 of 28` files, `14,111 of 14,138` lines = `99.8%` of component LOC)** carry top-level `"use client"` directives. Combined with unprojected `SELECT *` Drizzle rows passed directly as props into client trees, `.next/prerender-manifest.json` records a prerendered `/` payload of **`408,033 bytes` (`398.5 KB` HTML + RSC Flight stream)**. On Largest Contentful Paint (LCP), `HeroSlider` (`components/public/hero-slider.tsx`) is a `"use client"` component that mounts **all** carousel `<Image fill>` slides simultaneously in the DOM, uses the **deprecated Next.js 15 `priority` prop** (`image.md:294`), competes in `<head>` against `PublicHeader`'s `40×40` logo `priority` preload (`components/layout/public-header.tsx:180`), fetches cold external Unsplash hero imagery, and runs a `duration-10000 scale-105` CSS transform on the LCP element.

## 2. Detailed Findings

### S03-001 — `99.8%` client-component LOC skew across `components/public/*` & `components/planner/*` + `398.5 KB` `/` HTML/RSC Flight payload from unprojected DB rows and eager modal/step imports
- Severity: P1
- Category: seo
- Where: `components/public/marketing-sections.tsx:1-518`, `components/layout/public-header.tsx:1-342`, `components/public/group-packages-section.tsx:1-579`, `components/planner/custom-journey-builder.tsx:11-20`, `app/(public)/page.tsx:100-141,338-345`, `.next/prerender-manifest.json`
- Brief claim contradicted (if any): None.
- Evidence:
  - `27 of 28` `.tsx` files in `components/public/` and `components/planner/` (`14,111 / 14,138` lines = `99.8%`) declare `"use client"` at line 1, violating the Next.js App Router RSC-first target (`>=70%` Server Components on marketing/content surfaces per `nextjs-technical-seo-and-metadata.md` §3).
  - **`MarketingSections` (`components/public/marketing-sections.tsx:1-518`)**: Marks 518 lines of completely static trust, process timeline, Ziyarat showcase, and verified testimonial markup `"use client"` solely because the bottom `<Accordion>` FAQ (`L477-513`) uses interactive state.
  - **`PublicHeader` (`components/layout/public-header.tsx:1-342`)**: Marks the entire desktop navigation bar, brand emblem, and top utility strip `"use client"` solely for mobile `<Sheet>` drawer state (`mobileOpen`) and the 60s prayer clock `useEffect` (`L140-155`).
  - **Eager modal & multi-step JS hydration**: `GroupPackagesSection` (`components/public/group-packages-section.tsx:41,566-570`) statically imports `GroupBookingModal` (`801` lines) and mounts a `<GroupBookingModal>` instance inside every rendered group package card on initial load. Similarly, `CustomJourneyBuilder` (`components/planner/custom-journey-builder.tsx:11-20`) statically imports Steps 2–6 (`FlightPreferencesModule` 621L, `HotelSelectionModule` 479L, `TransportSelectionModule` 456L, `ZiyaratSelectionModule` 600L, `ReviewAndSubmitStep` 1,054L, `LeadCaptureDialog` 485L = `3,695` lines) even though 100% of visitors start on Step 1 (`setup`).
  - **Unprojected `SELECT *` RSC Flight serialization (`398.5 KB` `/` HTML)**: `app/(public)/page.tsx:100-137` runs `db.select().from(hotels)`, `db.select().from(vehicles)`, `db.select().from(ziyaratPlaces)`, `db.select().from(visaPricing)`, `db.select().from(serviceCharges)`, and `db.select().from(hajjPackages)` and passes full Drizzle row objects into `"use client"` components (`page.tsx:338-345`), serializing internal columns (`sharingPriceSar`, `roomPriceSar`, `quadPriceSar`, `defaultRateSar`, `updatedByUserId`, `createdAt`, `updatedAt`, `isActive`) into `self.__next_f.push(...)` inside the `408,033`-byte prerendered `/` HTML! (Note: check overlap with security/data minimization — internal SAR supplier rate columns on `hotels`/`vehicles` do not even need to be shipped to the browser when volatile services show `"Live Rate — Confirmed upon submission"`!)
- Impact (business terms): Mid-tier Android phones on Pakistani 4G networks (`Jazz`, `Zong`, `Telenor`) must download ~`400 KB` of uncompressed HTML/RSC payload plus hydrate `>14,000` lines of client JS on `/`, degrading Interaction to Next Paint (INP > 200ms) when tapping "Build Custom Plan" or WhatsApp CTAs and lowering Google Mobile Core Web Vitals rankings.
- Root cause: Rapid vertical-slice feature delivery placed `"use client"` at section/shell roots instead of isolating interactive leaf islands (`FaqAccordionClient`, `MobileNavDrawer`, `PrayerPillClient`) and lazily loading off-screen wizard steps/modals.
- Recommended fix:
  1. Convert `MarketingSections` (`components/public/marketing-sections.tsx`) into a pure Server Component and extract only the interactive `<Accordion>` block (`L477-513`) into a small `components/public/faq-accordion-client.tsx` leaf island; ensure all new Phase B hub/spoke pages (`/umrah-packages/**`, `/hajj-2027`, `/umrah-visa`, `/hotels/**`, `/ziyarat/**`, `/about`, `/contact`, `/faq`) are `>=80%` Server Components.
  2. Split `PublicHeader` into a Server Component shell (`PublicHeader`) with two tiny client leaf islands (`PrayerStatusPill` and `MobileNavSheet`).
  3. Dynamically import `GroupBookingModal` (`next/dynamic` with `ssr: false`) and mount a **single** shared modal instance only when `bookingModalPkg !== null` instead of N instances inside `.map()`. Dynamically import Steps 2–6 and `LeadCaptureDialog` inside `CustomJourneyBuilder`.
  4. Project/sanitize public DTOs in `app/(public)/page.tsx` (and `lib/seo/public-queries.ts`) so only fields actually rendered by the client UI are serialized into the RSC Flight payload (stripping `createdAt`, `updatedAt`, `updatedByUserId`, and internal SAR supplier rate columns where unused).
- Test to add: Vitest architectural budget test `tests/unit/seo/rsc-client-budget.test.ts` asserting: (a) `MarketingSections` and all new `app/(public)/**/page.tsx` spoke files have zero top-level `"use client"`, (b) public DTO mappers strip internal `updatedByUserId` / unused SAR columns, and (c) only 0 `GroupBookingModal` instances mount prior to user click.
- Effort: M (<1d)
- Confidence: High
- Needs owner decision: no

### S03-002 — Hero LCP degradation: deprecated Next.js 16 `priority` prop, competing navbar logo preload, simultaneous multi-slide DOM mount, and cold external Unsplash origin
- Severity: P1
- Category: seo
- Where: `components/public/hero-slider.tsx:1-62,145-174`, `components/layout/public-header.tsx:174-181`, `app/not-found.tsx:18-24`
- Brief claim contradicted (if any): `AGENTS.md` ("Read the relevant guide in `node_modules/next/dist/docs/` ... Heed deprecation notices").
- Evidence:
  - **Deprecated Next.js 16 `priority` prop**: Per `node_modules/next/dist/docs/01-app/03-api-reference/02-components/image.md:292-294`, *"Starting with Next.js 16, the `priority` property has been deprecated in favor of the `preload` property in order to make the behavior clear."* Yet `components/public/hero-slider.tsx:167`, `components/layout/public-header.tsx:180`, `app/not-found.tsx:22`, and `app/admin/(auth)/login/page.tsx` all pass the deprecated `priority` prop.
  - **Competing `<head>` image preloads**: `PublicHeader` (`components/layout/public-header.tsx:174-181`) puts `priority` on the tiny `40×40` `/logo.jpg` emblem, injecting a `<link rel="preload" as="image">` in `<head>` that competes for early TCP/HTTP bandwidth against the full-bleed `100vw` Hero LCP backdrop (`hero-slider.tsx:167`).
  - **All carousel slides mounted simultaneously in DOM**: `HeroSlider` (`hero-slider.tsx:145-174`) maps over all `activeSlides` (`3` fallback slides or N DB `heroSlides`) and renders an `<Image fill sizes="100vw" />` for **every** slide at initial render (`opacity-0 pointer-events-none` for `idx !== 0`). Because hidden slides still sit inside the above-the-fold viewport (`inset-0`), browsers with `loading="lazy"` consider `opacity-0` in-viewport `<img>` elements visible and immediately fetch **all 3–5 full-viewport `100vw` hero images concurrently** on page load!
  - **External Unsplash origin + CSS scale transition on LCP**: `FALLBACK_SLIDES` (`hero-slider.tsx:25-62`) and seeded `heroSlides` point to `https://images.unsplash.com/...` (`w=1920`), incurring upstream cross-origin fetch + `sharp` transcoding latency on cold Next.js image cache misses, and `hero-slider.tsx:166` applies `scale-105 transition-transform duration-10000` on the LCP `<img>`.
- Impact (business terms): Mobile pilgrims concurrently download 3+ full-bleed `100vw` hero images plus a competing logo preload on initial visit, pushing mobile LCP past the `2.5s` Good threshold (`3.5s–5.5s` on 4G) and hurting both Google search rankings and paid Meta/TikTok landing-page conversion rates.
- Root cause: Classic CSS-opacity carousel pattern (`slides.map(...)` with `opacity-0`) combined with Next.js 15 `priority` prop carry-over.
- Recommended fix:
  1. Replace deprecated `priority` with Next.js 16 `preload={idx === 0}` (or `fetchPriority="high"` + `loading="eager"` per `image.md:288-290` — note Next.js 16 docs specify not combining `preload` and `loading`/`fetchPriority` on the same `<Image>`) on Slide `0` only, and change `PublicHeader`'s `40×40` `/logo.jpg` (`public-header.tsx:180`) from `priority` to `loading="eager"` (so it loads immediately without injecting a competing `<head>` preload).
  2. In `HeroSlider` (`hero-slider.tsx:145-174`), render `<Image>` **only** for `idx === 0` on initial SSR/mount, and lazily mount `idx === current || idx === (current + 1) % activeSlides.length` **after** hydration/idle (or when carousel auto-advance begins), eliminating concurrent downloads of off-slide `100vw` images!
  3. Add a lightweight warm-emerald/dark `placeholder="blur"` data URI on Slide `0` and host default hero WebP/AVIF assets locally in `public/images/hero/` (or Cloudflare R2 CDN) rather than `images.unsplash.com`.
- Test to add: Unit/render test `tests/unit/seo/hero-lcp.test.ts` verifying initial SSR HTML of `HeroSlider` renders exactly **one** `<img>` element (Slide `0` with `preload` / eager loading) rather than `activeSlides.length` simultaneous `100vw` images, and codebase lint/grep test ensuring zero deprecated `<Image priority` usages remain in `components/public/`, `components/layout/`, and `app/(public)/`.
- Effort: M (<1d)
- Confidence: High
- Needs owner decision: no

### S03-003 — Duplicate uncached `agencySettings` DB queries per public render and missing `revalidatePath` coverage on `/privacy`, `/terms`, `/refund-policy`, and `/sitemap.xml`
- Severity: P2
- Category: seo
- Where: `app/(public)/layout.tsx:16-24`, `app/(public)/page.tsx:138-140`, `app/(public)/privacy/page.tsx:18-20`, `app/(public)/terms/page.tsx:17-19`, `app/(public)/refund-policy/page.tsx:18-20`, `app/actions/catalog.ts:219-221`, `app/actions/cms.ts:70-72`, `app/actions/groups.ts`
- Brief claim contradicted (if any): None.
- Evidence:
  - **Duplicate DB queries within a single render pass**: `app/(public)/layout.tsx:18` executes `db.select().from(agencySettings).limit(1)` (Drizzle query builder, not `fetch`), and then `app/(public)/page.tsx:139`, `privacy/page.tsx:18`, `terms/page.tsx:17`, and `refund-policy/page.tsx:18` each execute an identical second `db.select().from(agencySettings).limit(1)` query without `React.cache()` memoization. As Phase B adds 13+ public hub/spoke routes + JSON-LD generators under `app/(public)/layout.tsx`, every route regeneration will duplicate `agencySettings` round-trips to Neon PostgreSQL.
  - **Incomplete on-demand ISR invalidation**: In `app/actions/catalog.ts:219-221` and `app/actions/cms.ts:70-72`, `safeRevalidatePaths()` only invalidates `["/", "/admin/catalog", "/admin/settings"]`. Updating agency phone/WhatsApp/address/license numbers in `/admin/settings` does **not** revalidate `/privacy`, `/terms`, `/refund-policy` (nor future `/contact`, `/about`, `/umrah-packages/**`, `/sitemap.xml`), creating temporary NAP inconsistency across public pages!
- Impact (business terms): Extra Neon serverless cold-start latency during ISR regeneration and temporary NAP (Name, Address, Phone) mismatches across legal/contact pages vs header/footer after admin settings updates.
- Root cause: Direct inline `db.select().from(agencySettings).limit(1)` calls per file instead of a shared `React.cache()` helper + centralized public-route revalidation list.
- Recommended fix:
  1. Create `getCachedAgencySettings = cache(async () => ...)` in `lib/seo/public-queries.ts` and call it across `app/(public)/layout.tsx`, all public pages, `generateMetadata()`, and JSON-LD builders so Neon is queried at most once per RSC render pass.
  2. Centralize public revalidation in a shared helper (e.g. `revalidatePublicSeoPaths()` or `revalidatePath("/", "layout")` + `revalidatePath("/sitemap.xml")`) invoked whenever `agencySettings`, `groupPackages`, `groupDepartures`, `hajjPackages`, `hotels`, or `ziyaratPlaces` mutate.
- Test to add: Unit test verifying `getCachedAgencySettings()` invokes the underlying DB query once across multiple calls in the same request context, and action test verifying catalog/settings mutations call `revalidatePath` covering public spoke layouts and `/sitemap.xml`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### S03-004 — Global preload contention from loading 4 Google Font families (`12` weights) on every route in `app/layout.tsx`
- Severity: P2
- Category: seo
- Where: `app/layout.tsx:2,12-38,77`
- Brief claim contradicted (if any): None.
- Evidence:
  - `app/layout.tsx:12-38` instantiates four separate `next/font/google` families globally on `<html>`:
    1. `Plus_Jakarta_Sans` (`weights: ["400", "500", "600", "700"]`)
    2. `Playfair_Display` (`weights: ["600", "700", "800"]`)
    3. `JetBrains_Mono` (`weights: ["400", "500", "600"]`)
    4. `Amiri` (`weights: ["400", "700"]`, `subsets: ["arabic", "latin"]`)
  - By default in Next.js, every `next/font/google` instance with specified `subsets` sets `preload: true`, injecting WOFF2 `<link rel="preload" as="font" crossorigin>` tags into `<head>` for all 4 font families (including `JetBrains_Mono`, which is only used for monospace numbers/codes below the fold or in admin, and `Amiri` `"latin"` subset, which duplicates Latin glyphs already covered by `Plus_Jakarta_Sans`!).
- Impact (business terms): Excessive WOFF2 preloads in `<head>` compete directly with CSS and the Hero LCP image during the critical first 1.5 seconds on mobile 4G, delaying both First Contentful Paint (FCP) and Largest Contentful Paint (LCP).
- Root cause: All 4 font families were configured identically in `app/layout.tsx` without setting `preload: false` on secondary/decorative fonts or trimming redundant subsets/weights.
- Recommended fix:
  1. Keep `preload: true` (default) ONLY on `Plus_Jakarta_Sans` and `Playfair_Display` (above-the-fold heading + body fonts).
  2. Set `preload: false` on `JetBrains_Mono` and `Amiri` (and restrict `Amiri` to `subsets: ["arabic"]` so its Latin subset is not preloaded unnecessarily).
- Test to add: Source/config test in `tests/unit/seo/fonts-and-cls.test.ts` verifying `JetBrains_Mono` and `Amiri` in `app/layout.tsx` configure `preload: false` and `Amiri` uses `subsets: ["arabic"]`.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### S03-005 — Cumulative Layout Shift (CLS) risks: skeleton-less `next/dynamic()` landing sections, client-clock prayer header mutation, and unguarded null `bannerUrl` package headers
- Severity: P2
- Category: seo
- Where: `app/(public)/page.tsx:29-51`, `components/layout/public-header.tsx:136-156`, `components/public/group-packages-section.tsx:267-278`
- Brief claim contradicted (if any): None.
- Evidence:
  - **Skeleton-less `next/dynamic()` sections**: `app/(public)/page.tsx:29-51` wraps `HajjInquirySection`, `StatusTracker`, `MarketingSections`, and `ContactSection` in `dynamic(() => import(...))` with **no `loading: () => <div className="min-h-[...]" />` fallback**. When a pilgrim navigates via anchor hash (`/#hajj-2027`, `/#status-tracker`, `/#faq`, `/#contact` — all linked directly in `PublicHeader` `NAV_LINKS` at `public-header.tsx:58-63`!), any deferred chunk boundary without reserved height causes scroll-position jump / CLS.
  - **Client-clock mount mutation in `PublicHeader`**: `components/layout/public-header.tsx:136-143` initializes `prayer` state to `null`, renders a static fallback `"Makkah Prayer Schedule · AST (UTC+3)"` during SSR (`L145-146`), and then synchronously calls `updatePrayer()` inside `useEffect` on hydration (`L142`), replacing the top-bar text width (`"Next in Makkah: Maghrib · 6:28 PM AST"`), which can wrap or shift utility bar items on narrow viewports.
  - **Package card banner fallback**: `GroupPackagesSection` (`components/public/group-packages-section.tsx:267-278`) has a fixed `h-52` wrapper (good for CLS), but when `pkg.bannerUrl` is null (as happens on freshly extracted Studio packages before cover image upload), it renders a completely blank `bg-muted` gray box instead of a branded Haramain luxury placeholder.
- Impact (business terms): Anchor navigation (`/#contact`, `/#faq`, `/#hajj-2027`) jumps unexpectedly on slower mobile devices, and header utility text shifts subtly upon hydration.
- Root cause: Missing `loading` skeletons on `next/dynamic()` imports (plus `MarketingSections` shouldn't even need `next/dynamic` once converted to a Server Component per `S03-001`!) and SSR-to-CSR text length change in `PublicHeader`.
- Recommended fix:
  1. Render `MarketingSections` directly as a zero-JS Server Component (eliminating `next/dynamic` on it completely) and provide fixed `min-h` skeleton placeholders on any remaining `next/dynamic` client sections.
  2. Reserve fixed single-line `truncate min-w-[240px]` container width on the top utility prayer pill in `PublicHeader` so hydration from static label to live AST prayer countdown causes `0.000` layout shift.
  3. Render a branded Haramain geometric/emblem fallback inside the `h-52` card header when `pkg.bannerUrl` is null.
- Test to add: Playwright CLS check (or component unit test) verifying `/#contact` and `/` hydrate with `CLS < 0.05` and top-bar prayer container maintains fixed single-line height across SSR -> CSR hydration.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no
