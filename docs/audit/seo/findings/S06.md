### S06-001 — `group_packages.slug` exists in PostgreSQL, but zero public `/umrah-packages` or `/umrah-packages/[slug]` routes or crawlable `<Link>` elements exist
- Severity: P1
- Category: seo
- Where: `web/db/schema/packages.ts:48`, `web/app/(public)/page.tsx:216–259`, `web/components/public/group-packages-section.tsx:26,260–574`
- Brief claim contradicted (if any): None
- Evidence: `groupPackages` already defines `slug: text("slug").notNull().unique()` (`web/db/schema/packages.ts:48`), and `web/app/(public)/page.tsx:218` maps `slug: pkg.slug` into every `PublicGroupPackageItem`. However, inspecting `web/components/public/group-packages-section.tsx:260–574` shows `pkg.slug` is **never referenced or rendered**. Clicking `"Reserve Seats"` (`L530–552`) opens a client-side dialog (`<GroupBookingModal>`, `L566–570`), and neither `/umrah-packages/page.tsx` nor `/umrah-packages/[slug]/page.tsx` exists in `web/app/(public)/`.
- Impact (business terms): Individual Umrah packages (`Royal Ramadan Last Ashra VIP`, `Executive 5-Star Gold`, `Classic Silver 14-Day Family`, `Economy Bronze 21-Day Long-Stay`) and any future packages published from the Admin BYO-Poster Studio (`marketing-ops.ts:1388`) have zero indexable URLs, zero `Product`/`TouristTrip` + `AggregateOffer` rich-result eligibility, and cannot be shared as deep-linked landing pages in WhatsApp/social campaigns.
- Root cause: Database schema anticipated per-package detail routes (`slug` column + `slugSchema` validation), but UI delivery stopped at homepage modal cards.
- Recommended fix:
  1. Confirm **no schema migration is required on `group_packages.slug`** (column already exists and is `NOT NULL UNIQUE`).
  2. Build server-rendered `/umrah-packages/page.tsx` (Hub) and `/umrah-packages/[slug]/page.tsx` (Detail Spoke) (`F-SEO-UMRAH`) displaying full Makkah/Madinah hotel profiles (`distanceMeters`, `starRating`), Quad/Triple/Double/Sharing/Infant PKR breakdown (`multiHotelOptions` + batch overrides), upcoming batch table (`batchCode`, flight numbers, live remaining seats), inclusions/exclusions, `Product`/`TouristTrip` + `BreadcrumbList` JSON-LD, and booking CTA.
  3. Update `GroupPackagesSection` cards to include a crawlable `<Link href={`/umrah-packages/${pkg.slug}`}>View Full Itinerary</Link>` alongside quick modal reservation.
- Test to add: Integration + Playwright test asserting `/umrah-packages` lists all active packages with `<a href="/umrah-packages/<slug>">` links and `/umrah-packages/executive-5-star-gold-umrah` returns `200` with valid `Product`/`AggregateOffer` JSON-LD matching DB PKR rates.

### S06-004 — Studio flyer-to-package publishing prepends internal `art-...` codes to slugs, and admin edits allow unrestricted `slug` mutation without redirect protection
- Severity: P2
- Category: seo
- Where: `web/app/actions/marketing-ops.ts:1389–1392`, `web/components/admin/catalog/group-package-dialog.tsx:355–364`, `web/app/actions/groups.ts:276–306`
- Brief claim contradicted (if any): None
- Evidence:
  1. When staff publish an AI-extracted supplier flyer to the live website via `publishExtractedPackageToCatalogAction` (`web/app/actions/marketing-ops.ts:1389–1392`), `baseSlug` is generated as `${pkg.postCode.toLowerCase()}-${pkg.makkahHotelName ?? pkg.rawTitle}` — producing machine-code-polluted URLs like `/umrah-packages/art-sae-101-al-kiswah-towers-hotel` instead of clean semantic slugs (`/umrah-packages/14-day-makkah-al-kiswah-umrah-package`).
  2. In `GroupPackageDialog` (`web/components/admin/catalog/group-package-dialog.tsx:355–364`) and `upsertGroupPackage` (`web/app/actions/groups.ts:288`), editing an existing package allows overwriting `slug` directly in place with zero warning and no `previous_slugs` redirect lookup, silently breaking any indexed `/umrah-packages/[slug]` URL or distributed WhatsApp/social link.
- Impact (business terms): Machine prefixes (`art-sae-101-...`) lower organic click-through rate (CTR) and dilute URL keyword signals (`nextjs-business-seo-geo-auditor` Pillar 2), while unguarded slug edits on live packages break indexed URLs (`404`) and active social/WhatsApp campaign links.
- Root cause: `slug` had no public route consumer when `marketing-ops.ts` and `GroupPackageDialog` were built, so `slug` was treated as an internal unique string rather than a permanent public permalink.
- Recommended fix: Create a shared `buildSemanticPackageSlug({ durationDays, tier, title, suffix })` helper in `lib/seo/slugs.ts` (`F-SEO-PLAT`) that strips internal `ART-*` codes from the front of the slug (putting uniqueness suffixes at the tail only on collision), and lock `slug` from accidental auto-regeneration once a package is saved (requiring explicit admin confirmation if edited).
- Test to add: Unit test on `buildSemanticPackageSlug` asserting clean lowercase hyphenated output without leading `art-*` prefixes and collision-safe suffixing.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no
