- **Passport Count Rule (`Invariant #4` & `visa-calc.ts:103`)**: `totalPassports = adults + children + infants`. Infants (`<2 yrs`) require a full Saudi Umrah visa and passport entry even though they occupy `0` hotel beds and `0` transport seats.
- **Compliance Rule for `/umrah-visa` (`Invariant #1`, `Invariant #2` & `OD-09a`)**:
  - Render the live **Standalone Visa-Only PKR Table** directly from `visa_rates.pricePkr` (`short_term` `<=30d` vs `long_term` `31–90d`) — never hardcoded numbers!
  - Explain clearly how Nusuk Masar hotel-bundled e-Visas work (`withMasar*DaysSar` brackets) without violating Invariant #2 (bundle packages display `"Live Rate — Confirmed upon submission"`, while standalone `Visa Only` links directly to `/?preset=visa_only#journey-builder` for immediate fixed PKR checkout/submission).

### S07-001 — Hajj 2027 has no dedicated `/hajj-2027` route and locks `1,589` lines of high-authority Maktab, document, and diaspora guidance inside a `next/dynamic` `"use client"` component on `/`
- Severity: P1
- Category: seo
- Where: `web/app/(public)/page.tsx:29–33,354`, `web/components/public/hajj-inquiry-section.tsx:1–1589`
- Brief claim contradicted (if any): None
- Evidence: No `web/app/(public)/hajj-2027/page.tsx` exists (`GET /hajj-2027` returns `404`). Instead, `HajjInquirySection` (`1,589` lines, marked `"use client"` at `L1`) is dynamically imported on `/` (`web/app/(public)/page.tsx:29–33`). Rich, citation-worthy informational assets — Maktab A/B/C zone & Mina camp definitions (`L49–87`), Qurbani & Haramain High-Speed Train add-ons (`L937–973`), the 6-document Hajj checklist (`L980–1052`), and the 3-step pre-registration timeline (`L1054–1119`) — are compiled into client JavaScript on `/` without a dedicated `<title>`, `<h1>`, canonical URL, or `Service`/`FAQPage` JSON-LD.
- Impact (business terms): High-ticket Hajj 2027 queries (`"Hajj 2027 packages Pakistan"`, `"Maktab A vs Maktab B Mina camp difference"`, `"Hajj 2027 pre registration Lahore"`, `"overseas Pakistani Nusuk Hajj vs private Hajj scheme"`) represent `PKR 1.89M–3.65M+` per pilgrim (`PKR 7.5M–14.6M` per family of 4), yet Al Ramlah Travels has zero dedicated URL to rank or earn AI Overview citations for Hajj 2027.
- Root cause: Hajj 2027 inquiry UI was built as a monolithic interactive section inside `/` rather than a server-rendered `/hajj-2027` hub with a lightweight client pre-registration form island.
- Recommended fix: Create `web/app/(public)/hajj-2027/page.tsx` (`F-SEO-GUIDES`) as a React Server Component querying live `hajj_packages` (`isActive = true`), rendering server-side HTML for:
  1. Prominent **Indicative Pre-Registration & Non-Binding Quota Disclaimer** (`OD-09e`: zero confirmed seat/visa guarantee before official Saudi Ministry & Pakistan MORA 1448H/2027 allocations).
  2. Server-rendered Maktab `A+` / `A` / `B` / `C` comparison table (Mina zone, Jamarat distance, Mashair train/bus logistics, shifting vs non-shifting Aziziya stays).
  3. **Pakistani Passport Resident Scheme vs Overseas Diaspora (`Nusuk Hajj` Direct Portal) Eligibility Matrix** (`hajj_packages` / `hajjInquirySchema` already tracks `countryOfResidence` and passport nationality — surface clear truthful guidance for UK/USA/Canada/EU/GCC diaspora vs Pakistan-resident pilgrims).
  4. Server-rendered 6-document readiness checklist + `Service`, `FAQPage`, and `BreadcrumbList` JSON-LD, mounting only the interactive pre-registration form/drawer as a client island (and keeping a concise teaser gateway on `/` linking to `/hajj-2027`).
- Test to add: Playwright/Vitest route test asserting `/hajj-2027` returns `200`, contains server-rendered Maktab comparison HTML, displays the mandatory `OD-09e` indicative pre-registration notice, renders `FAQPage` + `BreadcrumbList` JSON-LD, and submits a valid pre-registration inquiry.

- Confidence: High
- Needs owner decision: no

### S07-002 — `coerceMaktabCode` collapses seeded `Maktab A+` (`PKR 3.65M`) into `Maktab A`, `db/seed.ts` omits `Maktab C`, and Hajj catalog mutations never revalidate public routes
- Severity: P1
- Category: data-integrity
- Where: `web/components/public/hajj-inquiry-section.tsx:424–429,532–535`, `web/db/seed.ts:2334–2419`, `web/app/actions/catalog.ts:1781,1826,1871,1921,1942`
- Brief claim contradicted (if any): None
- Evidence:
  1. `web/db/seed.ts:2337` seeds `hajj-2027-maktab-a-plus-courtyard-vip` with `maktabTier: "A+"` (`PKR 3,650,000`), alongside `maktabTier: "A"` (`PKR 2,590,000`, `L2366`) and `maktabTier: "B"` (`PKR 1,890,000`, `L2394`). However, `coerceMaktabCode` in `web/components/public/hajj-inquiry-section.tsx:424–429` executes:
     `const upper = maktabTier.toUpperCase(); if (upper.includes("B")) return "B"; if (upper.includes("C")) return "C"; return "A";` — silently erasing `"A+"` and mislabeling the `PKR 3.65M` VIP package as regular `"Maktab A"`.
  2. Because `db/seed.ts` seeds 3 rows (`A+`, `A`, `B`) and `0` rows for `Maktab C`, when `hajjPackages.length > 0` (`L532–535`) the 10 hardcoded `HAJJ_2027_PACKAGES` fallback items are bypassed and clicking the `"Maktab C — Value"` tab shows **0 packages**.
  3. All 5 Hajj package CRUD actions in `web/app/actions/catalog.ts` (`L1781, 1826, 1871, 1921, 1942`) call `safeRevalidatePaths(["/admin/groups"])` — revalidating **neither** `"/"` **nor** `"/hajj-2027"`!
- Impact (business terms): VIP Hajj pilgrims see two conflicting `"Maktab A"` tiers with a `PKR 1.06M` price gap (`PKR 3.65M` vs `PKR 2.59M`) without understanding the `A+` Jamarat-adjacent VIP camp distinction, budget pilgrims see an empty `Maktab C` tab, and admin edits in `/admin/catalog` never appear on the public site until redeploy.
- Root cause: `MaktabCode` union type (`"A" | "B" | "C"` at `L29`) was narrower than `hajjPackages.maktabTier` (`"A+"`, `"A"`, `"B"`, `"C"`), `db/seed.ts` omitted a `Maktab C` seed row, and `catalog.ts` revalidation paths missed public Hajj surfaces.
- Recommended fix: Support `"A+" | "A" | "B" | "C"` explicitly across `/hajj-2027` (`F-SEO-GUIDES`) and `HajjInquirySection`, seed an indicative `Maktab C` 2027 package in `web/db/seed.ts` (`F-SEO-PLAT`), ensure all prices carry `"Indicative 2027 Estimate"` badges (`OD-09e`), and add `"/"` + `"/hajj-2027"` to `safeRevalidatePaths` for Hajj CRUD actions.
- Test to add: Unit test verifying `maktabTier: "A+"`, `"A"`, `"B"`, and `"C"` preserve distinct tier labels without collapsing `"A+"` to `"A"`, plus seed check confirming all 4 Maktab tiers have active indicative rows.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no
