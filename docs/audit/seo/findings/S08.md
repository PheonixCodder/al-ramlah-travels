### S08-001 — All 18 Haramain hotels (`10` Makkah, `8` Madinah) are invisible to search engines inside client Wizard Step 3, and Footer hotel links point to `/#journey-builder`
- Severity: P1
- Category: seo
- Where: `web/components/layout/public-footer.tsx:250–263`, `web/components/planner/custom-journey-builder.tsx:72`, `web/app/(public)/` (missing `hotels/makkah/page.tsx` and `hotels/madinah/page.tsx`)
- Brief claim contradicted (if any): None
- Evidence: `PublicFooter` (`web/components/layout/public-footer.tsx:250–263`) renders `"Makkah Clock Tower Hotels"` and `"Madinah Markaziah Stays"`, both linking to `/#journey-builder`. On `/`, `CustomJourneyBuilder` (`web/components/planner/custom-journey-builder.tsx:72`) mounts `<StepHotels />` **only** when `activeStepId === "hotels"` (Step 3). Consequently, initial server HTML on `/` contains **zero** hotel names (*Fairmont*, *Swissôtel Al Maqam*, *Dar Al Taqwa*, *Oberoi Madina*), **zero** gate proximity notes (*Ladies Gate 25*, *Ajyad Gate*, *Ibrahim Al Khalil Road*), and `GET /hotels/makkah` and `GET /hotels/madinah` both return `404`.
- Impact (business terms): High-converting Haramain accommodation queries (`"Madinah hotels near Ladies Gate 25"`, `"Clock Tower Umrah hotel packages Pakistan"`, `"walking distance vs shuttle hotels Makkah"`, `"Markaziyah hotels Madinah for elderly pilgrims"`) cannot discover Al Ramlah Travels in Google Search or AI Overviews (`ChatGPT` / `Perplexity` / `Gemini`), despite the database holding 18 richly structured hotel records across 1★–5★.
- Root cause: Hotel inventory was modeled solely as Step 3 catalog state for the client-side Custom Journey Builder rather than dual-serving dedicated server-rendered city hospitality spokes.
- Recommended fix: Create `web/app/(public)/hotels/[city]/page.tsx` (`generateStaticParams` returning `[{ city: "makkah" }, { city: "madinah" }]`, `dynamicParams = false`) under `F-SEO-GUIDES`:

  3. **Strict Invariant #2 Compliance**: Display `"Live Rate — Confirmed upon submission"` on hotel conversion CTAs (if seasonal reference SAR bands are shown for orientation, label them explicitly as non-binding seasonal catalog references confirmed upon submission). Emit `ItemList` + `BreadcrumbList` + `FAQPage` JSON-LD.
- Test to add: Playwright/Vitest test verifying `/hotels/makkah` renders all 10 Makkah hotels in initial SSR HTML, `/hotels/madinah` renders all 8 Madinah hotels (highlighting Ladies Gate 25 proximity), `/hotels/jeddah` returns `404`, and no standalone fixed PKR checkout price is promised for hotels (Invariant #2).

### S08-002 — All 18 seeded `hotels` carry `validUntil: "2026-12-31"`, creating a hard expiration cliff that would empty `/hotels/makkah`, `/hotels/madinah`, and Step 3 on `2027-01-01`
- Severity: P1
- Category: data-integrity
- Where: `web/db/seed.ts:358,390,422,455,490,522,554,586,618,647,680,711,743,775,807,839,871,908`, `web/app/(public)/page.tsx:167–170`
- Brief claim contradicted (if any): None
- Evidence: Every single one of the 18 hotels in `web/db/seed.ts` sets `validFrom: "2026-01-01", validUntil: "2026-12-31"`. Meanwhile, `web/app/(public)/page.tsx:168` filters hotels using `(!h.validUntil || h.validUntil >= todayPktIso)`. On `2027-01-01` (46 days after `2026-11-15`), `18/18` seeded hotels fail `h.validUntil >= todayPktIso`! If `/hotels/makkah` and `/hotels/madinah` copy that filter, both hotel spoke pages will suddenly drop from 18 properties to **0 properties** overnight on New Year's Day.
- Impact (business terms): Sudden disappearance of all 18ホテル listings on `2027-01-01` causes soft-404 de-indexing on `/hotels/makkah` and `/hotels/madinah` and leaves the Custom Journey Builder Step 3 completely empty of selectable hotels.
- Root cause: `hotels` conflates permanent property catalog visibility (`isActive = true`) with a calendar-year rate-sheet window (`validUntil = "2026-12-31"`).
- Recommended fix:
  1. In `web/db/seed.ts` (`F-SEO-PLAT`), extend `validUntil` on seeded hotels into `2027-12-31` (or rolling future horizon).
  2. In `lib/seo/public-queries.ts` and `/hotels/[city]/page.tsx` (`F-SEO-GUIDES`), query hotels by `isActive = true` **regardless** of `validUntil`: if a hotel's `validUntil` has passed, keep rendering the hotel's permanent profile (`name`, `starRating`, `distanceMeters`, `locationNotes`, `amenities`) with `"Seasonal Tariff Refreshing — Live Rate Confirmed Upon Submission"` rather than dropping the property from the page!
- Test to add: Unit test on the public hotel spoke query passing a mocked date of `"2028-01-15"` and verifying active hotels still render with `"Live Rate — Confirmed upon submission"` instead of returning an empty array.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no
