## 1. Executive Summary

A full scan across `app/**`, `components/**`, and `lib/**` (`git grep -n -E "ld\+json|schema\.org" -- app components lib`) returned **0 matches**. Every public route currently ships with **zero Schema.org JSON-LD blocks** (`has_json_ld_schema: false` on 100% of routes in `docs/audit/seo/baseline/geo_liftability.json`, dragging Pillar 4 Entity/NAP/Schema down to `6.0 / 15`).

Despite having rich, normalized PostgreSQL entities in `agencySettings` (`db/schema/settings.ts`), `groupPackages` + `groupPackageDepartures` (`db/schema/packages.ts`), `hotels` / `ziyaratPackages` / `visaRates` (`db/schema/catalog.ts`), and `faqs` (`db/schema/cms.ts`), search engines and AI citation crawlers (`OAI-SearchBot`, `PerplexityBot`, `Claude-SearchBot`, Google Knowledge Graph) receive zero machine-readable entity graphs.

At the same time, high-ticket Umrah and Hajj travel (`PKR 280,000` to `PKR 4,450,000`) is subject to strict Google Search Central Rich-Result spam enforcement and `OD-10` / `OD-09` invariants:
1. **Zero fake `AggregateRating` or `Review` markup (`OD-10`)**: `db/seed.ts:2325` seeds `0` verified customer reviews, and Google explicitly penalizes self-serving `LocalBusiness` / `TravelAgency` review markup.
2. **Zero fabricated prices on volatile or indicative flows (`OD-09`)**: Custom Journey Builder itineraries with flights/hotels/transport (`"Live Rate — Confirmed upon submission"`) and `/hajj-2027` pre-registration tiers (`isIndicative = true`) must **never** emit fake binding `Offer` checkout prices.
3. **XSS-safe JSON-LD serialization**: Every `<script type="application/ld+json">` block rendering CMS strings (`faqs.answer`, `groupPackages.description`, `agencySettings.officeAddress`) must escape `<` as `\u003c` (`JSON.stringify(data).replace(/</g, "\\u003c")`) so an admin entering `</script>` or `<30 days` cannot break out of the script context.

### Reference Implementation Pattern (`lib/seo/json-ld.ts`)

```tsx
export function serializeJsonLd(schema: Record<string, unknown>): string {
  return JSON.stringify(schema).replace(/</g, "\\u003c");
}

export function JsonLd({ data }: { data: Record<string, unknown> | Record<string, unknown>[] }) {
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{
        __html: JSON.stringify(data).replace(/</g, "\\u003c"),
      }}
    />
  );
}
```

## 3. Detailed Findings

### S09-001 — Zero Schema.org JSON-LD blocks and no XSS-safe JSON-LD serializer across the entire application
- Severity: P1
- Category: seo
- Where: `app/layout.tsx:1-95`, `app/(public)/layout.tsx:1-60`, `app/(public)/page.tsx:1-226`, `app/(public)/privacy/page.tsx:1-190`, `app/(public)/terms/page.tsx:1-225`, `app/(public)/refund-policy/page.tsx:1-194` (0 matches across `app/**`, `components/**`, `lib/**`)
- Brief claim contradicted (if any): None (confirms baseline Pillar 4 gap in `docs/audit/seo/baseline/score_report.md` at `6.0/15`)
- Evidence: Running `git grep -n -E "ld\+json|schema\.org" -- app components lib` returns zero matches. Automated baseline verification in `docs/audit/seo/baseline/geo_liftability.json` confirms `"has_json_ld_schema": false` across 100% of public and dynamic routes (`/`, `/privacy`, `/refund-policy`, `/terms`, `/voucher/[token]`). Furthermore, no shared `<JsonLd />` helper exists in `lib/` to enforce `\u003c` `<` character escaping when serializing admin-editable database records (`faqs`, `groupPackages`, `agencySettings`).
- Impact (business terms): Google Search, Bing, Perplexity, ChatGPT Search, and Google AI Overviews cannot machine-verify Al Ramlah Travels as a licensed Lahore `TravelAgency`, extract live PKR group package availability into Rich Results, or link spoke pages back to a canonical entity `@id`. Additionally, ad-hoc `JSON.stringify()` in `<script type="application/ld+json">` without `.replace(/</g, "\\u003c")` exposes public pages to stored XSS / script-tag breakout if staff paste `<30 days` or `</script>` in CMS fields.
- Root cause: Structured data architecture (`lib/seo/json-ld.ts`) was never scaffolded during initial storefront slices, which focused on interactive client components (`HeroSlider`, `GroupPackagesSection`, `CustomJourneyBuilder`).
- Recommended fix: Create `lib/seo/json-ld.ts` (owned by `F-SEO-PLAT`) exporting typed builders (`buildTravelAgencyJsonLd`, `buildWebSiteJsonLd`, `buildTouristTripJsonLd`, `buildFaqPageJsonLd`, `buildBreadcrumbJsonLd`) and a shared server `<JsonLd data={...} />` component that always serializes via `JSON.stringify(data).replace(/</g, "\\u003c")`. Render appropriate graphs in RSC page/layout trees so crawlers receive structured data on initial HTML response without client hydration.
- Test to add: Unit test `tests/seo/json-ld-serializer.test.ts` asserting `serializeJsonLd({ text: "</script><script>alert(1)</script> <=30 days" })` contains zero raw `<` characters (`\u003c/script>`), strips `undefined` fields, and produces valid parseable JSON when unescaped.
- Effort: S (<2h)
- Confidence: High
- Needs owner decision: no

### S09-003 — Missing truthful `TouristTrip` + `Offer` schema on `/umrah-packages/[slug]` and need for Rich-Result penalty guardrails (`OD-09`, `OD-10`)
- Severity: P1
- Category: seo
- Where: `db/schema/packages.ts:43-163`, `components/public/group-packages-section.tsx:52-77`, `components/public/hajj-inquiry-section.tsx:55-96`, `components/planner/custom-journey-builder.tsx:52-79`, and planned `/umrah-packages/[slug]/page.tsx`
- Brief claim contradicted (if any): None (enforces `OD-09` pricing truthfulness and `OD-10` zero-fake-review mandate)
- Evidence: `db/schema/packages.ts:43-163` defines rich relational data for fixed group packages (`title`, `slug`, `durationNights`, `makkahNights`, `madinahNights`, `quadPricePkr`, `triplePricePkr`, `doublePricePkr`, `sharingPricePkr`, `childWithBedPricePkr`, `infantPricePkr`) and `groupPackageDepartures` (`departureDate`, `returnDate`, `originCity`, `totalSeats`, `bookedSeats`, `status: 'open' | 'sold_out' | 'closed' | 'cancelled'`). Currently, packages render only inside a client modal on `/` (`group-packages-section.tsx`) with zero dedicated `/umrah-packages/[slug]` URLs and zero `TouristTrip` / `Offer` JSON-LD. Meanwhile, `db/seed.ts:2325` seeds `0` testimonials (`testimonials: 0`), `hajjPackages` (`db/schema/packages.ts:199`) carries `isIndicative: true`, and Custom Journey Builder volatile services (`AGENTS.md` Business Invariant #2) have no fixed upfront PKR price.
- Impact (business terms): High-intent transactional searches (`"15 days Umrah package from Lahore price"`, `"Ramadan Umrah package PKR"`) cannot surface price/availability Rich Snippets in Google Search or structured product comparisons in Perplexity/ChatGPT. Conversely, carelessly adding `Offer` with `price: 0` on Custom Builder / indicative Hajj pages or adding hardcoded `AggregateRating` (`4.9★`) would trigger a Google Search Console Structured Data Manual Action across the entire domain.
- Root cause: Individual package spoke routes (`/umrah-packages/[slug]`) and guarded `buildTouristTripJsonLd()` builders do not exist yet.
- Recommended fix: Implement `buildTouristTripJsonLd(pkg, departures)` in `lib/seo/json-ld.ts` and mount it exclusively on `/umrah-packages/[slug]`:
  1. Emit `TouristTrip` (`name`, `description`, `touristType: "Umrah Pilgrims"`, `provider: { "@id": "${SITE_URL}/#organization" }`, `itinerary` `ItemList` for Makkah & Madinah nights/hotels).
  2. Collect positive room-tier prices (`[pkg.sharingPricePkr, pkg.quadPricePkr, pkg.triplePricePkr, pkg.doublePricePkr].filter((n): n is number => typeof n === "number" && n > 0)`). Emit `offers` (`AggregateOffer` with `lowPrice`, `highPrice`, `priceCurrency: "PKR"`, `offerCount`, plus child `Offer` items per room tier) **only when `prices.length > 0`**.
  3. Derive `availability` strictly from future departures (`departureDate >= todayPKT`): `"https://schema.org/InStock"` iff at least one future departure has `status === "open"` and `(totalSeats - bookedSeats) > 0`; else `"https://schema.org/SoldOut"`.
  4. **Hard ban in code & tests**: Never include `aggregateRating` or `review` on `TravelAgency` or `TouristTrip` (`OD-10`), and never emit `Offer.price` on Custom Builder or `isIndicative === true` `/hajj-2027` tiers (`OD-09`).
- Test to add: Unit test `tests/seo/tourist-trip-jsonld.test.ts` testing: (1) valid PKR package with 12 open seats -> `InStock`, `lowPrice: 455000`, `priceCurrency: "PKR"`; (2) `bookedSeats >= totalSeats` or all departures `sold_out`/past -> `SoldOut`; (3) zero/null prices or `isIndicative: true` -> `offers` omitted completely; (4) `aggregateRating` and `review` keys strictly `undefined`.
- Effort: M (<1d)
- Confidence: High
- Needs owner decision: no (resolved by `OD-09` & `OD-10`)

### S09-004 — Visible FAQ accordion lacks `FAQPage` JSON-LD and risks DOM-vs-Schema mismatch without strict 1:1 binding

- Category: seo

- Impact (business terms): AI answer engines (Google AI Overviews, Perplexity, Bing Copilot, ChatGPT Search) heavily weight `FAQPage` (`Question` + `acceptedAnswer`) pairs for direct citation on pilgrim policy questions (e.g., infant visa/bed rules, Makkah-first `JED` entry lock, Short-Term `<=30d` vs Long-Term `>30d` visa rules).
