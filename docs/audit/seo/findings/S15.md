## 1. Executive Summary

Expanding Al Ramlah Travels from a single-page funnel (`/`) to an 18-route Hub-and-Spoke architecture creates **two classes of high-stakes risks**:
1. **Conversion Cropping (Intent Loss Between Spoke & Funnel):** Currently, `PlannerProvider` ([planner-context.tsx:417-795](file:///c:/dev/al-ramlah-travels/web/components/planner/planner-context.tsx#L417-L795)) ignores URL search parameters completely and unconditionally hydrates stale `sessionStorage["alramlah_planner_draft_v1"]` state on mount; meanwhile, post-submission `"Track Application Status Live"` buttons across all 4 modals/wizards assume `#track-status` exists in the current page DOM (making them dead clicks on `/umrah-packages/[slug]` or `/hajj-2027`).
2. **Haramain Domain Invariant Violations on Spoke Pages:** Database catalog tables (`hotels`, `vehicles`, `transport_rates`, `visa_rates`) contain internal wholesale SAR tariffs (`sharingPriceSar`, `roomPriceSar`, `quadPriceSar`, `defaultRateSar`, `ziyaratRateSar` in [db/schema/catalog.ts](file:///c:/dev/al-ramlah-travels/web/db/schema/catalog.ts#L195-L211)). If Wave 6 spoke pages (`/hotels/makkah`, `/hotels/madinah`, `/ziyarat`, `/umrah-packages/from-[city]`) render or emit JSON-LD `Offer.price` from those volatile SAR columns — or omit `OD-09b` (`0`-tier = `"On Request"`), `OD-09c` (`JED` entry lock + mandatory visa dates), or `OD-09e` (`Hajj 2027` Indicative Pre-Registration disclaimer) — they will directly violate core Haramain commercial and regulatory invariants.

## 2. Spoke-to-Conversion Deep-Link Contract (`CustomJourneyBuilder`)

To connect every SEO spoke cleanly into the homepage `CustomJourneyBuilder` (`/#journey-builder`) without duplicating a 2,200-line wizard across 10 routes, `PlannerProvider` (`components/planner/planner-context.tsx`) MUST support a strict Zod-validated URL query-parameter prefill contract:

| Spoke Origin Route | Canonical CTA Href into `CustomJourneyBuilder` | Validated `PlannerProvider` State Mutation (Applied **After** `sessionStorage` Hydration) |
| :--- | :--- | :--- |
| `/umrah-visa` | `/?preset=visa_only#journey-builder` | `setPresetMode("visa_only")` → `pillars = { visa: true, flights: false, hotels: false, transport: false, ziyarat: false }`; keeps mandatory PKT Arrival & Departure dates (`OD-09c`) |
| `/umrah-packages/from-lahore` | `/?preset=complete_umrah&departureCity=LHE#journey-builder` | Resolves `departureCities.find(c => c.airportCode === "LHE")?.id`, sets `flights.departureCityId`, syncs default `contactDraft.customerCity = "Lahore"` |
| `/umrah-packages/from-karachi` | `/?preset=complete_umrah&departureCity=KHI#journey-builder` | Resolves `KHI` → `flights.departureCityId`, syncs default `contactDraft.customerCity = "Karachi"` |
| `/umrah-packages/from-islamabad` | `/?preset=complete_umrah&departureCity=ISB#journey-builder` | Resolves `ISB` → `flights.departureCityId`, syncs default `contactDraft.customerCity = "Islamabad"` |
| `/hotels/makkah` (Hub CTA) | `/?preset=hotels_only&citySequence=makkah_madinah#journey-builder` | `setPresetMode("hotels_only")`, `setCitySequence("makkah_madinah")` (locks `entryAirport = "JED"`, chains stays), advances `activeStepId = "hotels"` |
| `/hotels/makkah` (Hotel Card CTA) | `/?preset=complete_umrah&citySequence=makkah_madinah&hotelId=<uuid>#journey-builder` | Validates `hotelId` exists in `catalog.hotels` (`city === "makkah"`), assigns `stays[0].hotelId`, runs `calculatePrivateRoomSplits(bedAndSeatCount, hotel.availableRoomTypes)` & `allowsPrivateRooms`/`allowsSharedRooms` guards |
| `/hotels/madinah` (Hotel Card CTA) | `/?preset=complete_umrah&citySequence=madinah_makkah&hotelId=<uuid>#journey-builder` | Validates `hotelId` (`city === "madinah"`), sets `citySequence = "madinah_makkah"` (`entryAirport = "MED"`, `exitAirport = "JED"`), assigns `stays[0].hotelId` with room-splitter guard |

> **Next.js 16 SSR/ISR Safety Rule:** Never call `useSearchParams()` directly inside `PlannerProvider` without a `<Suspense fallback={null}>` boundary around the child URL-hydrator component (`<PlannerUrlHydrator />`), otherwise Next.js 16 de-optimizes the entire `/` tree out of static/ISR caching during `npm run build`!

### S15-001 — `PlannerProvider` ignores URL query parameters and lets stale `sessionStorage` overwrite spoke deep-link intent

- Severity: P0
- Category: functional
- Where: [components/planner/planner-context.tsx:417-795](file:///c:/dev/al-ramlah-travels/web/components/planner/planner-context.tsx#L417-L795), [components/planner/custom-journey-builder.tsx:95-112](file:///c:/dev/al-ramlah-travels/web/components/planner/custom-journey-builder.tsx#L95-L112)
- Brief claim contradicted (if any): `N/A — implicit production expectation` (seamless spoke-to-builder prefill across `/umrah-visa`, `/umrah-packages/from-[city]`, `/hotels/[city]`, and `/ziyarat`).
- Evidence:
  - `PlannerProvider` (`planner-context.tsx:430-439`) hardcodes initial `presetMode = "complete_umrah"` and `departureCityId = catalog.departureCities[0]?.id` (`ISB`, because Islamabad has `sortOrder: 1` in `db/seed.ts:189-193`!), with zero inspection of `window.location.search` or `useSearchParams()`.
  - Furthermore, lines `692-794` hydrate `sessionStorage.getItem("alramlah_planner_draft_v1")` on mount — meaning even if initial state props were passed, `sessionStorage` hydration would overwrite them unless URL query parameters explicitly take precedence over `sessionStorage`.
- Impact (business terms): A pilgrim reading *"Umrah Visa Price in Pakistan — PKR 42,500 Fixed Rate"* on `/umrah-visa` who clicks `"Apply for Umrah Visa Only"` (`/?preset=visa_only#journey-builder`) lands on `/` seeing **"Complete Umrah Journey — Live Rate Confirmed upon submission"** (all 5 volatile pillars enabled, fixed PKR price hidden!), or a Lahore pilgrim clicking `"Build Custom Package from Lahore"` (`/?departureCity=LHE#journey-builder`) gets defaulted to Islamabad (`ISB`). This jarring intent mismatch directly kills conversion rate on high-intent SEO landings.
- Root cause: `PlannerProvider` was designed for single-page usage without URL search-parameter hydration or URL-over-`sessionStorage` merge precedence.
- Recommended fix: Add a Zod-validated URL prefill parser (`parsePlannerUrlPrefill` in `components/planner/planner-context.tsx`) invoked via a `<Suspense fallback={null}>`-wrapped child hydrator or inside the mount `useEffect` **immediately after** `sessionStorage` restoration (`L794`), applying valid `preset`, `departureCity` (matching `airportCode` case-insensitively), `citySequence` (enforcing `JED` lock + `recomputeStays`), `hotelId` (enforcing `calculatePrivateRoomSplits` + `allowsPrivateRooms`/`allowsSharedRooms`), and `ziyaratCity` overrides.
- Test to add: `tests/seo/planner-url-prefill.test.tsx` — seeds `sessionStorage["alramlah_planner_draft_v1"]` with `presetMode: "complete_umrah"` and `departureCity: "ISB"`, mounts `CustomJourneyBuilder` with URL `?preset=visa_only` and separately `?departureCity=LHE&citySequence=makkah_only`, asserting URL params win over stale `sessionStorage` while preserving `JED` entry airport lock and PKT dates.

- Confidence: High

### S15-002 — Public catalog queries pass raw internal wholesale SAR columns (`sharingPriceSar`, `roomPriceSar`, `defaultRateSar`) to client props

- Severity: P0
- Category: security
- Where: [app/(public)/page.tsx:214-224,337-346](file:///c:/dev/al-ramlah-travels/web/app/(public)/page.tsx#L214-L224), [db/schema/catalog.ts:195-211,254-255,328](file:///c:/dev/al-ramlah-travels/web/db/schema/catalog.ts#L195-L211)
- Brief claim contradicted (if any): Contradicts Business Invariant #2 & #8 (`"Only Visa Only mode displays an immediate fixed PKR total to the customer"` and wholesale supplier/internal tariff confidentiality).
- Evidence:
  ```tsx
  // app/(public)/page.tsx:214-219 — selects ALL columns (SELECT *) from hotels & vehicles and serializes them into RSC HTML payload:
  db.select().from(schema.hotels).where(eq(schema.hotels.isActive, true))...
  db.select().from(schema.vehicles).where(eq(schema.vehicles.isActive, true))...
  ```
  In `db/seed.ts:353-357`, `schema.hotels` rows contain `sharingPriceSar: 450, roomPriceSar: 1250, quadPriceSar: 1650, triplePriceSar: 1450, doublePriceSar: 1250` and `schema.vehicles` rows contain `defaultRateSar` and `ziyaratRateSar`. While `HotelCard` (`components/planner/hotel-card.tsx:143-145`) carefully avoids rendering those fields visually, `SELECT *` serializes every wholesale SAR column into the public Next.js `__next_f` RSC flight payload in browser View-Source, and creates an immediate trap for Wave 6 fixers building `/hotels/makkah`, `/hotels/madinah`, and `/ziyarat` to accidentally render or include them in JSON-LD `Offer.price`!
- Impact (business terms): Competitors and retail customers inspecting page source (or viewing spoke pages if rendered) can extract Al Ramlah Travels' internal SAR hotel/fleet rate benchmarks (`sarToPkrRate` + per-hotel SAR tariffs), eroding quoting margin; worse, emitting volatile SAR/PKR figures on `/hotels/*` or `/ziyarat` violates Haramain Invariant #2 and binds the agency to stale off-peak tariffs during Ramadan/Rabi-ul-Awwal surges.
- Root cause: Public Server Component queries used unfiltered `db.select().from(schema.hotels)` / `schema.vehicles` instead of a public safe column projection DTO.
- Recommended fix: Create public catalog projection helpers (`getPublicHotelsCatalog`, `getPublicVehiclesCatalog` in `lib/data/public-catalog.ts` or `lib/seo/`) that explicitly omit/zero out internal SAR rate columns (`sharingPriceSar`, `roomPriceSar`, `quadPriceSar`, `triplePriceSar`, `doublePriceSar`, `breakfastPriceSarPerPax`, `lunchPriceSarPerPax`, `dinnerPriceSarPerPax`, `fullBoardPriceSarPerPax`, `defaultRateSar`, `ziyaratRateSar`) before passing data to `/` or any `/hotels/*` and `/ziyarat` spoke components, and omit `offers.price` from `LodgingBusiness`/`Hotel` JSON-LD on hotel spokes.
- Test to add: `tests/seo/public-catalog-confidentiality.test.ts` — asserts public hotel/vehicle DTOs and rendered HTML/JSON-LD on `/hotels/makkah`, `/hotels/madinah`, and `/ziyarat` never expose `sharingPriceSar`, `roomPriceSar`, `quadPriceSar`, or fixed PKR hotel rates, and always display `"Live Rate — Confirmed upon submission"`.
