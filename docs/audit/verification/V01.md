## 5. Newly Surfaced Adversarial Residual Risks & Polish Notes (Non-Blocking for Gate A)

1. **`V01-NEW-01` [`P2` Medium — Defense-in-Depth — `FIXED & VERIFIED` in Wave 4 by `v06`] `extractClientIp()` Trusts `cf-connecting-ip` Unconditionally Before Proxy Mode Check**
   - **Location**: [lib/rate-limit.ts](file:///c:/dev/al-ramlah-travels/web/lib/rate-limit.ts#L77-L95), [app/actions/applications.ts](file:///c:/dev/al-ramlah-travels/web/app/actions/applications.ts#L1820-L1832)
   - **Wave 4 Resolution (`v06`)**: Gated `cf-connecting-ip` behind `process.env.CLOUDFLARE_PROXY === "true"`, prioritized `x-vercel-forwarded-for` when `process.env.VERCEL === "1"`, and added secondary per-reference rate limit `enforceRateLimit("status-tracker:ref", cleanRef, { max: 12, windowSec: 900 })` in `lookupApplicationStatus`. Verified in `tests/w3/f-plat/security-primitives.test.ts` (`03-fix-log.md` §5).
   - **Observation**: `extractClientIp` returns `headers.get("cf-connecting-ip")` whenever present (`<=64` chars) before checking `x-real-ip` or the rightmost `x-forwarded-for` hop. When deployed directly on Vercel (`OD-07` primary target) or self-hosted Nginx ([nginx/nginx.conf](file:///c:/dev/al-ramlah-travels/web/nginx/nginx.conf#L104-L119) overwrites `X-Real-IP` with `$remote_addr` and keys Nginx `limit_req` on socket `$binary_remote_addr`, but does not strip client `CF-Connecting-IP`) *without* Cloudflare orange-cloud proxying in front, an attacker can send a random `CF-Connecting-IP` header per request to rotate PostgreSQL `enforceRateLimit` IP buckets on public Server Actions (`lookupApplicationStatus`, `submitCustomApplication`, etc.).
   - **Why Not Reopening `T-016` (`P0`)**: `lookupApplicationStatus` now requires BOTH a 48-bit CSPRNG reference (`ART-YYYYMMDD-<10-char>`) AND a constant-time HMAC match on the full normalized E.164 phone number (`~10^8` domestic / `>10^9` international combinations, up from the broken `endsWith("")` / 4-digit suffix), and `/api/auth/*` is independently rate-limited by Better Auth DB storage + Nginx `$binary_remote_addr`.
   - **Recommended Post-GA Hardening**: Gate `cf-connecting-ip` trust behind `process.env.CLOUDFLARE_PROXY === "true"`, prefer `x-vercel-forwarded-for` on Vercel (`process.env.VERCEL === "1"`), and add a secondary per-reference bucket `enforceRateLimit("status-tracker:ref", cleanRef, 10, 900)` in `lookupApplicationStatus`.
