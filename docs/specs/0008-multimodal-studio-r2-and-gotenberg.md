# 0008. Multimodal Studio R2 Presigned Uploads and Gotenberg Infrastructure

**Date**: 2026-11-02
**Status**: Approved (Implemented)

## Summary

This specification establishes production grade media handling and multimodal intelligence for the Al Ramlah Travels marketing studio. You gain direct client to object storage uploads that bypass serverless request limits, automated social media image resizing with sharp, and remote poster rendering powered by an Oracle Cloud Always Free Gotenberg instance. It also provides a resilient dual mode extraction engine that parses finished 4K marketing posters as well as raw B2B supplier flyers into structured catalog departures with accurate calendar dates.

## Context

Al Ramlah Travels operates an administrative marketing and quotation studio that converts raw supplier packages into branded marketing collateral and public catalog departures. The current implementation faces four technical bottlenecks that prevent reliable operation in production:

First, Vercel serverless functions enforce a strict 4.5 megabyte request body limit. Marketing administrators frequently upload high resolution supplier flyers, multi page package sheets, and 4K showcase posters that reach 10 to 30 megabytes. Routing these file uploads through Next.js Server Actions or Route Handlers triggers HTTP 413 Payload Too Large errors and crashes serverless worker processes.

Second, the existing poster and quotation rendering pipeline relies on launching a local Google Chrome or Microsoft Edge binary via the Chrome DevTools Protocol (CDP). While this works on developer desktop workstations, production serverless environments running on Amazon Linux or Alpine Linux lack Chrome binaries and required dynamic shared libraries (such as libnss and libatk). Installing headless Chromium into serverless function bundles exceeds the maximum deployment bundle limits and results in execution timeouts.

Third, the poster engine produces ultra high resolution 4K PNG files at 3240 by 4560 pixels. Social media distribution channels, particularly Instagram feeds, Facebook posts, and TikTok image carousels, reject or aggressively recompress PNG files of this size. These platforms mandate progressive JPEG images with a shorter side capped at 1080 pixels (aspect ratio 9 by 12.67 or 4 by 5) and file sizes under 2 megabytes.

Fourth, the existing flyer extraction logic in `extract-supplier-flyer.ts` uses fragile raw text prompts against a single Google Gemini endpoint without schema validation, fallback providers, or error recovery. When reading finished 4K posters generated by Gemini Ultra, the system fails to preserve pre assigned reference codes (such as `ART-2026-0001`), cannot back calculate supplier net costs from retail display prices, and forces costly duplicate poster re rendering. Furthermore, when extracting raw supplier flyers, the system extracts flight date labels (such as "03 NOV") as raw strings but fails to parse real ISO calendar dates. As a result, the action that publishes flyer cards to public group packages (`publishFlyerCardToPublicGroupPackages` in `marketing-ops.ts`) hardcodes the current day as the departure and return date, corrupting batch schedules.

## Requirements

**User stories**:
- As an agency marketer, I want to upload large 4K posters and multi page supplier PDFs directly to Cloudflare R2 storage without hitting payload size errors, so that our promotional artwork uploads smoothly every time.
- As an agency administrator, I want high resolution posters automatically converted into lightweight progressive JPEGs sized for Instagram and TikTok, so that our social broadcasts publish quickly and display clearly on mobile devices.
- As an agency executive, I want HTML posters and quotation PDFs rendered reliably on dedicated cloud infrastructure without local browser crashes, so that customer quotations and marketing flyers generate on schedule.
- As a package operations manager, I want the multimodal extraction engine to understand both finished Al Ramlah posters and raw supplier flyers, preserving post codes and computing correct net or retail prices.
- As a catalog administrator, I want extracted packages to resolve real calendar departure dates and airport codes automatically, so that one click publishing creates complete, ready to book group departures.

**Acceptance criteria**:
- **AC-1**: Direct to R2 Presigned Uploads: The route handler `POST /api/uploads/presign` validates authenticated admin sessions via `requireAdmin`, accepts file metadata (fileName, contentType, sizeBytes, folder prefix), and returns a signed AWS Signature V4 direct PUT URL using `@aws-sdk/s3-request-presigner` with a 15 minute lifetime, bypassing serverless function size limits.
- **AC-2**: Local Development Upload Fallback: When Cloudflare R2 credentials are not configured in local development, `POST /api/uploads/presign` returns an endpoint pointing to `POST /api/uploads/local` that streams files directly to `public/uploads/r2-local/`, preserving offline developer productivity.
- **AC-3**: Resilient Client Upload Dropzone: Client upload components in the marketing studio execute direct HTTP PUT requests to the presigned storage URL with real time progress tracking, returning the permanent public access URL upon successful completion.
- **AC-4**: Sharp Social Image Normalizer: The utility `optimizePosterForSocialToR2` in `web/lib/posters/social-optimizer.ts` processes 4K poster PNGs (3240 by 4560 pixels) using `sharp`, producing progressive sRGB JPEGs with the shorter side constrained to 1080 pixels (1080 by 1520 pixels), quality 85, and mozjpeg compression enabled.
- **AC-5**: Dual Asset Storage: Social media JPEGs are uploaded to Cloudflare R2 under `posters/social/`, preserving the original lossless 4K PNG and vector PDF alongside the lightweight JPEG in database records across `post_assets` and `supplier_flyer_packages`.
- **AC-6**: Gotenberg Microservice Client: Production poster and PDF rendering routes requests through `renderHtmlViaGotenberg` in `web/lib/posters/gotenberg.ts`, which sends multipart form data payloads to a self hosted Gotenberg v8 microservice.
- **AC-7**: Gotenberg Security and Proxy: The Gotenberg microservice runs behind a Caddy reverse proxy that terminates TLS and enforces the custom header `X-Gotenberg-Api-Key`, rejecting any unauthenticated request with HTTP 401 Unauthorized.
- **AC-8**: Infrastructure as Code Deployment: Complete deployment manifests for Gotenberg, including `docker-compose.yml`, `Caddyfile`, and an environment variable template, reside in `scripts/oracle-gotenberg/` targeting the Oracle Cloud Always Free compute tier.
- **AC-9**: Development Rendering Gateway: A unified render gateway automatically selects `renderHtmlViaGotenberg` when `GOTENBERG_API_URL` is set, and falls back to `renderHtmlViaChromiumCdp` in local development when the variable is absent.
- **AC-10**: Vercel AI SDK Multimodal Engine: The extraction engine `web/lib/ai/extract-packages.ts` uses the Vercel AI SDK with `Output.object()` structured outputs, orchestrating `@openrouter/ai-sdk-provider` with `google/gemini-2.5-flash` as primary, `anthropic/claude-3.5-sonnet` as secondary fallback, and `@ai-sdk/google` as tertiary fallback, equipped with automated JSON response healing.
- **AC-11**: Mode A Finished Poster Ingestion: When processing finished 4K Al Ramlah posters or PDFs, the engine preserves pre assigned reference codes matching pattern `ART-...`, extracts published retail prices, back calculates net supplier costs using flyer commission settings, and attaches the uploaded 4K file directly to the package record without re rendering.
- **AC-12**: Mode B Raw Supplier Flyer Extraction: When processing raw supplier flyers or pasted WhatsApp text, the engine extracts supplier net pricing, adds markup when the supplier uses `net_plus_markup`, and parses full ISO dates (YYYY-MM-DD) for departure and return by combining seasonal context with calendar labels.
- **AC-13**: Accurate Group Batch Publishing: `publishFlyerCardToPublicGroupPackages` resolves `departureCityCode` against `departure_cities.airport_code` in the database, and creates `group_departures` batches populated with real extracted ISO `departureDate` and `returnDate` values instead of placeholder dates.

## Options considered

### Option 1: In process Puppeteer rendering and direct serverless file uploads
Process all file uploads through Next.js API routes and launch headless Chrome directly inside the serverless runtime using community packages like chrome-aws-lambda or puppeteer-core.

**Pros**:
- Keeps all logic within a single Next.js repository without provisioning external servers.
- Avoids setting up an external reverse proxy or separate Docker containers.

**Cons**:
- Fails immediately on Vercel because file uploads larger than 4.5 megabytes trigger HTTP 413 errors.
- Exceeds serverless function bundle limits (50 megabytes zipped, 250 megabytes unzipped) due to heavy browser binaries.
- High risk of execution timeouts and random crashes caused by missing shared libraries on modern Linux serverless runtimes.
- Consumes expensive serverless memory and CPU limits during heavy rasterization of 4K images.

### Option 2 (Chosen): Direct to R2 Presigned Uploads, Sharp Social Normalization, Oracle Gotenberg Microservice, and Dual Mode Vercel AI SDK Extraction
Issue short lived AWS Signature V4 presigned PUT URLs for direct browser to R2 uploads, normalize social graphics into progressive JPEGs with sharp, offload rendering to an Oracle Cloud Always Free Gotenberg instance secured with Caddy, and implement structured multimodal extraction with Vercel AI SDK.

**Pros**:
- Completely bypasses Vercel payload limits, allowing seamless uploads of 30 megabyte 4K posters and multi page PDFs.
- Zero infrastructure hosting cost by utilizing the Oracle Cloud Always Free tier (4 OCPU ARM compute with 24 gigabytes RAM).
- Gotenberg v8 provides isolated, battle tested headless Chromium instances designed specifically for high volume PDF and screenshot rendering.
- Sharp delivers lightning fast, memory efficient image conversion that produces compliant progressive JPEGs under 500 kilobytes for Instagram and TikTok.
- Vercel AI SDK with typed Zod schemas and multiple model fallbacks guarantees reliable extraction from complex flyers and finished posters.
- Fixes the catalog publishing bug by populating real calendar dates and airport codes in group departures.

**Cons**:
- Requires one time setup of a Docker container and Caddy proxy on an Oracle Cloud virtual machine.
- Introduces an external network dependency for rendering, requiring a fallback to local CDP in development.

### Option 3: Third party commercial rendering and OCR software as a service
Subscribe to managed rendering and vision parsing platforms such as DocRaptor or CloudConvert for PDF and screenshot generation, paired with specialized document extraction SaaS providers.

**Pros**:
- Eliminates the need to self host Docker containers on Oracle Cloud.
- Provides managed service level agreements for browser rendering.

**Cons**:
- Recurring operational costs that scale linearly with rendering volume, creating an ongoing financial burden for a boutique agency.
- Vendor lock in and data privacy concerns regarding sensitive customer quotation details and passport estimates.
- Lacks native optimization tailored to Al Ramlah's custom 4K layouts, luxury fonts, and social media dimensions.

## Decision

**Chosen option**: Option 2: Direct to R2 Presigned Uploads, Sharp Social Normalization, Oracle Gotenberg Microservice, and Dual Mode Vercel AI SDK Extraction.

Al Ramlah Travels will implement direct client to R2 presigned uploads, convert 4K posters into progressive social media JPEGs with sharp, route production rendering to a secure Gotenberg microservice hosted on Oracle Cloud Always Free infrastructure, and deploy a dual mode multimodal AI extraction engine supporting finished posters and raw supplier flyers.

**Implementation skills**: `shadcn` (`shadcn/ui`, `.agents/skills/shadcn/`)

## Rationale

This decision solves the core reliability and scalability limits of the marketing operations studio while keeping ongoing infrastructure costs at zero.

Direct presigned uploads resolve the Vercel 4.5 megabyte limitation at the architectural level. Rather than streaming multi megabyte buffers through serverless function memory, the browser transfers raw bytes directly to Cloudflare R2 using AWS Signature V4 credentials generated on the server. The serverless function handles only tiny JSON authorization payloads, keeping execution times under 100 milliseconds and completely eliminating payload size errors.

Headless browser rendering belongs on persistent container infrastructure, not ephemeral serverless functions. Chrome requires stable font rendering, memory for large DOM trees, and specific Linux libraries that serverless runtimes deliberately omit. Gotenberg is an open source microservice built specifically for headless Chromium operations. Hosting Gotenberg on Oracle Cloud's Always Free ARM architecture provides 4 virtual CPU cores and 24 gigabytes of memory at zero cost, easily handling concurrent 4K screenshot rasterization.

Downsizing 4K PNGs to progressive JPEGs with sharp ensures immediate compliance with Meta and TikTok advertising requirements. While the original 4K PNG remains accessible for high quality print materials, marketing staff can instantly broadcast social ready images that load smoothly for users on mobile cellular networks.

Finally, standardizing AI extraction on the Vercel AI SDK with `Output.object()` replaces fragile raw JSON string matching with guaranteed Zod validation. Using OpenRouter to cascade from Gemini 2.5 Flash to Claude 3.5 Sonnet ensures that illegible or complex flyer layouts are parsed correctly. Differentiating Mode A (finished posters) from Mode B (raw flyers) prevents costly re rendering and ensures that public group packages display valid flight dates and departure cities.

### State transitions

The marketing asset lifecycle transitions through seven clearly defined stages:

1. `Raw Flyer or 4K Poster`: Uploaded by the marketing administrator in the web studio interface.
2. `Uploaded to Cloudflare R2`: Transferred directly from the browser via presigned AWS Signature V4 PUT URL, bypassing serverless limits.
3. `Extracted Flyer Cards`: Processed by the Vercel AI SDK multimodal extraction engine using Mode A or Mode B.
4. `Asset Attachment or Generation`: Mode A attaches the uploaded 4K PNG directly without re rendering. Mode B renders 4K PNG and vector PDF assets through the remote Gotenberg microservice.
5. `Social Media Optimization`: Sharp converts the 4K PNG into a lightweight progressive sRGB JPEG (1080 by 1520 pixels) and uploads it to Cloudflare R2.
6. `Admin Review and Verification`: Agency administrators verify extracted hotel names, prices, and ISO calendar dates in the quoting worksheet.
7. `Live Catalog Publication`: One click publishing creates or updates `group_packages` and populates `group_departures` batches with accurate calendar dates.

### Key invariants

- Vercel Serverless Exemption: In production, binary file bytes for uploads must never pass through Vercel serverless request bodies. All uploads over 4 megabytes transfer directly from client browser to Cloudflare R2 via presigned URLs.
- Dual Resolution Preservation: Generating a social media JPEG must never overwrite or delete the master 4K PNG (`3240x4560`) or the vector PDF. Both URLs remain permanently recorded in the database.
- Mode A Idempotent Ingestion: Ingestion of a finished Al Ramlah poster must never trigger a new Chromium or Gotenberg rendering cycle. The existing uploaded asset is attached directly as the spotlight poster.
- Positive Margin Guarantee: For any package card, the calculated retail price must be greater than or equal to the supplier net cost, ensuring positive agency profitability.
- ISO Date Validation: Every departure and return date written to `group_departures` must conform strictly to the ISO calendar format `YYYY-MM-DD` and represent a valid calendar day. Return date must be chronologically after departure date.
- Header Authentication Barrier: The Gotenberg microservice must reject any incoming rendering request that does not present the correct `X-Gotenberg-Api-Key` secret header.

### Security model

- Role based access control: All endpoints (`/api/uploads/presign`, `/api/uploads/local`, `/api/ai/extract-flyer`) and Server Actions (`publishFlyerCardToPublicGroupPackages`) enforce administrative authentication using Better Auth `requireAdmin()`. Non admin users and unauthenticated guests receive HTTP 401 Unauthorized or HTTP 403 Forbidden.
- Time limited storage access: Presigned PUT URLs expire exactly 15 minutes (900 seconds) after issuance, preventing unauthorized reuse.
- Storage path sandboxing: Upload keys are sanitized using alphanumeric prefixes, UUIDs, and strict folder scoping (`uploads/flyers/`, `uploads/posters/`). Path traversal attempts using relative sequences like `../` are stripped.
- MIME type restriction: Presigned URL generation enforces whitelisted content types (`image/jpeg`, `image/png`, `image/webp`, `application/pdf`). Executable files and scripts are rejected immediately.
- Secret isolation: The `GOTENBERG_API_KEY` shared secret is stored exclusively in environment variables and validated at the Caddy reverse proxy layer, shielding the Gotenberg process from direct public access.

### Configuration required

- `R2_ACCOUNT_ID`: Cloudflare Account ID used to construct the S3 endpoint hostname.
- `R2_ACCESS_KEY_ID`: Cloudflare R2 API token access key ID with object read and write permissions.
- `R2_SECRET_ACCESS_KEY`: Cloudflare R2 API token secret access key.
- `R2_BUCKET_NAME`: Target R2 storage bucket name, defaulting to `al-ramlah-assets`.
- `R2_PUBLIC_URL`: Custom public domain or Cloudflare worker URL serving cached R2 assets (e.g. `https://assets.alramlahtravels.com`).
- `GOTENBERG_API_URL`: Fully qualified HTTPS URL of the Oracle Cloud Gotenberg instance (e.g. `https://render.alramlahtravels.com`).
- `GOTENBERG_API_KEY`: Cryptographically random 64 character secret key passed in the `X-Gotenberg-Api-Key` header.
- `OPENROUTER_API_KEY`: API key for OpenRouter routing to Gemini 2.5 Flash and Claude 3.5 Sonnet.
- `GEMINI_API_KEY`: Direct Google AI Studio API key used as tertiary fallback.

- Remote Gotenberg execution: The system sends an HTML quotation payload to Gotenberg over HTTPS with the `X-Gotenberg-Api-Key` header. The service returns a pristine vector PDF buffer within 4 seconds, verifying **AC-6** and **AC-7**.
- Dev rendering gateway fallback: When `GOTENBERG_API_URL` is omitted in development, rendering calls execute via local `chromium-cdp.ts` without throwing connection errors, verifying **AC-9**.

## Migration plan

**Strategy**: Strangler pattern with backward compatibility.

**Phases**:
1. Phase 1: Deploy Direct to R2 presigning and Sharp normalizer alongside existing upload functions. Existing upload helpers continue functioning while new studio components switch to direct presigned uploads.
2. Phase 2: Deploy Gotenberg client on Oracle Cloud compute. Configure `GOTENBERG_API_URL` and `GOTENBERG_API_KEY` on production while retaining `chromium-cdp.ts` as the development fallback.
3. Phase 3: Roll out dual mode Multimodal AI extraction in the marketing studio. Update `publishFlyerCardToPublicGroupPackages` to read parsed ISO dates, updating existing draft flyers during normal admin review.

**Rollback**:
If the Gotenberg microservice becomes unreachable in production, setting `GOTENBERG_API_URL` to empty temporarily reverts rendering to local Chromium where available, while presigned uploads can fall back to local disk storage if Cloudflare R2 credentials encounter issues.

**Risks**:
- Oracle Cloud virtual machine restart or network interruption could temporarily interrupt remote rendering. Mitigation: Caddy and Gotenberg run with Docker restart policies (`restart: always`), and health checks alert administrators.
- High variance in raw supplier flyer formats may challenge AI date extraction. Mitigation: Mode B prompts enforce explicit calendar year and month context matching, falling back to manual date picker verification in the admin worksheet before publishing.

## Consequences

**Positive**:
- Eliminates Vercel HTTP 413 Payload Too Large errors completely by routing media directly to Cloudflare R2.
- Enables stable, high volume 4K poster and vector PDF rendering on dedicated, zero cost cloud infrastructure.
- Produces lightweight, mobile friendly progressive JPEGs ready for immediate distribution on Instagram and TikTok.
- Automates the extraction of finished posters and raw supplier flyers with guaranteed Zod type safety and multi model fallbacks.
- Corrects catalog batch scheduling by populating real calendar departure dates and airport gateway codes.

**Negative / tradeoffs**:
- Requires ongoing monitoring of an external Oracle Cloud virtual machine and Caddy TLS proxy.
- Adds `sharp` and `@aws-sdk/s3-request-presigner` to project dependencies, slightly increasing server build size.

**Neutral**:
- Requires updating environment variables on Vercel deployment dashboards.
- Marketing staff must verify extracted calendar dates during flyer review before publishing to the live website.
