## Feature design

**Data model sketch**:
No PostgreSQL schema changes or Drizzle migrations required (`48` tables, `47` enums, `17` SQL `CHECK` constraints, and `0000`..`0003` migrations remain completely untouched).

**State transitions**:
No server or database state machine transitions change. Client component state synchronization across admin dialogs, worksheets, and realtime banners is standardized to eliminate synchronous `setState` inside `useEffect`:
1. **Entity Edit Dialogs (`components/admin/catalog/*-dialog.tsx`, `meta-template-builder-modal.tsx`, `whatsapp-auto-reply-studio.tsx`, `studio-media-picker-modal.tsx`)**: Keep `<Dialog open={open} onOpenChange={onOpenChange}>` mounted so Base UI exit animations and focus return work cleanly, and place a composite `key` only on an extracted inner `<FormBody key={`${entity?.id ?? "new"}-${openCycle}`} />` child (or reset inside `onOpenChange` / trigger click handlers) instead of `useEffect(() => { if (open) setField(...) }, [open, entity])`.
2. **Prop Derived Buffers (`quote-dispatch-bar.tsx`, `quote-worksheet-form.tsx`, `applications-kanban-board.tsx`, `catalog-hub-client.tsx`)**: Track local user overrides or last seen prop version during render (or derive effective display state `localOverride ?? serverProp`) instead of mirroring props in `useEffect`.
3. **Async Fetch & Debounced Search (`command-palette.tsx`, `campaign-realtime-status.tsx`, `studio-realtime-run-banner.tsx`, `whatsapp-linked-device-card.tsx`)**: Derive `isLoading` from `debouncedQuery !== trimmedQuery || pendingFetch` or set loading state inside event handlers / async `Promise.resolve().then(...)` callbacks with `AbortController` / `active` cancellation flags rather than synchronous top of effect `setState`.
4. **Render Time Clock & ID Purity (`applications/page.tsx`, `applications-kanban-board.tsx`, `desk-hub-client.tsx`, `connections-settings-client.tsx`)**: Compute server side SLA cutoff timestamps via a dedicated helper outside JSX render expressions (in `applications/page.tsx`), pass optional `initialNowMs?: number` from `desk/page.tsx` and `settings/page.tsx` into client hubs (refreshed via `setInterval` callback so SSR and hydration never drift across a minute boundary), and replace `Math.random().toString()` optimistic message IDs in `desk-hub-client.tsx` with `crypto.randomUUID()` (or a monotonic `useRef` counter).
