## Summary

Today, once an Umrah quote is approved and deposit is paid, consultants still chase family passport scans, national ID cards, and visa photos manually across scattered chat threads. This feature adds a private self service checklist at `/documents/[token]` (reachable from a dedicated secret link or from `/#track-status` with booking phone verification, no account password required) with role aware upload slots for every adult, child, and infant on the booking, plus a structured verification panel inside `/admin/applications/[id]`. Files upload directly to private encrypted cloud storage (`passports/`) with binary file header checks (magic bytes) up to `10 MB`, unlock strictly on approved and deposit verified bookings, and purge automatically `60` days after the family returns from Saudi Arabia.

## Requirements

**User stories**:
- As a **Pilgrim with an approved and deposit verified booking**, I want to open a secure checklist from `/#track-status` or a link from my consultant, verify my booking phone number once, enter each family member's passport details, and upload their passport bio page, CNIC or NADRA B Form, and visa photo from my phone or laptop so my visas can be filed without back and forth chat confusion.
- As **Desk Staff**, I want to inspect `10` minute signed previews of every traveller's documents inside `/admin/applications/[id]`, approve clear scans or request a reupload with a specific reason, and notify the pilgrim via email or WhatsApp so visa filing stays organized and auditable.
- As a **Super Admin**, I want strict role gates on `6` month passport expiry overrides, capability token rotation, and passenger slot reductions, backed by `noindex` crawl headers, private `passports/` storage, immutable `audit_logs`, and automatic `60` day post return PII deletion.

**Acceptance criteria**:
- **AC-1 (Approval & Verified Deposit Unlock Gate)**: When a request hits `/documents/[token]` or any pilgrim document endpoint, the system shall return `404` (`notFound()`) for malformed or unknown tokens (verified in constant time via SHA256 `document_portal_token_hash`), return HTTP `403` (`forbidden.tsx`) whenever `applications.status !== 'approved'` or `applications.source === 'hajj_inquiry'` or the latest quote's `paymentStatus` is neither `'deposit_paid'` nor `'paid_in_full'` or verified `SUM(application_payments.amount_pkr) <= 0` (including immediate `403` lock if an approved booking is later `cancelled` or `rejected`), and idempotently mint `documentPortalToken` inside a `SELECT ... FOR UPDATE` lock on `applications` across all four unlock transition points (`saveApplicationQuote`, `updateApplicationStatus`, `recordApplicationPaymentAction`, and `respondToApplicationQuoteAction`), preserving `documentPortalTokenHash` and `documentPortalTokenEncrypted` across subsequent quote versions and status changes unless explicitly rotated by `super_admin`.
- **AC-2 (Two Factor Capability + Phone Session Gate & Crawl Isolation)**: Given a valid unlocked `/documents/[token]` URL, until the visitor presents a valid signed session cookie (`__Host-art_doc_sess` with `secure: true` when `NODE_ENV === "production" && !isAuditLocalE2eMode()`, else `art_doc_sess` with `secure: false`, always `path: "/"`, `httpOnly: true`, `sameSite: "lax"`, `maxAge: 86400`, serialized as `<base64urlJsonPayload>.<hmacHex>` bound to `applicationId` and `documentPortalTokenHash`), the page shall render only the booking reference number and a phone verification prompt (rate limited in PostgreSQL `rate_limit_buckets` at `5` attempts per `15` minutes per IP and `12` attempts per `15` minutes per token, using constant time normalized `>= 9` digit phone comparison against `customerPhone` or `customerWhatsapp`) and shall serialize zero traveller names, passport numbers, national IDs, or file URLs; `/documents/` shall enforce `Disallow: /documents/` in `app/robots.ts`, `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` plus `Referrer-Policy: no-referrer` in `proxy.ts`, and `robots: { index: false, follow: false }` plus `referrer: "no-referrer"` in route metadata.
- **AC-3 (Role Aware Traveller Provisioning & Non Destructive Reconciliation)**: When an unlocked booking loads in `/documents/[token]` or `/admin/applications/[id]`, `syncApplicationTravellerSlots()` shall perform a fast read and, only when counts diverge, lock `applications` `FOR UPDATE` inside `withTransaction()` to deterministically provision and order `application_travellers` (`slot_index = 1..totalPassportCount`: `adults` rows of `'adult'`, followed by `children` rows of `'child'`, followed by `infants` rows of `'infant'`) and `3` `application_documents` slots per traveller (`'passport_bio_page'`, `'national_id'`, `'visa_photo'`), displaying National ID labels as `CNIC (Front & Back or Smart Card)` for `'adult'` and `NADRA B-Form / Smart Card` for `'child'` and `'infant'`; `updateApplicationTravellerCountsAction` shall append new category slots without disturbing existing uploads when counts increase, and when decreasing a category count would remove a row where `full_name IS NOT NULL OR passport_number IS NOT NULL` or any child `application_documents.status != 'missing'`, it shall return `{ success: false, statusCode: 409, code: "DESTRUCTIVE_SLOT_REDUCTION" }` unless called by `super_admin` with `confirmDestructiveReduction: true` (deleting removed rows' R2 keys after transaction commit).
- **AC-4 (Typed Passport Metadata & 6 Month Saudi Validity Rule)**: When a pilgrim saves traveller details (`fullName`, `passportNumber`, `passportExpiryDate`, optional `nationalIdNumber`), Zod validation shall require trimmed `fullName` (`2..120` chars), normalize `passportNumber` via `.trim().replace(/[\s-]+/g, "").toUpperCase()` matching `^[A-Z0-9]{6,20}$`, normalize `nationalIdNumber` via `.trim()` (`<= 25` digits/hyphens, empty -> `null`), and require valid ISO `passportExpiryDate` (resetting `expiry_override_by_staff` to `false` if the pilgrim moves `passportExpiryDate` earlier than the previously saved date); when `anchorReturnDate` exists (resolved in order from `applications.ksaDepartureDate`, else linked `group_departures.return_date`, else `ksaArrivalDate + (totalKsaDays - 1)` UTC days; skipped with an advisory notice if all three are `null`) and `passportExpiryDate < anchorReturnDate + 6 UTC calendar months` while `expiry_override_by_staff` is `false`, pilgrim submission shall return `{ success: false, statusCode: 422, code: "PASSPORT_EXPIRY_TOO_SOON" }`, whereas `super_admin` in `/admin/applications/[id]` may record an audited `expiry_override_by_staff = true` with a mandatory reason.
- **AC-5 (10 MB Presigned Private Upload & Server Magic Byte Verification)**: When an authenticated pilgrim uploads a slot file, `/api/documents/[token]/presign` (rate limited at `30` requests per `15` minutes per IP and `30` per `15` minutes per token) shall accept only `image/jpeg`, `image/png`, `image/webp`, or `application/pdf` (`<= 10,485,760` bytes, rejecting `application/pdf` on `'visa_photo'` and blocking executable or markup extensions `.html`, `.svg`, `.xml`, `.js`), mint a `5` minute presigned R2 `PUT` (or a token and session gated `PUT /api/documents/[token]/local-upload` URL when R2 credentials are absent in `.env.audit` / local dev) under exact key `passports/<applicationId>/<travellerId>/<docType>-<uuid>.<ext>`, and upon commit `commitPilgrimDocumentUploadAction` shall read the first `512` bytes and total object length via S3 `GetObjectCommand({ Range: "bytes=0-511" })` (`ContentRange` / `ContentLength`) or `readLocalFallbackObject()`, verify `sniffAllowedBinaryMagicBytes()` equals the canonical declared MIME type and actual size `<= 10,485,760` bytes (deleting the uploaded object and returning `{ success: false, statusCode: 422, code: "INVALID_DOCUMENT_BINARY" }` on mismatch), lock the target `application_documents` row `FOR UPDATE` inside `withTransaction()`, set `status = 'uploaded'` while clearing `rejection_reason = null`, `reviewed_by_user_id = null`, and `reviewed_at = null`, and delete any superseded `storage_key` from R2 after transaction commit.
- **AC-6 (Approved Slot Lock & Reupload Lifecycle)**: While a document slot has `status === 'approved'`, pilgrim presign or commit calls on that slot shall return `409` (`SLOT_LOCKED_APPROVED`), and while all `3` slots for a traveller are `'approved'`, `savePilgrimTravellerDetailsAction` on that traveller shall also return `409`; pilgrims may upload or edit only when `< 3` slots are `'approved'` (for traveller details) or when the target slot is `'missing'`, `'uploaded'`, or `'reupload_requested'`, and staff transitioning any `'approved'` slot to `'reupload_requested'` (with a non empty `rejection_reason`) unlocks both that slot and the traveller's details.
- **AC-7 (Admin Dossier Review, RBAC Split & Token Rotation)**: Inside `/admin/applications/[id]`, active `staff` and `super_admin` (`requireAdmin()`, preserving `T-061` wholesale cost redaction and never serializing `documentPortalTokenHash` or `documentPortalTokenEncrypted` to Client Components) shall view per traveller progress (`X / 3N` verified), inspect `10` minute signed `/api/media/[...key]` image or PDF previews (using CSP safe link/image tiles without `<object>` or `<embed>`), lock `application_documents` `FOR UPDATE` to approve `'uploaded'` slots or mark `'reupload_requested'` with a mandatory reason; only `super_admin` (`requireSuperAdmin()`) may toggle `expiry_override_by_staff`, rotate `documentPortalToken` (invalidating old URLs and active session cookies immediately), or confirm destructive traveller count reductions, and every upload, review decision, count edit, override, and token rotation shall write an append only row to `audit_logs`.
- **AC-8 (Status Tracker Entry, Email Dispatch & WhatsApp Nudge)**: When `lookupApplicationStatus` on `/#track-status` succeeds for an unlocked booking, the response DTO shall include the decrypted `/documents/[token]` capability path and aggregate slot counts (`uploadedCount`, `approvedCount`, `reuploadRequestedCount`, `totalRequiredCount`, zero PII) so the pilgrim can launch the checklist in one click; `sendPilgrimDocumentPortalEmail()` in `lib/security/mailer.ts` (containing `referenceNumber`, company contact details from `getCompanyInfo()`, portal URL, and rejection summary if applicable, with zero passport or CNIC numbers) shall fire non fatally (`try/catch` logged, never aborting DB commits) when `customerEmail` exists on (a) first booking transition into the unlocked state, (b) `reviewPilgrimDocumentAction` with `decision === 'reupload_requested'` (`sendNotification` defaults to `true`), and (c) the transition where `'approved'` slots first reach `3N / 3N`, plus on manual `sendDocumentPortalNudgeAction({ channel: 'email' })`; in `/admin/applications/[id]` and `QuoteDispatchBar`, consultants shall also have `Copy Document Portal Link`, `1-Click WhatsApp` `wa.me` (disabled with an opted out badge whenever `isWhatsappContactOptedOut()` is true), and `sendDocumentPortalNudgeAction({ channel: 'whatsapp_24h' })` (returning `CONTACT_OPTED_OUT` if opted out per `CONST-OMNI-02` or `META_24H_WINDOW_CLOSED` when outside Meta's `24h` window).
- **AC-9 (Nightly 60 Day Post Return PII & Media Purge)**: When `runPiiAndMediaRetentionPurge` (`trigger/schedules.task.ts`) executes, it shall query unpurged bookings (`application_documents.pii_purged_at IS NULL` or `application_travellers.pii_purged_at IS NULL`) where `anchorReturnDate <= now - 60 days` (joining `group_departures.return_date` and computing `ksaArrivalDate + (totalKsaDays - 1)`, or falling back to `applications.decision_at <= now - 150 days` when `status === 'approved'` and all travel dates are `null`), delete every non null `application_documents.storage_key` under `passports/` via `deleteR2Objects()` *before* clearing DB keys (skipping DB scrub on any row whose R2 key returned a delete error so the next sweep retries it), and for succeeded rows set `storage_key = null`, `original_filename = null`, `passport_number = null`, `passport_expiry_date = null`, and `national_id_number = null`, set `application_documents.status = 'purged'`, and stamp `pii_purged_at` while preserving `application_travellers.full_name` alongside `applications`, `quotes`, and `application_payments` tax records for `6` years (`CONST-SEC-06`).

## Decision

**Chosen option**: Option 1: **Normalized Traveller and Document Tables + Separate Vaulted Capability Token with Phone Session Cookie + Two Step Presigned Private R2 Upload with Server Magic Byte Commit**

Model per traveller identity (`application_travellers`) and per slot verification (`application_documents`) in PostgreSQL, gate `/documents/[token]` behind a dedicated SHA256 indexed + `v2:` vault encrypted token paired with an `HttpOnly` phone verified session cookie, and upload files up to `10 MB` via short lived presigned `passports/` PUT URLs verified server side on commit via `512` byte binary magic byte inspection.

## Feature design

**Data model sketch**:
1. **New PostgreSQL enums (`web/db/schema/applications.ts` + `web/drizzle/0004_pilgrim_document_portal.sql`)**:
   - `traveller_category`: `'adult' | 'child' | 'infant'`
   - `pilgrim_document_type`: `'passport_bio_page' | 'national_id' | 'visa_photo'`
   - `pilgrim_document_status`: `'missing' | 'uploaded' | 'approved' | 'reupload_requested' | 'purged'`
2. **Additive columns on `applications`**:
   - `documentPortalTokenHash`: `varchar("document_portal_token_hash", { length: 64 }).unique()` (nullable; hex SHA256 digest of `portal:<rawToken>`)
   - `documentPortalTokenEncrypted`: `text("document_portal_token_encrypted")` (nullable; `v2:` HKDF AES 256 GCM vault ciphertext from `encryptSecret()` in `lib/security/vault.ts`)
   - `documentPortalTokenRotatedAt`: `timestamp("document_portal_token_rotated_at", { withTimezone: true })` (nullable)
3. **New table `application_travellers`**:
   - `id`: `uuid("id").primaryKey().defaultRandom()`
   - `applicationId`: `uuid("application_id").notNull().references(() => applications.id, { onDelete: "cascade" })`
   - `slotIndex`: `integer("slot_index").notNull()` (`1..N`)
   - `category`: `travellerCategoryEnum("category").notNull()`
   - `categoryOrdinal`: `integer("category_ordinal").notNull()` (`1..adults`, `1..children`, `1..infants`, for stable labels such as `Adult 1`, `Child 1`, `Infant 1` across count increases)
   - `fullName`: `text("full_name")` (nullable until saved)
   - `passportNumber`: `varchar("passport_number", { length: 32 })` (nullable; cleared on 60 day purge)
   - `passportExpiryDate`: `date("passport_expiry_date")` (nullable; cleared on 60 day purge)
   - `nationalIdNumber`: `varchar("national_id_number", { length: 32 })` (nullable; cleared on 60 day purge)
   - `expiryOverrideByStaff`: `boolean("expiry_override_by_staff").notNull().default(false)`
   - `expiryOverrideReason`: `text("expiry_override_reason")` (nullable)
   - `piiPurgedAt`: `timestamp("pii_purged_at", { withTimezone: true })` (nullable)
   - `createdAt` / `updatedAt`: `timestamp(..., { withTimezone: true }).notNull().defaultNow()`
   - Constraints & indexes: `uniqueIndex("uq_app_traveller_slot").on(table.applicationId, table.slotIndex)`, `uniqueIndex("uq_app_traveller_cat_ord").on(table.applicationId, table.category, table.categoryOrdinal)`, `check("chk_app_traveller_slot_pos", sql\`slot_index >= 1 AND category_ordinal >= 1\`)`, `check("chk_app_traveller_override_reason", sql\`expiry_override_by_staff = false OR (expiry_override_reason IS NOT NULL AND length(btrim(expiry_override_reason)) > 0)\`)`
4. **New table `application_documents`**:
   - `id`: `uuid("id").primaryKey().defaultRandom()`
   - `applicationId`: `uuid("application_id").notNull().references(() => applications.id, { onDelete: "cascade" })`
   - `travellerId`: `uuid("traveller_id").notNull().references(() => applicationTravellers.id, { onDelete: "cascade" })`
   - `docType`: `pilgrimDocumentTypeEnum("doc_type").notNull()`
   - `status`: `pilgrimDocumentStatusEnum("status").notNull().default("missing")`
   - `storageKey`: `text("storage_key")` (nullable; `passports/...` private R2 object key)
   - `originalFilename`: `varchar("original_filename", { length: 200 })` (nullable)
   - `mimeType`: `varchar("mime_type", { length: 64 })` (nullable)
   - `sizeBytes`: `integer("size_bytes")` (nullable)
   - `rejectionReason`: `text("rejection_reason")` (nullable)
   - `uploadedAt`: `timestamp("uploaded_at", { withTimezone: true })` (nullable)
   - `reviewedByUserId`: `text("reviewed_by_user_id").references(() => user.id, { onDelete: "set null" })` (nullable)
   - `reviewedAt`: `timestamp("reviewed_at", { withTimezone: true })` (nullable)
   - `piiPurgedAt`: `timestamp("pii_purged_at", { withTimezone: true })` (nullable)
   - `createdAt` / `updatedAt`: `timestamp(..., { withTimezone: true }).notNull().defaultNow()`
   - Constraints & indexes: `uniqueIndex("uq_traveller_doc_type").on(table.travellerId, table.docType)`, `index("idx_app_docs_app_status").on(table.applicationId, table.status)`, `check("chk_app_doc_size_bounds", sql\`size_bytes IS NULL OR (size_bytes > 0 AND size_bytes <= 10485760)\`)`, `check("chk_app_doc_rejection_reason", sql\`status != 'reupload_requested' OR (rejection_reason IS NOT NULL AND length(btrim(rejection_reason)) > 0)\`)`, `check("chk_app_doc_visa_photo_mime", sql\`doc_type != 'visa_photo' OR mime_type IS NULL OR mime_type IN ('image/jpeg', 'image/png', 'image/webp')\`)`

**State transitions**:
- **Portal Unlock State** (computed at read/write time, never stored stale):
  `locked_unapproved` (`status !== 'approved'` or `source === 'hajj_inquiry'`) -> `locked_awaiting_deposit` (`status === 'approved'` but `paymentStatus` not in `('deposit_paid', 'paid_in_full')` or `amountPaidPkr <= 0`) -> `unlocked` (`status === 'approved'` and verified deposit or full payment) -> `locked_closed` (if booking later transitions to `'cancelled'` or `'rejected'`, immediately returning HTTP `403`).
- **Document Slot State (`application_documents.status`)**:
  - `'missing'` -> `'uploaded'` (pilgrim commits verified file)
  - `'uploaded'` -> `'uploaded'` (pilgrim replaces file before approval; previous `storageKey` deleted from R2)
  - `'uploaded'` -> `'approved'` (staff or super admin approves scan; locks slot against pilgrim overwrite)
  - `'uploaded'` -> `'reupload_requested'` (staff or super admin requests clearer scan with `rejectionReason`)
  - `'approved'` -> `'reupload_requested'` (staff or super admin reopens slot with `rejectionReason`)
  - `'reupload_requested'` -> `'uploaded'` (pilgrim uploads replacement scan; clears `rejectionReason` display banner to pending review and deletes superseded R2 object)
  - `any` -> `'purged'` (nightly `60` day post return retention sweep deletes R2 object and clears PII columns)

**Key invariants**:
- **Strict Separation of Voucher QR Token vs Document Portal Token**: `applications.voucherToken` (printed on physical hotel/transport QR vouchers) and `applications.documentPortalTokenHash` / `documentPortalTokenEncrypted` MUST never share values or lookup columns.
- **Key Prefix Binding on Commit**: `commitPilgrimDocumentUploadAction` MUST verify that `storageKey` starts with exact prefix `passports/${applicationId}/${travellerId}/${docType}-` before reading or binding it, preventing cross booking or cross traveller key substitution (`IDOR`).
- **Zero Public CDN Exposure**: `storageKey` always resides under `passports/` (`PRIVATE_MEDIA_PREFIXES`), and every preview renders through `10` minute HMAC signed `/api/media/[...key]?exp=...&sig=...` (`Cache-Control: private, no-store`), never `R2_PUBLIC_URL`.
- **Non Destructive Slot Reconciliation**: Increasing `adults`, `children`, or `infants` appends new `(category, category_ordinal)` rows and recalculates `slot_index` deterministically without touching existing uploads; decreasing counts below populated rows requires explicit `super_admin` confirmation and deletes R2 objects of removed rows inside the workflow.

**Security model**:
- **Compliance Scope**: Touches passport bio pages, passport numbers, and Pakistani CNIC / NADRA B Form identifiers (`CONST-SEC-06`, `OD-06`, `/privacy` sub processor and `60` day post return retention commitment, plus Pakistan Income Tax Ordinance 2001 §174 `6` year financial ledger preservation).
- **Pilgrim Access**: Requires BOTH possession of the unguessable `256` bit `base64url` capability token AND one time verification of the booking's `customerPhone` / `customerWhatsapp` (minting an `HttpOnly`, `SameSite=Lax`, `Secure` in production HMAC session cookie bound to `applicationId` and `tokenHash`, so rotating the token immediately invalidates all open browser cookies).
- **Admin RBAC**: `requireAdmin()` (`staff` and `super_admin`, with live DB `user.isActive` verification per `CONST-SEC-02`) gates reading dossier documents, approving/requesting reuploads, and sending nudges. `requireSuperAdmin()` strictly gates `6` month passport expiry overrides, capability token rotation, and destructive traveller slot reductions.
- **Audit Trail**: Every file upload commit, document approval, reupload request, expiry override, and token rotation writes an immutable entry to `audit_logs` (`trg_audit_logs_immutable`, `CONST-SEC-03`).

**Configuration required**:
None (`0` new environment variables or external credentials required; reuses `ENCRYPTION_KEY`, Cloudflare R2 credentials, `RESEND_API_KEY`, and PostgreSQL `rate_limit_buckets`).

**Critical test scenarios**:
- **Happy Path (End to End Unlock -> Phone Gate -> Upload -> Staff Review -> Full Approval)**: Approved + deposit paid Umrah booking mints `documentPortalToken`, shows `Upload Travel Documents` on `/#track-status`, verifies pilgrim phone into `HttpOnly` session cookie on `/documents/[token]`, saves `Adult 1` + `Child 1` + `Infant 1` metadata and `9` valid scans (`JPG`/`PNG`/`PDF`), lets `staff` request a clearer reupload on `1` blurry scan, lets pilgrim replace it (deleting old R2 object), and reaches `9/9` `'approved'` with locked slots and confirmation email, verifies **AC-1**, **AC-2**, **AC-3**, **AC-4**, **AC-5**, **AC-6**, **AC-7**, **AC-8**, **AC-10**.
- **Failure, Polyglot & Validity Guards**: Uploading a renamed `.html` or `.svg` file as `passport.jpg` or uploading a `PDF` into `'visa_photo'` is rejected (`422`) on commit after `512` byte magic byte inspection and deleted from R2; entering a passport expiring `< 6` months after `ksaDepartureDate` fails (`422`) for pilgrims until `super_admin` records an audited override; cancelling an approved booking immediately turns `/documents/[token]` into HTTP `403`, verifies **AC-1**, **AC-4**, **AC-5**, **AC-7**.
- **AuthZ, Token Isolation, Crawl & 60 Day Retention Purge**: Scanning `voucherToken` against `/documents/[token]` returns `404`; unverified `/documents/[token]` HTML contains `0` traveller names or passport numbers and carries `X-Robots-Tag: noindex`; `staff` calls to `rotateDocumentPortalTokenAction` or `setTravellerExpiryOverrideAction` return `403`; running `runPiiAndMediaRetentionPurge` at `ksaDepartureDate + 61 days` deletes `passports/` R2 keys, scrubs passport/CNIC columns, marks rows `'purged'`, and leaves `applications` and `application_payments` intact, verifies **AC-1**, **AC-2**, **AC-7**, **AC-9**.

## Consequences

**Positive**:
- Replaces unstructured WhatsApp passport chasing with a deterministic `3` slot per traveller checklist tied to `adults`, `children`, and `infants` (`CONST-DOM-05`).
- Preserves `10 MB` high resolution camera scans and PDFs on Vercel serverless without hitting the `4.5 MB` function body ceiling while still enforcing server side `512` byte binary magic byte verification before a file is accepted.
- Keeps passport PII isolated from printed hotel QR vouchers (`voucherToken`), search crawlers (`noindex`), plaintext DB leaks (`v2:` vault + SHA256 hash), link forwarding (`HttpOnly` phone session cookie), and indefinite storage (`60` day post return purge).
- Every document upload, review decision, expiry override, and token rotation is permanently recorded in append only `audit_logs`.

**Negative / tradeoffs**:
- Adds `2` PostgreSQL tables (`48` -> `50` tables) and `3` enums (`47` -> `50` enums), requiring `/sync` to update table/enum counts in `AGENTS.md` and `db/AGENTS.md` after shipping.
- Two step upload (`presign` -> `PUT` -> `commit`) adds one lightweight round trip per file and can leave an uncommitted R2 object if a browser tab closes mid upload; mitigated by prefixing keys under `passports/${applicationId}/` so the existing `60` day post return (and `1` day multipart abort) lifecycle rules sweep any orphaned object cleanly.
- Requiring one time phone verification per browser (`24h` cookie) adds a single input step when a pilgrim first opens `/documents/[token]`, accepted deliberately to protect family passport numbers and scans if a WhatsApp link is forwarded.

**Neutral**:
- Reuses existing Cloudflare R2, Resend, Better Auth, and Trigger.dev infrastructure at `$0` incremental monthly vendor cost.
