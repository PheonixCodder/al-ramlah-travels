## Summary

Today, homepage hero slides only display static photographs and require administrators to paste prehosted image URLs manually inside `/admin/catalog?tab=cms`. This feature adds an optional ambient MP4 video layer (`video_url`) over each slide's required poster photograph (`image_url`) so mixed video and photo slides play smoothly on the homepage without delaying initial page paint. Super admins can upload poster photos (`JPG`, `PNG`, `WebP`) and ambient `MP4` loops up to `25 MB` directly to Cloudflare R2 from `HeroSlideDialog`, while visitors get silent inline video playback with smart slide timing, automatic reduced motion and Data Saver poster fallback, and an accessible pause button.

## Requirements

**User stories**:
- As a **Pilgrim visiting the homepage**, I want the hero stage to paint an instant Haramain photograph and smoothly fade into calm, silent ambient video when my device and connection allow it, with a clear pause button and zero layout shift or audio surprises.
- As a **Super Admin**, I want to upload a poster photograph and an optional `MP4` loop (`<= 25 MB`) directly inside `/admin/catalog?tab=cms` with live progress, inline preview, one click video removal, and automatic cleanup of replaced cloud files so managing hero campaigns takes seconds.
- As **Desk Staff**, I want `/admin/catalog?tab=cms` to show slide media badges (`Video + Poster` versus `Photo Slide`) in a clean read only view across all CMS sub tabs without exposing broken `403` edit buttons reserved for `super_admin`.

**Chosen option**: Option 1: **Nullable `video_url` on `hero_slides` + Super Admin `25 MB` Presigned R2 Upload with `512` Byte Commit Verification + Post Hydration `<video>` Crossfade Over Mandatory `next/image` Poster**

## Feature design

**Data model sketch**:
1. **Additive column & SQL `CHECK` constraint on `hero_slides` (`web/db/schema/cms.ts` + `web/drizzle/0005_hero_slides_video_url.sql`)**:
   - `imageUrl`: `text("image_url").notNull()` (existing; remains mandatory first frame poster and fallback image)
   - `videoUrl`: `text("video_url")` (new nullable column; stores `https://` R2 CDN URL, `/uploads/r2-local/cms/hero-slides/videos/...` non prod fallback path, or safe relative `/videos/...` asset path)
   - Constraint: `check("chk_hero_slides_non_empty_video_url", sql\`video_url IS NULL OR length(btrim(video_url)) > 0\`)`

**State transitions**:
- **Admin Upload Slot State (`HeroSlideDialog` per media slot: `poster` and `video`)**:
  - `idle` (empty dropzone on create, or saved asset preview on edit) -> `validating_client` (checks MIME type and `size <= 26,214,400` bytes before network call) -> `presigning` (`POST /api/uploads/presign` returning canonical `contentType`) -> `uploading` (raw binary `XMLHttpRequest` `PUT` `xhr.send(file)` with `Content-Type: canonicalMime` and `withCredentials = false` on cross origin R2 URLs, tracking `0..100%` byte progress; Save disabled while uploading) -> `staged` (displays uploaded poster or muted `<video>` preview; records `stagedDraftKey` so clicking `Remove Video`, replacing again, or closing dialog via `Cancel`/`Escape`/backdrop/`X` aborts active XHR and calls `deleteUnreferencedHeroMediaAction`) -> `committed` (`upsertHeroSlide` verifies managed origin + `512` byte magic bytes, commits DB row, and deletes any superseded unreferenced `cms/hero-slides/` object) | `error` (displays inline destructive message and restores previous URL).
- **Public Slide Playback State (`HeroSlider` active slide)**:
  - `ssr_poster` (`hasHydrated === false`; `0` `<video>` elements rendered; `Slide 0` `next/image` `preload` paints LCP)
  - -> `poster_only` (`videoUrl === null` OR `prefersReducedMotion` OR `saveData === true` OR `failedVideoIds.has(slideIdentity)`; advances after `7,500ms` when `slides.length > 1` and `!isPausedByInteraction`)
  - -> `video_buffering` (`hasHydrated === true` and `videoUrl !== null` and motion/data allowed; `<video>` mounted at `opacity-0` while poster remains `100%` visible; starts `20,000ms` slide ceiling + `7,500ms` buffering stall guard, and renders `Pause` / `Play` toggle)
  - -> `video_playing` (`onPlaying` fired; clears `7,500ms` stall guard and crossfades `<video>` to `opacity-100`; advances on `onEnded` or `20,000ms` cap when `slides.length > 1` and `!isPausedByInteraction`, loops gently if hovered when `onEnded` fires, or loops seamlessly when `slides.length === 1`)
  - -> `video_paused_manual` (visitor clicked `Pause background video`; calls `video.pause()`, halts video slide auto advance, sets `aria-pressed="true"`, persists across video slides while photo slides keep normal `7,500ms` rotation)
  - -> `video_paused_offscreen` (`IntersectionObserver` `isIntersecting === false` or tab hidden; pauses `<video>` and timer until visible again)
  - -> `poster_only` (if `onError`, non `AbortError` `.play()` rejection, or `7,500ms` buffering stall fires; records `slideIdentity` in `failedVideoIds` on media error, hides `<video>` and Pause/Play button, keeps poster visible on `7,500ms` timer).

**Key invariants**:
- **Mandatory Poster First (`image_url NOT NULL`)**: Every `hero_slides` record, whether photo only or video enhanced, MUST retain a valid `image_url` so SSR LCP, OpenGraph/SEO crawlers, reduced motion users, Data Saver users, and failed video streams always display a crisp Haramain photograph.

## Consequences

**Positive**:
- Gives the public homepage calm, luxury ambient Haramain motion without sacrificing SSR Largest Contentful Paint, SEO crawlability, or mobile Data Saver / reduced motion comfort.
- Eliminates external URL copy paste friction in `/admin/catalog?tab=cms` by letting `super_admin` upload poster photos and `MP4` loops directly to Cloudflare R2 with live progress and instant preview while keeping `web/public/` clean in local dev (`T-013`).
- Closes the `cms/hero-slides/*` upload authorization gap (`403` for `staff`), enforces managed origin and `512` byte binary magic byte verification before DB save, and automatically purges unreferenced `cms/hero-slides/*` objects from R2.

**Negative / tradeoffs**:
- Hero ambient videos are capped at `25 MB` `MP4` (`video/mp4`), so `super_admin` editors must export short (`8` to `20` second), web compressed `1080p` MP4 loops rather than raw `4K` `.mov` camera files, and production Cloudflare R2 requires a one time bucket CORS rule allowing `PUT` from the app domain.
- Every video slide still requires a poster image (`image_url`), adding one extra image selection step when creating a brand new video slide from scratch.

**Neutral**:
- Existing seeded and production `hero_slides` rows keep `video_url = null` after migration `0005` and continue rendering identically as `7.5` second photo slides with zero manual backfill required.
